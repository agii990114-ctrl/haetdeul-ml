## What changed

The rule as originally written scoped a log file to a **session**, with updates
appended as work progressed. The user corrected this: every request produces a
result, so **every request gets its own file**.

| | before | after |
|---|---|---|
| unit | one file per session | **one file per request** |
| on repeat | update the same file, keep the name | **create a new file** |
| filename time | when the log was first written in that session | **when this log is written** |

Filename format is unchanged: `참고/Claude/YYYY-MM-DD_HHMMSS.md`, seconds
included so two requests in the same minute cannot collide.

## Additions made while rewriting

Two gaps in the previous wording, fixed at the same time:

  miss happened — two completed pieces of work never made it into the log until
  the user pointed it out.

  files will accumulate quickly; the timestamp alone is not findable.
- Conversation-only requests still get a file **if something was measured or
  decided.** A verbal answer that contains a judgment is a result.
