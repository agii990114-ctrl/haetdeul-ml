|---|---|---|---|---|

### 주의 — 명칭으로 매칭하지 마세요

원본의 표기가 해마다 다릅니다.

```
신정(2015~2017)  →  1월1일(2018~)
국회의원선거     ↔  국회의원선거일
```

날짜 기준으로 쓰고, 명칭이 필요하면 `설날`·`추석`처럼 확인된 값만 쓰세요.
`ref_calendar` 가 명절 당일을 유도할 때 쓰는 것도 이 두 값뿐입니다.

### 주의 — 5/1 근로자의 날은 2026년부터만 있습니다

```
ref_holiday 의 5월 1일: 2026 · 2027 · 2028   (2015~2025 없음)
```

법정공휴일이 아니라 근로자의 날 제정에 관한 법률에 따른 유급휴일이라
API 수록이 최근에야 시작됐습니다. `ref_calendar` 는 이와 무관하게
**5/1 을 규칙으로 처리**하므로 전 구간 일관됩니다.

### 갱신

연 1회. API 가 **현재연도 +2년**까지만 확정합니다(현재 2028).
매년 `fetch_holidays.py` 를 다시 돌리고 `ref_calendar` 도 재생성해야 합니다.

> **임시공휴일·대체공휴일은 지정된 뒤에야 올라옵니다.**
> 즉 예측 시점에 알 수 없는 휴일이 원리적으로 존재합니다.
> 과거 재현에는 문제가 없고 미래 추론에서만 리드타임이 어긋납니다.

## 2. `ref_calendar` — 달력 (2축)

**축이 두 개**입니다. 가락 경매와 KAMIS 가격조사는 쉬는 날이 다릅니다.

```
가락 경매 거래일   2015~2025   3,348일
중도매가 조사일                2,700일
```

| # | 컬럼 | 타입 | 예시 | 설명 |
|---|---|---|---|---|
| 1 | `dt` | date | 2026-08-29 | 날짜. PK |
| 2 | `dow` | int | 6 | 요일. **0=일 … 6=토** (PostgreSQL `EXTRACT(dow)`) |
| 3 | `is_open` | boolean | true | **경매 거래일**인가 |
| 4 | `is_survey` | boolean | false | **중도매가 조사일**인가 |
| 5 | `open_reason` | text | NULL | 휴장 사유. 개장이면 NULL |
| 6 | `survey_reason` | text | weekend | 휴무 사유. 조사일이면 NULL |
| 7 | `open_seq` | bigint | 3401 | 경매 축 일련번호 |
| 8 | `survey_seq` | bigint | 2712 | **조사 축 일련번호 — `lead_biz_d` 의 축** |

**범위** 2015-01-01 ~ 2028-12-31 · 5,114행

### `open_seq` / `survey_seq` 쓰는 법

두 날짜의 일련번호 차이가 곧 그 축의 영업일 간격입니다.

```sql
-- 기준일에서 18영업일 뒤 (중도매가·소매가 타겟용)
SELECT t.dt
FROM ref_calendar b
JOIN ref_calendar t ON t.is_survey AND t.survey_seq = b.survey_seq + 18
WHERE b.dt = CURRENT_DATE;
```

**타겟에 따라 축이 다릅니다.**

| 타겟 | 축 |
|---|---|
| `target_auc_prc` (경락가) | `open_seq` |
| `target_whsl_prc` · `target_rtl_prc` | `survey_seq` |

`crop_price_train.lead_biz_d` 는 `survey_seq` 기준입니다.

### 사유 값

| `open_reason` | 뜻 |
|---|---|
| `sunday` | 일요일 |
| `new_year` | 신정 1/1~1/2 |
| `seol` · `chuseok` | 명절 당일 ~ +2일 |
| `summer_break` | 8월 첫 토요일 (하계휴장) |
| `override:...` | 비정기. `ref_calendar_override` 참조 |

| `survey_reason` | 뜻 |
|---|---|
| `weekend` | 토·일 (**조사일 중 토요일 0건 / 2,700일**) |
| `labor_day` | 5/1 |
| `dec_first_fri` | 12월 첫째 금요일 (11년 연속 휴장) |
| `holiday:<명칭>` | `ref_holiday` 의 공휴일 |
| `override:...` | 비정기 |

### 명절 처리가 축마다 하루 다릅니다

```
경매      D-1 거래  │ D0  D+1 D+2 휴장
중도매 조사  D-1 휴무 │ D0  D+1 휴무      ← 법정 연휴 그대로
```

실측 D-1 미조사 17/17 · D0 16/16 · D+1 14/14 (예외 0건).

### 검증 상태

| 검사 | 결과 |
|---|---|
| 경매 축 vs 실거래일 (2016-01~2026-08) | 오탐 0 · 미탐 0 |
| 조사 축 vs 실조사일 (2015~2025) | 오탐 0 · 미탐 0 |
| `lead_biz_d` 재현 | 배추·양파·무 불일치 0 |

`26_check_calendar.sql` 로 언제든 재판정할 수 있습니다.

## 4. `ref_school_day` — 학사일정 (급식 수요)

서울 초·중·고 개교율입니다. 중도매가 사용자가 식당·급식 구매담당이므로
방학 여부가 수요에 직접 걸립니다.

| # | 컬럼 | 타입 | 예시 | 설명 |
|---|---|---|---|---|
| 1 | `dt` | date | 2023-07-25 | 날짜. PK. 2015-01-01 ~ 2028-12-31 |
| 2 | `school_open_ratio` | numeric(6,4) | 0.1726 | 개교율 0~1. **모델 입력은 이 컬럼** |
| 3 | `school_open_ratio_meas` | numeric(6,4) | 0.1690 | NEIS 실측. 2020-09 이후만. 참고·검증용 |

### 실측이 아니라 연중 프로파일을 쓰는 이유 ★

NEIS 학사일정 개방일이 2019-04-01 이고 **API 는 최근 2개 학년도만 보유**합니다
(2026-08 확인: 2025-03 이후만 조회됨). 그래서 실측은 2020-09 부터이고
**학습 구간(2017~2022) 커버리지가 36.6%** 입니다.

결측을 그대로 두면 "2020-09 이전인가" 가 시점 식별자가 되어, 경제 변수를
제거한 것과 같은 과적합을 부릅니다 (`CLAUDE.md` 5.2). 그래서 실측 5년으로
(월,일) 중앙값 프로파일을 만들어 **전 구간에 같은 규칙**을 적용했습니다.

| | 값 |
|---|---|
| leave-one-year-out MAE | 0.0315 |
| 급식일(≥0.5) 이진 일치 | **96.7%** |
| 월별 평균 | 1월 0.23 · 2월 0.21 · 3~6월 0.96~1.00 · 7월 0.71 · 8월 0.49 · 9~11월 0.99 · 12월 0.94 |

**부수 효과가 큽니다.** 규칙이라 미래에도 값이 있어 리드타임 18영업일 앞을
채울 수 있습니다. 실측이었다면 배치에서 쓸 수 없었습니다.

### 집계 기준

```
분모  서울(B10) 초·중·고 1,422교 (전 기간 등장 학교 합집합)
분자  수업공제일명 ∈ {휴업일, 공휴일} 인 학교 수
프로파일 산출 시 토·일과 공휴일 제외
```

토·일과 공휴일을 빼는 이유는 두 가지입니다. **NEIS 는 일요일에 휴업일 행을
만들지 않아 일요일이 "개교"(실측 중앙값 0.995)로 잡힙니다.** 그리고 공휴일
휴교는 `ref_calendar` 가 이미 담당합니다. 결국 학사일정이 새로 주는 정보는
**여름·겨울방학뿐**입니다.

양력 고정 공휴일 8일(1/1 3/1 5/5 6/6 8/15 10/3 10/9 12/25)은 프로파일 산출에서
빠지므로 앞뒤 평균으로 보간했습니다. 조사 축(`target_dt`)에 공휴일이 없어
모델은 이 값을 보지 않습니다. **이 날짜의 값을 근거로 삼지 마세요.**

### 원본의 한계

원본 CSV 71개는 파일명과 내용이 어긋난 것이 있습니다. "2024년10월" 이
10/09~11/08 을 담는 식으로 31일 창으로 받은 흔적이고, 이어붙여도 **8곳 45일**이
빕니다. 프로파일은 연도별 중앙값이라 이 구멍의 영향이 작습니다.

### `crop_price_train` 결합

`target_dt` 로 붙입니다 (기준일이 아닙니다). 학사일정은 학년 초에 공시되므로
3주 뒤 급식 여부를 오늘 이미 알 수 있어 **미래정보 누출이 아닙니다.**

## 5. `ref_prediction_band` — 예측 구간 근거

`prediction_log.pred_lo` / `pred_hi` 를 만드는 값입니다.
검증 구간에서 잰 **`actual / pred` 비율의 분위수**입니다.

| # | 컬럼 | 타입 | 예시 | 설명 |
|---|---|---|---|---|
| 1 | `target_kind` | varchar(4) | whsl | `auc` · `whsl` · `rtl`. PK(1) |
| 2 | `item_nm` | varchar(20) | 배추 | PK(2) |
| 3 | `lead_biz_d` | smallint | 12 | PK(3) |
| 4 | `ratio_q10` | numeric(8,4) | 0.7402 | actual/pred 10분위 |
| 5 | `ratio_q50` | numeric(8,4) | 0.9981 | 중앙값 |
| 6 | `ratio_q90` | numeric(8,4) | 1.3105 | actual/pred 90분위 |

**162행** = 3 타겟 × 3 품목 × 18 리드타임. 값 범위 q10 0.74~0.94 · q90 1.05~1.47.

```
pred_lo = pred_prc * ratio_q10
pred_hi = pred_prc * ratio_q90
```

"그 조합에서 10건 중 8건이 이 범위 안에 들어왔다" 는 뜻입니다.

### 시드 편차를 구간으로 쓰지 마세요 ★

`seed_spread` 는 시드끼리 얼마나 다르게 답하느냐일 뿐이라 **실제 오차와
자릿수가 다릅니다.**

```
LT3   시드 편차 1.6%   실제 WMAPE 10.4%
LT18  시드 편차 1.8%   실제 WMAPE 16.8%
```

신뢰구간처럼 쓰면 불확실성을 10배 가까이 과소평가합니다.

### 밴드 폭 (실측)

| 타겟 | 폭 중앙값 | 배추 LT1 → LT18 |
|---|---|---|
| 경락가 | 59.3% | 62% → 71% |
| 중도매가 | 44.8% | 35% → 67% |
| 소매가 | 22.9% | 13% → 41% |

리드타임이 길수록 넓어집니다. 적중률 실측 79.6%(설계 80%) —
단 밴드를 잰 구간에서 측정한 in-sample 값입니다.

### 갱신

**모델과 짝입니다.** 재학습하면 `export_band_sql.py` 로 다시 만들어야 합니다.

| 17 | `actual_prc` | numeric(15,3) | NULL | 실제값. 사후 UPDATE |
| 18 | `abs_pct_err` | numeric(10,4) | NULL | 절대오차율(%). 사후 UPDATE |
| 19 | `scored_at` | timestamp | NULL | 채점 시각 |

**자연키** `(base_dt, item_nm, lead_biz_d, target_kind, model_ver)` — UNIQUE

**제약**
- `target_kind IN ('auc','whsl','rtl')`
- `lead_biz_d BETWEEN 1 AND 18`
- `pred_prc > 0 AND anchor_prc > 0`

**인덱스** `(target_dt, item_nm, target_kind)` · `(base_dt DESC)` ·
`(item_nm, target_kind) WHERE actual_prc IS NULL`

### 현재 들어 있는 더미

```
3-a  과거 7 기준일 (2025-11-25 ~ 12-03) · LT1~18 · 1,134행
       └ 972행 채점 완료(actual_prc 있음) + 162행 미채점
3-b  오늘 기준 (2026-08-24) · 대상일 08-25 ~ 09-17 · 162행 · 전부 미채점
합계 1,296행 · model_ver = 'dummy-v0'
```

앵커·대상일·정답은 **실제 값**이고 `pred_prc` 만 만들어낸 값입니다.
난수가 아니라 결정적 함수라 재실행해도 같습니다.
`model_ver = 'dummy-v0'` 으로 실제 예측과 구분됩니다.

## 8. `v_prediction_latest` — 소비자용 뷰

## 9. 쓰기 전에 반드시 알 것 — 세 가지

### ① 단위가 타겟마다 다릅니다

| `target_kind` | `unit` | 기준 |
|---|---|---|
| `auc` | 원/kg | 서울가락 · 특등급 |
| `whsl` | 원/kg | 가락도매 · 상품 |
| `rtl` | **원/단위** | 서울 · 상품. **배추는 포기 단위라 kg 아님** |

세 값을 그대로 더하거나 비교하면 안 됩니다. 반드시 `unit` 을 보고 쓰세요.

### ② 모든 조합이 쓸 만하지 않습니다

`use_recommended = false` 인 세 조합(경락 양파, 중도매 무·양파)은
모델이 "어제 가격 그대로" 보다 **나쁩니다.** 그 경우 `anchor_prc` 를 쓰세요.
뷰의 `prc_to_use` 가 이미 그렇게 골라 줍니다.

### ③ `gated = true` 는 두 가지 사유가 있습니다

| `gate_reason` | 뜻 |
|---|---|
| `lead_time` | LT<3. 어제 가격이 이미 정답에 가까워 모델이 개입할 여지가 없음 |
| `quality` | 품목×타겟 조합이 baseline 보다 나쁨 (`ref_prediction_quality.use_recommended=false`) |
| `quality:unknown` | 품질표에 없는 조합. 검증 전이라 안전하게 앵커 |
| `lead_time+quality` | 둘 다 |

**`quality` 는 조합 단위로 통째로 걸립니다.** 현재 9개 중 3개(경락 양파 ·
중도매 무·양파)가 해당해, 그 조합은 리드타임과 무관하게 전부 앵커입니다.
사유를 보지 않으면 모델이 고장난 것처럼 보이니 주의하세요.

### ④ LT1~2 는 `gated = true` 입니다

`pred_prc = anchor_prc` 로 나갑니다. 버그가 아닙니다.
가까운 미래는 어제 가격이 이미 정답에 가까워 모델이 개입할수록 손해였습니다
(검증 2022·2023 두 폴드, 세 타겟 모두).
