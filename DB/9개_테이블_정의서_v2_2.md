# 2. 공통 설계 원칙

## 2.1 RAW 테이블 원칙

RAW 계층은 외부 데이터의 원형 보존을 우선한다.

- 원본 값은 임의로 수정하지 않는다.
- 원래 값이 `0`, `0.0`이면 그대로 저장한다.
- 값이 없는 경우 `NULL`로 저장한다.
- RAW 단계에서 결측치 대체, 이상치 제거, 스케일링, rolling feature 생성을 하지 않는다.
- 날짜나 시각을 원본 문자열 그대로 보존할 필요가 있으면 `VARCHAR`로 저장한다.
- 데이터 출처와 의미를 추적할 수 있도록 컬럼 COMMENT를 작성한다.
- 내부 식별을 위해 `id BIGSERIAL`을 사용한다.
- 적재 시각 확인을 위해 `created_at TIMESTAMP`를 사용한다.

예외: `daily_volume`은 일자 × 품목 격자가 그 자체로 유일하고 재적재(UPSERT)가 잦아 자연키 PK와 `loaded_at`을 사용한다. 상세는 10.2 참조.

## 2.2 네이밍 규칙

- 테이블명과 가공 컬럼명: `snake_case`
- API 원본 컬럼명 보존이 필요한 경우: 원본명 유지
- 긴 컬럼: 약어 사용
- 축약명은 COMMENT로 의미를 보완

예외: `daily_volume`은 적재 스크립트와의 1:1 대응을 위해 `base_date`, `req_date` 처럼 약어 대신 전체 단어를 사용한다.

# 4. `veg_daily_price_raw`

## 4.1 목적

공공데이터포털에서 제공하는 한국농수산식품유통공사(aT)의 일별 도·소매 가격정보를 원형 그대로 저장한다.

- 출처: 공공데이터포털
- 서비스: `B552845/perDay`
- 오퍼레이션: `price` (일별 도,소매 가격정보)
- 엔드포인트: `https://apis.data.go.kr/B552845/perDay/price`
- 용도: 가격 예측 모델의 정답 라벨 및 가격 시계열 Feature 원천
- 특징: API 응답 컬럼명을 그대로 유지

주요 역할:

- 품목별 일별 도매(중도매인 판매) 가격
- 품목별 일별 소매 가격
- 시장·지역·품종·등급별 세분 가격
- 가격 예측 평가 및 검증

### v2.0 대비 변경 사유

v2.0은 농넷 "주요 채소류 일일가격 현황" 파일데이터를 전제로 설계되었으나, 실제 수집은 aT 오픈API로 이루어졌다. 두 데이터는 구조가 근본적으로 다르다.

| 구분 | v2.0 (농넷 파일) | v2.1 (aT 오픈API) |
|---|---|---|
| 행 단위 | 조회일 × 품목 | 조사일 × 품목 × 품종 × 등급 × 구분 × 시장 |
| 도매/소매 | 한 행에 컬럼으로 병렬 | `se_cd` 로 행 분리 |
| 파생값 | 전일/전순/전년순/평년순 포함 | 없음 (원본 가격만) |
| 위기단계 | 포함 | 없음 |
| 시장 구분 | 없음 (대표값) | 전국 도·소매시장 개별 |

파생값(전일·전순·평년순·비율)과 위기단계는 RAW 계층에서 보관하지 않는다. 전자는 일별 가격 시계열에서 계산 가능한 파생 지표이므로 CLEAN/FEATURE 계층의 책임이며, 후자는 농넷 내부 산정 기준이 비공개여서 원천으로 확보할 수 없다.

## 4.2 키

- PK: `id`
- UNIQUE: `(exmn_ymd, item_cd, vrty_cd, grd_cd, se_cd, sgg_cd, mrkt_cd, unit, unit_sz)`

품목만으로는 행을 특정할 수 없다. 같은 날 같은 품목이라도 품종(봄배추/월동배추), 등급(상품/중품), 조사구분(소매/중도매), 시장(가락도매/엄궁도매), 단위(포기/kg)에 따라 별도 행으로 존재한다.

2015-01-02 ~ 2025-12-31 배추·양파 377,230행 기준으로 위 자연키의 중복은 0건임을 확인했다.

배추는 계절 작형에 따라 품종이 교대되므로, 단일 품종만 선택하면 시계열이 연중 단절된다. 연속 시계열이 필요하면 작형을 이어붙이거나 품목 단위로 집계해야 한다.

| 인덱스명 | 컬럼 | 용도 |

## 4.6 관련 뷰

`v_veg_daily_wholesale` — 가락도매·중도매·상품 기준 단일 시계열.

```sql
CREATE OR REPLACE VIEW public.v_veg_daily_wholesale AS
SELECT exmn_ymd, item_cd, item_nm, vrty_cd, vrty_nm,
       unit, unit_sz, exmn_dd_prc, exmn_dd_cnvs_prc
FROM public.veg_daily_price_raw
WHERE se_cd = '02' AND grd_cd = '04' AND mrkt_nm = '가락도매'
ORDER BY item_cd, exmn_ymd;
```

RAW 계층 자체는 필터 없이 원형을 보존하고, 대표 시계열 선택은 뷰 또는 CLEAN 계층에서 수행한다.

## 4.7 주의사항

- **단위 혼재**: 배추는 포기·kg(그물망)·g가 섞여 있다. 품목 간 또는 기간 간 비교 시 `exmn_dd_prc`를 그대로 쓰면 안 되고 `exmn_dd_cnvs_prc`(kg환산)를 사용하거나 단위를 명시적으로 고정해야 한다.
- **단일 시계열 아님**: 하루에 품목당 수십 행이 존재한다. 집계 없이 시계열로 취급하면 안 된다.
- **휴장일 결측**: 일요일, 신정, 설·추석 연휴에는 도매시장이 휴장하여 행 자체가 존재하지 않는다. 결측 보간은 CLEAN/FEATURE 계층에서 수행한다.
- **코드 선행 0 보존**: `grd_cd='04'`, `vrty_cd='00'`, `mrkt_cd='0110211'` 등 선행 0이 있는 코드가 다수다. 적재 시 문자열로 읽어야 하며, 숫자 추론으로 읽으면 코드가 손상된다.
- **경락가 아님**: `se_cd='02'`는 중도매인 판매가격이다. 가락시장 경락가격이 필요하면 별도 데이터 소스가 필요하다.
- **친환경 구분**: `se_cd` `03`/`07`은 일반 도소매와 성격이 다르므로 분석 시 분리하거나 제외 여부를 명시해야 한다.

# 10. `daily_volume`

## 10.1 목적

품목별 일자별 반입 물량과 상위 산지를 저장한다.

- 원천 파일: `daily_volume.csv`
- 적재 대상: DB `cost_catcher_raw` / 스키마 `public`
- 원본 범위: 1,438행 / 2021-05-29 ~ 2025-12-31
- 원본 `item_label`: 단일값 `배추`
- 용도: 반입량 계열 Feature(`arr_qty_lag1`, `arr_qty_avg7`, `arr_qty_prev_yr`)의 원천, 공급량 충격 신호
- 특징: 원본 `1위`/`2위` 문자열에서 산지명을 분리하고, 원문은 `top1_raw`/`top2_raw`에 그대로 보존

가격만으로는 공급 충격의 방향을 알 수 없다. 반입 물량은 가격과 반대 방향으로 움직이는 대표적인 수급 변수이며, 상위 산지 정보는 주산지 기상 Feature(`prod_area_*`)와 연결할 관측소를 실제 데이터로 검증하는 근거가 된다.

## 10.2 키 및 제약

- PK: `(base_date, item_label)`
- `loaded_at`: 적재 시각 (`TIMESTAMPTZ`, 기본값 `now()`)

| 제약명 | 내용 |
|---|---|
| `pk_daily_volume` | `PRIMARY KEY (base_date, item_label)` |
| `ck_daily_volume_ton_nonneg` | `total_ton`, `top1_ton`, `top2_ton`, `etc_ton` 모두 0 이상 |
| `ck_daily_volume_rank_order` | `top1_ton >= top2_ton` (순위 정합성) |
| `ck_daily_volume_req_date` | `req_date >= base_date` (수집일은 기준일 이후) |
| `ck_daily_volume_sum` | **비활성화.** 원본에 ±1 반올림 오차가 있어 기본 주석 처리 |

`ON CONFLICT (base_date, item_label) DO UPDATE` 로 재적재 시 멱등성을 보장한다.

### 다른 RAW 테이블과의 설계 차이

이 테이블은 2.1의 RAW 공통 원칙 중 일부를 따르지 않는다.

| 항목 | 다른 RAW 7개 | `daily_volume` |
|---|---|---|
| PK | `id BIGSERIAL` | 자연키 `(base_date, item_label)` |
| 적재 시각 | `created_at TIMESTAMP` | `loaded_at TIMESTAMPTZ` |
| CHECK 제약 | 없음 | 4종 (1종 비활성) |
| 생성 컬럼 | 없음 | `mmdd` |

일자 × 품목이 그 자체로 유일한 격자 구조이고 재적재 빈도가 높아 자연키 PK + UPSERT 방식을 채택했다. 명칭 통일이 필요하면 `loaded_at`을 `created_at`으로 정렬하는 것이 이후 유지보수에 유리하다.

## 10.3 컬럼 정의

| DB 컬럼 | 원본 컬럼 | 타입 | 설명 |
|---|---|---|---|
| `base_date` | ymd | DATE NOT NULL | 기준일자 |
| `item_label` | item_label | VARCHAR(20) NOT NULL | 품목명 |
| `total_ton` | 합계_톤 | INTEGER NOT NULL | 일 합계 물량(톤) |
| `top1_region` | 1위 (파싱) | VARCHAR(20) | 1위 산지. 물량 0인 날은 NULL |
| `top1_ton` | 1위_톤 | INTEGER NOT NULL | 1위 산지 물량(톤) |
| `top2_region` | 2위 (파싱) | VARCHAR(20) | 2위 산지. 물량 0인 날은 NULL |
| `top2_ton` | 2위_톤 | INTEGER NOT NULL | 2위 산지 물량(톤) |
| `etc_ton` | 기타_톤 | INTEGER NOT NULL | 1·2위 외 기타 산지 합계 물량(톤) |
| `req_date` | req_date | DATE NOT NULL | 데이터 수집/요청 일자. 항상 `base_date` 이상 |
| `top1_raw` | 1위 | TEXT | 1위 원문 보존. 구분자가 NBSP(U+00A0) |
| `top2_raw` | 2위 | TEXT | 2위 원문 보존 |
| `loaded_at` | - | TIMESTAMPTZ NOT NULL | DB 적재 시각 (기본값 `now()`) |
| `mmdd` | 날짜 | VARCHAR(5) GENERATED | `base_date` 파생 `MM/DD`. 원본 `날짜` 컬럼 대체 |

원본 `날짜`(MM/DD)는 `base_date`에서 100% 파생되므로 별도 저장하지 않고 생성 컬럼(`GENERATED ALWAYS AS ... STORED`)으로 노출한다.

```text
        ↓  COPY / \copy (HEADER true)
daily_volume_stg  (전 컬럼 TEXT)
        ↓  NBSP 치환 → ' 숫자톤' 접미사 제거 → 빈 문자열 NULL 처리 → 반올림 캐스팅
daily_volume      (최종)
```

스테이징을 전 컬럼 `TEXT`로 두는 이유는 캐스팅 실패 한 건 때문에 `COPY` 전체가 롤백되는 것을 막기 위해서다. 파이썬 정제(`load_daily_pg.py`)를 쓰는 경우 스테이징과 SQL 변환 단계는 생략한다.

산지명 파싱 핵심:

```sql
nullif(btrim(regexp_replace(replace(top1_raw, U&'\00A0', ' '),
                            '\s*\d+톤$', '')), '')
```

## 10.6 적재 검증

| 항목 | 기대값 |
|---|---|
| 건수 | 1,438행 |
| 기간 | 2021-05-29 ~ 2025-12-31 |
| 산지 파싱 실패 (`top1_region ~ '[0-9]\|톤'`) | 0건 |
| 지역 목록 | 47개 시군 + `기타` |
| 합계 오차 `total_ton - (top1+top2+etc)` | -1 ~ 1 |
| 물량 0인 날 | `top1_region`, `top2_region` 모두 NULL |

## 10.7 주의사항

- **NBSP 구분자**: 원본 `1위`/`2위` 컬럼의 구분자는 일반 공백(U+0020)이 아니라 **NBSP(U+00A0)** 이다. 일반 공백 기준으로 split 하면 파싱이 통째로 실패한다.
- **0톤인 날**: 데이터가 없는 날은 지역명 없이 `0톤`만 존재한다. 이때 `top1_region`/`top2_region`은 NULL이며, 이는 "산지 정보 없음"이지 "물량 0인 산지"가 아니다.
- **±1 반올림 오차**: `합계_톤`과 `1위+2위+기타`는 원본 반올림 때문에 최대 ±1 차이가 난다. 합계 검증 CHECK를 기본 비활성화한 이유이며, 물량 비율을 계산할 때는 `total_ton`과 부분합 중 어느 쪽을 분모로 쓸지 명시해야 한다.
- **정수 반올림**: 원본이 소수를 포함하더라도 `round(...)::int`로 적재되어 소수점 정보는 보존되지 않는다. 2.1의 "원형 보존" 원칙에 대한 예외이므로, 소수 정밀도가 필요해지면 타입을 `NUMERIC`으로 변경해야 한다.
- **CSV 인코딩**: UTF-8 BOM + CRLF. `HEADER true`로 헤더행을 버리면 BOM은 무해하고 CRLF는 `COPY`가 자동 처리한다.
- **단일 품목**: 현재 `item_label`은 `배추` 단일값이다. PK에 `item_label`이 포함되어 있어 품목 확장은 가능하나, 확장 시 품목별 톤 단위 기준이 동일한지 먼저 확인해야 한다.
- **시장 범위 확인 필요**: `crop_price_train`의 `arr_qty_*`는 가락시장 반입량으로 정의되어 있다. 이 테이블이 가락시장 단독 집계인지 전국 도매시장 합계인지 확정한 뒤 결합해야 하며, 범위가 다르면 Feature 정의를 수정해야 한다.
- **`req_date` 활용**: 수집일이 기준일보다 늦을 수 있으므로, 미래정보 누출 방지 관점에서 as-of 결합 시 `base_date`가 아니라 `req_date`가 실제 이용 가능 시점이다.

# 11. `crop_price_train`

## 11.1 목적

농산물 약 3주 범위의 일별 가격 예측 모델을 학습하기 위한 통합 데이터 테이블이다.

기준일 기준으로 가격·반입량·주산지 기상·소비지 기상·도메인·경제 변수를 결합하고, 예측 대상일까지의 리드타임을 명시한다.

이 테이블은 RAW가 아니라 TRAIN 계층이다.

v2에서는 단순 기상 변수 대신 **품목 및 작형/시기에 맞는 주산지 관측소 기준 기상정보**를 사용하도록 변경했다.  
또한 최근 30일 적산온도(GDD)를 추가하고, 소비지인 서울 가락시장 주변의 직전일 평균기온을 보조 변수로 추가했다.

## 11.2 키 및 제약

- PK: `id`
- UNIQUE: `base_dt + item_nm + lead_biz_d`
- `lead_biz_d`: 1~18
- `kimchi_season_yn`: 0 또는 1
- `market_closed_lag1_yn`: 0 또는 1

## 11.5 주산지 기상 적용 원칙

품목별 날씨는 전국 ASOS 단순 평균을 사용하지 않는다.

```text
품목
  ↓
작형 / 계절
  ↓
주산지 결정
  ↓
주산지와 대응되는 ASOS 관측소 결정
  ↓
해당 관측소의 과거 기상정보 계산
  ↓
crop_price_train Feature 생성
```

동일 품목이라도 계절과 작형에 따라 주요 생산지역이 달라질 수 있으므로 관측소를 품목 하나에 영구 고정하지 않는다.

## 11.6 적산온도(GDD)

`prod_area_gdd_sum30`은 최근 30일 동안 작물 생육에 유효한 온도를 누적한 값이다.

기본 계산 개념:

```text
일별 GDD = max(일평균기온 - 작물별 기준온도, 0)

최근 30일 GDD
= 최근 30일의 일별 GDD 합계
```

작물별 기준온도는 별도 기준정보 또는 Feature 생성 규칙으로 관리한다.

## 11.7 미래정보 누출 방지

이 테이블은 예측 기준일 당시 실제로 알 수 있었던 정보만 포함해야 한다.

특히:

- `target_auc_prc`는 정답 라벨이며 입력 Feature에 포함하지 않는다.
- 주산지 기상은 `base_dt` 이전까지 실제 관측된 데이터만 사용한다.
- 중기예보는 `base_dt` 당시 실제 발표되어 있었던 예보만 사용한다.
- KREI 정보는 해당 `report_mon` 또는 실제 공개시점 이전 예측에 사용하지 않는다.
- 재배면적 등 저빈도 자료는 실제 발표 이후부터 적용한다.
- 경제변수도 실제 이용 가능 시점을 기준으로 결합한다.
- 연/월 단위 통계를 기준기간만 보고 과거 날짜에 소급 적용하지 않는다.

# 13. 시간축 결합 원칙

데이터 주기가 다르기 때문에 모든 데이터를 일별로 강제 변환해서 같은 의미로 취급하면 안 된다.

```text
ASOS             = 실제 일별 관측
채소 가격         = 실제 일별 가격
반입 물량         = 실제 일별 관측 (수집일 req_date 별도 존재)
국고채            = 거래일 관측 + 비거래일 전달
M2/EPU/PPI/CPI   = 월별 통계의 일별 적용
KREI 가격         = 월별
KREI 생산         = 연산/월보
KREI 수입         = 월별
KREI 재고         = 연산/월보
```

권장 결합 방식:

```text
기준일(base_dt)
     ↓
그 날짜까지 실제 공개된 최신 데이터 탐색
     ↓
as-of join
     ↓
feature 생성
```

핵심은 **자료가 의미하는 기간(reference period)**과 **실제로 공개된 시점(publication/report date)**을 구분하는 것이다.
