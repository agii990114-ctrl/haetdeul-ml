## 1. 경락가 — `auction_prices_daily`

**우리가 사는 값입니다.** 매입 판단의 핵심입니다.

```
출처    공공데이터포털 (data.go.kr) · 농수산식품유통공사(aT) 제공
주소    https://apis.data.go.kr/B552845/katOrigin/trades
인증    DATA_GO_KR_KEY  (.env)
수집기  데이터 수집/경락가 수집/auction_collector_handoff/
실행    python -m auction_collector update --load-postgres
```

### 이 API 의 특징 — 다른 것과 다릅니다

**거래 한 건마다 한 줄을 줍니다.** 하루치 합계가 아닙니다.

```
2026-08-27  가락  배추  특  그물망 10kg   6,500원   ← 이런 줄이 하루 수천 개
```

그래서 **포장 규격이 그대로 들어 있습니다** (`pkg_nm` · `unit_qty` · `gds_sclsf_nm`).

**2026-08-27 에 이걸 처음 쓰기 시작했습니다.** 그전에는 규격을 버리고 (날짜·시장·품목·등급)으로만 뭉쳐서, 그물망 10kg(710.8원/kg)과 소포장 1kg(11,223.7원/kg)이 한 평균에 섞여 있었습니다. 지금 타겟은 그물망+파렛트 10kg 를 합친 721.9원입니다.

### 범위와 한계

```
현재 보유   2017-01-02 ~ 2026-08-27
못 받은 것  2015~2016  (재수집 때 일일 쿼터 소진)
쿼터        일 10,000회. 전 구간 재수집에 약 12,000회 필요
시장        전국 32개 (우리는 서울가락 110001 만 씀)
```

**2015~2016 은 나중에 받아야 합니다.** "2017부터 학습" 판정을 다시 하려면 필요합니다.

## 2. 중도매가·소매가 — `veg_daily_price_raw`

**우리가 파는 값**(소매)과 **중간 값**(중도매)입니다.

```
출처    공공데이터포털 (data.go.kr) · aT KAMIS
주소    https://apis.data.go.kr/B552845/perDay/price
인증    DATA_GO_KR_KEY  (.env)
수집기  데이터 수집/중도매, 소매가/collect_kamis.py
실행    python collect_kamis.py
범위    2015-01-02 ~ 2026-08-27 · 1,044,775행
```

### ⚠ 이 원천은 **품목 이름을 바꿉니다**

실제로 두 번 당했습니다.

```
item_cd 241   2025 까지 '고추'  →  2026~ '건고추'
item_cd 244   2025 까지 '마늘'  →  2026~ '피마늘'
```

이름으로 최신일을 찾다가 **"신규 0행" 으로 보고하면서 매번 8개월치를 다시 받고** 있었습니다. 지금은 `item_cd` 로 찾습니다.

**품목을 세거나 최신일을 찾을 때 이름을 쓰지 마십시오.**

```
211 배추 · 231 무 · 241 건고추 · 244 피마늘 · 245 양파 · 258 깐마늘(국산)
```

**244(피마늘)와 258(깐마늘)은 다른 물건입니다.** 유통 마진이 다릅니다 (경락 3,398 → 피마늘 5,778 / 깐마늘 7,385).

## 4. 반입량 — `daily_volume`

**얼마나 들어왔나**입니다. 공급량 신호입니다.

```
출처    농넷 (nongnet.or.kr) 수급일보
주소    https://www.nongnet.or.kr
방식    ★ API 가 아니라 화면 긁기 (스크래핑)
수집기  데이터 수집/일일 산출량/농넷에서 일일산출량 적재.py
        → load_daily_volume.py
범위    2014-12-24 ~ 2026-08-28 · 18,285행
```

### 다른 것과 다른 점 — **깨지기 쉽습니다**

**API 가 없어서 화면을 긁습니다.** 그것도 표가 아니라 **화면에 숨어 있는 자바스크립트**를 읽습니다.

```javascript
tmpObj["dayStr"]      = "01/20";
tmpObj["rank1Weight"] = "719";     ← 여기서 뽑아냄
```

표에는 "조회된 데이터가 없습니다" 라고 나와도 이 값은 살아 있어서, 이쪽을 읽으면 2015년까지 거슬러 올라갑니다.

**농넷이 화면을 바꾸면 바로 깨집니다.** 다른 원천은 API 라 규격이 보장되지만 이건 아닙니다.

### 값이 나중에 정정됩니다

```
2026-08-25 배추   기존 [4, 2, 1, 1]  →  신규 [623, 120, 112, 391]
```

**당일치는 잠정값이고 며칠 뒤 정산됩니다.** 그래서 최근 구간은 덮어쓰고, 오래된 구간은 그대로 둡니다.

```
~2026-08-13   기존 유지 (대조만)
2026-08-13~   정정 반영
```

느립니다 — **20~25분**. 배치에서 가장 오래 걸리는 단계입니다.

## 5. 경제지표 — `econ_daily_raw`

**모델에서 뺐습니다.** 테이블은 남아 있습니다.

```
출처    한국은행 ECOS  (M2 통화량 · PPI 생산자물가)
        https://ecos.bok.or.kr/api
        KDI 경제정책불확실성(EPU)
        https://eiec.kdi.re.kr/bigdata/epu.do
인증    ECOS_API_KEY  (.env)
수집기  데이터 수집/경제 지표/fetch_economic_variables.py
범위    ~2026-06-30 · 4,199행
```

### 왜 뺐나 — 세 타겟 모두 성능이 **나빠졌습니다**


| 타겟   | 넣었을 때  | 뺐을 때       |
| ---- | ------ | ---------- |
| 경락가  | +6.8%  | **+8.7%**  |
| 중도매가 | +6.1%  | +7.2%      |
| 소매가  | +12.7% | **+15.3%** |


**월·분기 단위로 갱신되어 한 달 내내 같은 값이 반복됩니다.** 모델이 이걸 "지금이 몇 월인지 알려주는 표시" 로 오용해 외워버립니다.

증거가 있습니다 — 빼고 나니 모델이 **트리를 3배 더 쌓았습니다** (33~~51 → 102~~140). 경제 변수가 학습을 일찍 멈추게 하고 있었다는 뜻입니다.

**그래서 매일 안 받습니다.** 일별 배치는 `--skip collect_econ` 이고, 주 1회 별도 작업으로 받습니다. **59일 지연은 정상입니다.**

## 6. 공휴일 — `ref_holiday`

**미래 날짜를 세려면 필요합니다.**

```
출처    공공데이터포털 · 한국천문연구원 특일 정보제공 서비스
주소    http://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService
수집기  데이터 수집/휴일 달력/fetch_holidays.py
갱신    연 1회
범위    ~2028-12-25 · 264행
```

리드타임 1~18영업일을 세려면 **앞으로의 휴일**을 알아야 합니다. 그래서 미래까지 채워 둡니다.

### 축이 두 개입니다

```
중도매가 조사일   토·일 + 공휴일 + 12월 첫째 금요일
가락 경매 거래일  일 + 신정 + 명절 당일~+2일 + 8월 첫 토요일 + 비정기
```

**두 축의 규칙이 다릅니다** (3,348일 vs 2,700일). 하나로 쓰면 리드타임이 어긋납니다.

> **비정기 휴장은 게시판이 아니라 실거래일로 찾습니다.** 공고 본문이 대부분 이미지라 게시판을 못 믿습니다. "규칙상 개장인데 거래 0건" 을 뽑는 방법으로 14건을 찾아 오탐 0 · 미탐 0 을 만들었습니다.
> 아직 안 지난 날만 `watch_garak_notice.py` 로 월 1회 확인합니다
> (`https://www.garak.co.kr/homepage/M0000227/board`).

## 7. 학사일정 — `ref_school_day`

**판정 완료 · 기각.** 테이블만 남겼습니다.

```
출처    NEIS 교육정보 개방 포털
수집기  데이터 수집/학사일정/build_school_day.py
범위    2015~2028 · 5,114행
```

급식 수요 가설로 만들었는데 **3폴드 모두 부호가 갈려 기각**했습니다. 재실험할 때 다시 안 받아도 되게 테이블은 남겨뒀습니다.

`train.py` 의 `SCHOOL_COLS` 로 기본 제외되어 `--with-school` 없이는 안 섞입니다.

> **실측이 아니라 연중 프로파일입니다.** NEIS API 는 최근 2개 학년도만 갖고 있어 학습 구간 커버리지가 36.6% 였습니다. 결측을 그대로 두면 "2020-09 이전인가" 가 시점 표시가 되어 경제 변수와 같은 함정에 빠집니다.

## 알아둘 함정 셋

**① 원천이 이름을 바꿉니다** — `item_cd` 로 찾으십시오 (§2)

**② 값이 나중에 정정됩니다** — 반입량은 당일치가 잠정값입니다 (§4)

**③ 이상한 숫자를 그냥 넘기지 마십시오**

경락가 `max 19,900원/kg` 이 2015년부터 있었습니다. 평균의 21배인데 **어떤 검사도 이걸 보지 않았습니다.** 규격이 섞여 있다는 신호였고, 알아채는 데 1년 넘게 걸렸습니다.

지금 붙이려는 검사 셋입니다.

```
등급 순서    특 ≥ 상 인가?                  → 90% 의 날에 위반 중이었음
일중 분산    최고 ÷ 최저 가 10배 넘는가?     → 132배였음
계열 건전성  어제→오늘 연결이 0.3 미만인가?   → 0.085 였음
```
