## 4. Three decision rules added, each paid for

**Rule ③ — anything going to production must see fold C.**
Two-fold agreement plus 2×seed-sd is a *search* bar, not an *adoption* bar.

**Rule ④ — reproducibility does not catch a condition error.**
`auc_prc_spread_lag1` reproduced across two disjoint seed sets and was still
void, because the harness was training on the wrong data.
*Reproduction tells you "not luck." It does not tell you "measured the right thing."*

**§8 — folds answer relative questions, not absolute ones.**
Fold C trains 4 years, fold B 5, fold A 6, production 7. Onion needs more than
five years to beat its anchor (retail onion: 3yr −43.0% → 5yr +13.5%), so any
question whose answer depends on training volume cannot be settled by folds.

**A first ingest check, gating the rebuild.** v5 truncates before it rebuilds, so
this is the last place to stop bad data. Six checks; it caught the ten-day stall

# Friday 2026-09-04

## 1. ★★ Base dates had been one day stale for eight months

A `base_dt = D` row uses **only data through D−1** — the anchor is
`whsl_prc_lag1`. It never touches D's own value. But `predict_input` drew base
dates from *observed* days, so it waited for a value it then discarded.

```
morning of 09-04, data through 09-03
   produced   base_dt 09-03, anchor = 09-02   -> daily[0] = today
   available  base_dt 09-04, anchor = 09-03   -> daily[0] = tomorrow
```

**Two losses, not one:** the anchor was a day old *and* the horizon a day short.
The buying team's contract expects `daily[0] == as_of + 1`; they measured
**26 of 248 days passing.**

Fixed by inserting phantom base-date rows inside STEP 8 only. Training table
unchanged (201,178 rows); overlap comparison 0 mismatches on 1,404 rows.

## 2. ★★ The batch was discarding its own validation results

`do_rebuild` ran v5 as one blob and threw every result set away:

```python
cur.execute(sql)
while cur.nextset():
    pass          # validation results vanish here
```

Check [14] had been reporting **100% mismatch for a week** (v5.3 added ten
derived columns without updating STEP 8) and nobody saw it. Predictions were
unaffected — those ten columns are excluded from model input — but *the check
that exists to catch divergence was drowned.*

`SQL/verify_after_rebuild.sql` now returns
`(check, severity, bad, total, detail)` and **BAD stops the batch.** Tested:
a planted BAD stops it; a broken check does not (alerting must not kill the run);
a missing file does not. Real run: *"6 checks passed."*

## 3. Two more of the same shape

## 4. Drift detection built [I-04]

Measured as **gain against the anchor**, not raw error. Rising error in a
volatile month means the market moved, not that the model decayed — the anchor
rises with it and the ratio holds.

Rules: per item × target only; 60 rows per week minimum or no verdict; three
consecutive bad weeks before it speaks; **it never triggers retraining.**

**The first rule I wrote was wrong.** *"10pp below the 8-week median"* flagged
weeks the model had **won**, because a high baseline puts the threshold above
zero — and the ratio explodes when the anchor is very accurate
(anchor 4.0%, model 14.6% → −263.9%). Replaced with the **error gap in points**:
*"the model is more than 1pp worse than the anchor."* Cannot inflate, cannot explode.

## 6. Why 5% is not reachable on auction price

Asked whether 5% error is a viable target. Measured:

```
current            cabbage 16.0% · radish 19.6% · onion 13.7%
market movement    18.2% · 19.9% · 16.8% over the same horizon
we capture         12.1% · 1.5% · 18.5% of that movement
5% would require   ~72–75% capture
```

**Radish is essentially the anchor** (market 19.9%, model 19.6%).

The ceiling on supply information is already measured. From the 08-26 oracle
experiment: **perfect knowledge of target-day arrival volume moves
0.1801 → 0.1749 — 2.9–4.0% relative.** Most price movement is not explained by
volume at all. And the cascade that would deliver it is self-defeating: 70.5% of
the volume model's importance comes from features the price model already has,
and **5x the value sits in the residual no model can produce.**

Where 5% *is* already met: **retail, short lead times** (retail cabbage LT3–5 is
5.1%). Auction at LT11–18 is 17.4–21.5%.
