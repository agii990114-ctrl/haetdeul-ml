# QA 해석기 — 로컬 LLM(ollama) 대 Gemini 비교 (2026-09-17 16:39:44)

## 결론

**지금 운영에는 로컬 LLM 을 쓰지 않습니다.** 같은 지시문 · 같은 스키마 · 같은
채점표(정답을 아는 질문 17개 × 칸 4개 × 2회차 = 136칸 · 기준일 2026-09-14 ·
날짜 목록 판)로 재 보니, 판정 가능한 132칸 기준으로 Gemini 는 98.5% 를 맞히고
로컬에서 가장 나은 `gemma4:e2b` 는 87.9% 였습니다. 문항당 시간도 Gemini 1.5~1.8초
대 gemma4 12.3초입니다. 무엇보다 **로컬 모델 둘 다 우리가 다루지 않는 품목
(대파 · 마늘)을 거절하지 못하고 배추 · 무 · 양파 중 비슷한 것을 골라 버립니다.**
그러면 엉뚱한 품목의 값이 답으로 나갑니다. Gemini 는 거절합니다. 로컬은
API 키가 없거나 한도를 다 썼을 때의 비상용 · 오프라인 시연 자리에만 값이
있고, 그때도 지켜야 할 규칙(아래 «판단» 참조)이 아직 코드에 없습니다.

## 무엇을 비교했나

**대상은 채팅 질의응답(QA) 에이전트의 «해석기» 입니다.** 해석기는 사용자의
질문을 읽고 네 가지를 미리 정한 목록에서 고릅니다.

```
갈래       가격 / 배치 / 성능 중 무엇을 묻는가
품목       배추 / 무 / 양파
가격 종류  경락가 / 중도매가 / 소매가
날짜       어느 날을 묻는가
```

해석기는 숫자를 만들지 않습니다. 고르기만 합니다. 이 자리에서 LLM(글을
읽고 답을 내는 인공지능 모델)을 한 번 부릅니다.

**지금 운영**은 Google Gemini `gemini-3.5-flash-lite` 입니다. API(인터넷으로
부르는 방식)이고 무료 등급이라 분당 15회 한도가 있으며 팀이 나눠 씁니다.

**로컬 후보**는 이 PC 에 깔린 ollama 0.34.1 로 돌리는 모델입니다 (로컬 =
인터넷 없이 내 컴퓨터에서 돌리는 것). GPU 는 RTX 3050 6GB 입니다. 모델은 셋입니다.

| 모델 | 크기 | 양자화 | 파일 | 비고 |
|---|---|---|---|---|
| `gemma4:e2b` | 5.1B | Q4 | 7.2GB | thinking/tools 지원 |
| `gemma3:4b` | 4.3B | Q4 | 3.3GB | 연기 시험 1회만 · 21.6초에 정답 |
| `exaone3.5:2.4b` | 2.7B | Q4 | 1.6GB | |

셋 다 100% GPU 에서 돌았습니다.

**방법.** 코드에 공급자 스위치를 넣었습니다 (`ML_LLM_PROVIDER=ollama`). 응답
JSON 스키마(답의 모양을 정한 틀)를 ollama 의 `format` 에 그대로 넘기고,
temperature 0(매번 같은 답을 내도록 하는 설정) · timeout 60초로 두었습니다.
그래서 **같은 지시문 · 같은 스키마 · 같은 채점표**로 잴 수 있습니다.

채점표는 정답을 아는 질문 17개 × 칸 4개(갈래 · 품목 · 가격 종류 · 날짜) ×
2회차 = 136칸입니다. 기준일은 2026-09-14 이고, 날짜는 목록(enum)에서 고르는
판입니다. 이 중 4칸(«얼마나 맞아?» = accuracy · «믿고 사도 돼?» = usability
기대값)은 09-16 갈래 개편 뒤에 어떤 모델도 못 맞히는 칸이라, 이를 뺀
**«판정 가능 칸» 132** 로도 셌습니다.

## 틀린 문항 (목록 판)

**gemma4:e2b — 20칸**

- 「대파 내일 얼마야?」→ 범위 밖이라 거절해야 하는데 품목 = 배추
- 「마늘 경락가 알려줘」→ 품목 = 무
- 「배추 경락가 예측 얼마나 맞아?」→ perf (구조상 못 맞히는 칸)
- 「양파 중도매가 예측 믿고 사도 돼?」→ perf/forecast (구조상 못 맞히는 칸)
- 「모든날의 배추 경락가…」· 「배추 경락가 전부 다 보여줘」→ 2회차에만
  날짜 목록에서 09-29 · 09-30 이 빠지고 10-01 · 10-02 가 들어감

**exaone3.5:2.4b — 40칸 (두 회차가 완전히 같음)**

## 판단

**지금 운영에 로컬을 쓰지 않습니다.** 이유는 넷입니다.

1. 범위 밖 품목(대파 · 마늘)을 거절하지 못합니다.
2. 판정 가능 칸 정답률이 87.9% 대 98.5% 입니다 (gemma4 대 Gemini · 132칸 · 기준일 2026-09-14 · 목록 판).
3. 문항당 12.3초 대 1.5초입니다.
4. 같은 질문에 답이 흔들립니다 (gemma4 · 17문항 중 8).

**로컬이 값을 갖는 자리**는 API 키가 없거나 한도를 다 썼을 때의 비상용, 그리고
오프라인 시연입니다. 그때는 **«질문에 배추 · 무 · 양파 낱말이 없는데 품목이
차 있으면 그 답을 버리는» 규칙을 코드에 넣어야 합니다.** 아직 넣지 않았습니다.
