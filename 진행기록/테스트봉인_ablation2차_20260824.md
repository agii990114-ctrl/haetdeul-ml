## 1. 요약

1. `train.py` 에 `--valid-end` / `--report-test` 를 추가해 **학습 2017~2022 / 검증 2023 / 테스트 2024~2025** 로 3분할했다. early stopping 과 모든 판단은 검증 2023 으로만 한다.
2. 봉인 기준점을 잡기 위해 테스트를 **이번 한 번** 열었다. **중도매가의 +7.2% 는 2023년 한 해가 만든 값**이었고 2024~25 에서는 +0.6% 다. 소매가만 두 구간 모두 안정적이다.
3. ablation 2차(시드 10, 검증 2023)와 교차 확인용 2022 폴드를 돌렸다. **그룹 판정이 연도마다 뒤집힌다.** 두 폴드에서 같은 방향으로 유의한 그룹이 없어 **feature 변경 없음**.
4. `ref_calendar` 규칙을 실측 대조로 수정했다. 원래 가정(전날~다음날, 신정 1일)은 틀렸고, **명절 당일~+2일 · 신정 1/1~1/2 · 8월 첫 토요일** 이 맞다. 규칙 오탐 0건, 잔여 비정기 휴장 연 1.3회.

## 2. 3분할 성능 (봉인 기준점)

### 읽는 법

- **중도매가 무 −13.2%**: 테스트 구간 baseline 이 0.1385 로 검증(0.1946)보다 훨씬 조용한 시장이다. 변동이 작은 해에는 모델이 개입할수록 손해다. 중도매가는 LT1~10 이 전부 음수(LT3 −15.2%)이고 LT14 부터 양수로 돌아선다.
- **경락가 양파**: 두 구간 모두 음수. 경락가 양파는 모델을 쓰지 않는다는 기존 권고 유지.
- **소매가**: 세 품목 × 두 구간 모두 양수. 리드타임이 길수록 좋다(LT18 검증 +21.9%, 테스트 +19.4%). 매도 판단용으로 가장 믿을 만하다.
- **경락가 best_iter 가 34~814 로 흔들린다.** 검증 기준일이 245개뿐이라 조기종료 신호가 불안정하다. 시드 5 앙상블이 이를 완충하지만, 단일 시드 결과는 믿지 말 것.

### 기록

```
경락가  검증 0.1771 / 테스트 0.1643 (배추/양파/무 · 학습 2017~2022 · 검증 2023 · 테스트 2024~2025 ·
                                    앵커변환 · 시드5 · feature 31 · 경제 제외)
중도매가 검증 0.1357 / 테스트 0.1457 (동일 · feature 31 · 경제 제외)

```

**테스트 구간은 다시 봉인한다.** 다음 개봉은 feature 세트나 모델 구조가 바뀌어 최종 확인이 필요할 때 한 번.

## 3. ablation 2차 — leave-one-out

출발점은 1차 확정 feature 세트(경제 제외, 소매는 기상도 제외). 시드 10(42~51).
판정: 손실 > 편차×2 → O(필요) · 손실 < −편차×2 → X(빼는 게 나음) · 그 외 △.

### 폴드 A: 학습 2017~2022 / 검증 2023

| 제거 그룹 | 경락가 손실 | 판정 | 중도매가 손실 | 판정 | 소매가 손실 | 판정 |
|---|---|---|---|---|---|---|
| lag | +0.0003 | △ | +0.0035 | O | +0.0017 | O |
| anchor_season | +0.0018 | O | −0.0007 | △ | −0.0009 | △ |
| calendar | −0.0004 | △ | +0.0031 | O | +0.0018 | O |
| weather | −0.0009 | △ | +0.0018 | △ | (제외됨) | |
| volume | +0.0014 | △ | +0.0018 | △ | +0.0002 | △ |
| auction | **−0.0088** | **X** | −0.0037 | X | −0.0012 | X |

### 폴드 B: 학습 2017~2021 / 검증 2022 (교차 확인)

| 제거 그룹 | 경락가 손실 | 판정 | 중도매가 손실 | 판정 | 소매가 손실 | 판정 |
|---|---|---|---|---|---|---|
| lag | −0.0014 | △ | +0.0009 | △ | +0.0012 | △ |
| anchor_season | +0.0021 | △ | +0.0005 | △ | +0.0002 | △ |
| calendar | −0.0034 | X | −0.0031 | △ | **+0.0072** | O |
| weather | **+0.0087** | **O** | +0.0032 | O | (제외됨) | |
| volume | −0.0016 | △ | −0.0049 | X | −0.0055 | X |
| auction | +0.0024 | O | +0.0025 | O | +0.0023 | O |

### 판정

**폴드 A 에서 X 였던 auction 이 폴드 B 에서는 세 타겟 모두 O 다.** weather 도 A 에서 △, B 에서 O. 한 해 검증으로 feature 를 넣고 빼면 그 해에만 맞는 결정을 하게 된다.

두 폴드에서 **같은 부호로 일관된** 그룹만 추리면:

| 그룹 | 결론 |
|---|---|
| lag (소매) | 두 폴드 모두 양수 → 유지 |
| calendar (소매) | 두 폴드 모두 O → 유지. `holiday_remain_d` 의 기여 재확인 |
| anchor_season (경락) | 두 폴드 모두 양수(+0.0018, +0.0021) → 유지 |
| volume (중도매·소매) | B 에서 X, A 에서 △ → **제거 후보**이나 A 에서 부호가 반대라 보류 |
| auction | A/B 부호 반대 → 판정 불가, 유지 |
| weather (경락·중도매) | A △ / B O, B 의 손실이 크다 → 유지 |

**결론: feature 변경 없음.** 1차 ablation(경제 제외·소매 기상 제외)은 그대로 둔다.

### 이번 실험이 바꾼 것

feature 결정 규칙을 강화한다.

> **폴드 두 개(2022·2023) 에서 손실의 부호가 같고, 합산이 편차×2 를 넘어야 채택·제거한다.**

`ablation.py` 는 `--train-end 2021-12-31 --valid-end 2022-12-31` 로 폴드 B 를 돌릴 수 있다.
`ablation_result_2fold.csv` 에 두 폴드를 합친 표를 남겼다.

## 4. ref_calendar

### 규칙 검증

`auction_prices_daily` 서울가락(110001) 실제 거래일 2016-01 ~ 2026-08 (3,526일) 과 대조.

| 규칙 | 결과 |
|---|---|
| 원안: 일요일 + 신정 1/1 + 설·추석 전날~다음날 | 오탐 18건(규칙상 휴장인데 거래) · 미탐 63건 |
| **수정: 일요일 + 신정 1/1~1/2 + 설·추석 당일~+2일 + 8월 첫 토요일** | **오탐 0건 · 미탐 14건** |

원안의 오탐 18건은 전부 명절 **전날** 이었다. 가락시장은 명절 전날 거래하고 당일부터 사흘 쉰다.
미탐 63건 중 신정 1/2(매년), 8월 첫 토요일(12년 연속 하계휴장)이 규칙으로 흡수됐다.

잔여 14건(연 1.3회): 명절 연휴가 월요일에 붙는 징검다리 3건, 2023-11 이후 토요일 시범 휴업 등 비정기 11건.
규칙화 불가 → `ref_calendar_override` 테이블로 관리.

### 산출물

`SQL/25_ref_calendar.sql` — `ref_lunar_holiday`(명절 당일, ~2030) · `ref_calendar_override`(비정기) · `ref_calendar`(2015~2030, `is_open`, `close_reason`, `biz_seq`).
`biz_seq` 차이가 곧 `lead_biz_d` 다. 로컬 PostgreSQL 16 에서 실행 확인.

```sql
-- 기준일에서 18영업일 뒤
SELECT t.dt FROM ref_calendar b
JOIN ref_calendar t ON t.is_open AND t.biz_seq = b.biz_seq + 18
WHERE b.dt = CURRENT_DATE;      -- 2026-08-24 → 2026-09-14
```

**주의**: 2027 이후 명절 날짜는 미검증. 운영 전 달력 확인. 파일 끝의 대조 쿼리가 0행이면 정상.

`DBEAVER_run_v5.sql` 과 독립이라 실행 순서 무관.
