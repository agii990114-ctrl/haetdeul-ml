## 0. 먼저 — 세 갈래가 서로 모릅니다

**이 문서에서 제일 헷갈리기 쉬운 곳입니다.** 감시가 도는 길이 셋인데,
**서로 결과를 주고받지 않습니다.** 각자 처음부터 다시 봅니다.

```
   ┌ 갈래 1 ─ 09:00 배치가 실패한 그 순간 ──────────────────────────┐
   │   규칙(항상)  +  Gemini(키 있으면)   →   ALERT.txt            │
   │   ↑ 여기서 한 번 끝납니다                                      │
   └───────────────────────────────────────────────────────────────┘

   ┌ 갈래 2 ─ 09:23 별도 스케줄 ────────────────────────────────────┐
   │   Claude 가 **처음부터 다시** 봅니다                            │
   │   갈래 1 의 결과를 이어받지 않습니다                             │
   │   →  진행기록/agent_logs/YYYY-MM-DD_claude_check.md            │
   └───────────────────────────────────────────────────────────────┘

   ┌ 갈래 3 ─ 사람이 화면을 열 때 ──────────────────────────────────┐
   │   규칙만 그 자리에서 돕니다. AI 안 부름                          │
```

**"Claude 가 Gemini 다음" 이 아닙니다.** 20분 뒤에 도는 **딴 것**입니다.
갈래 1 이 아예 안 돌아도(배치가 성공하면 안 돕니다) 갈래 2 는 그대로 돕니다.

### 왜 이어붙이지 않았나

이어붙이면 **앞 갈래가 죽었을 때 뒤 갈래도 같이 죽습니다.** 그리고 앞이 낸
틀린 답을 뒤가 그대로 물려받습니다.

실제로 오늘 그 값을 봤습니다 — 09:23 Claude 점검이 **갈래 1 이 만든
`batch_agent` 의 버그 3개를 잡았습니다.** 앞의 결과를 물려받았다면
"연속 5회 실패" 를 사실로 믿고 그 위에 얘기를 쌓았을 것입니다.

**독립이라서 앞의 잘못을 잡을 수 있습니다.**

## 0-2. 세 AI 를 어디에 왜 쓰나

같은 문제(`run 28` · `_anchor_mix` 사고)를 셋에게 줘서 대조한 결과입니다
(2026-08-31 실측).

| | 어디서 실패 | **왜** 실패 | 검사 자체의 오류 | AI 죽어도 |
|---|---|---|---|---|
| **규칙만** | ✅ | ❌ | ❌ | — |
| **Gemini** | ✅ | ✅ 파일·줄 번호까지 | ❌ | 규칙은 나옴 |
| **Claude** | ✅ | ✅ | **✅** | 규칙은 나옴 |

```
규칙만    "predict 단계에서 3번 연속 실패했다"

Gemini    "predict.py 가 train.py 가 만든 _anchor_mix 컬럼을 안 만든다.
           120줄에서 막히고 280줄이 그 자리다"     ← 도구 9번 스스로 골라 씀

Claude    위와 같은 것 + "그런데 batch_agent 의 '연속 5회' 는 과장이다.
           5건 중 원인이 3가지고 중간에 성공이 두 번 있었다"
```

**둘 다 살려둡니다.**

```
Gemini   배치가 실패한 그 순간에 붙어 있다 (즉시 · 자동)
Claude   20분 뒤에 더 깊게 본다 (검사 자체도 의심)
```

**Gemini 를 지울 이유가 없습니다.** 09:00 에 붙어 있는 건 Gemini 고,
Claude 는 20분 뒤에 옵니다. 그 20분 사이에 사람이 `ALERT.txt` 를 열 수 있습니다.

> **다만 Gemini 무료 등급은 보낸 내용을 학습에 씁니다.** 그래서 `agent/mask.py`
> 가 접속 문자열·API 키·`.env` 를 가리고 내보냅니다.

## 2. ★ 가장 중요한 규칙 — 규칙이 판단하고, AI 는 설명만

```
규칙(코드)   이상을 찾아낸다        매번 똑같은 답. 확실함
AI          원인을 조사해 설명한다   사람이 하던 일
```

### 왜 이렇게 나눴나

**AI 가 조용히 죽으면 "이상 없음" 처럼 보이기 때문입니다.**

우리가 실제로 세 번 당했습니다.

```
08-27  성공했는데 경보 파일이 안 지워져 "매일 실패 중" 으로 보임
08-31  매입 파트: LLM 호출이 계속 실패했는데 결과물은 멀쩡해 보임
08-31  경락가 수집기가 0건 받고 "성공" 보고 → 하루가 통째로 비었는데 사흘 방치
```

**그래서 모든 검사는 AI 없이 끝까지 돕니다.** AI 는 그 위에 사람 말 요약을
얹는 선택지일 뿐이고, **없어도 보고서는 그대로 나옵니다.**

실제로 확인했습니다 — Gemini 한도가 떨어졌을 때 `(AI 조사 실패: ClientError)`
만 붙고 나머지는 정상 출력됐습니다.

### 그리고 도우미에게 고치게 하지 않습니다

**단, 성격을 나눠야 합니다** (2026-08-31 에 배운 것).

```
rebuild(v5)      표를 통째로 비우고 다시 채운다 (TRUNCATE)
                 → 중간에 죽으면 데이터가 날아간다. 자동 재실행 금지

collect(경락가)   날짜 하나를 받아 UPSERT 한다
                 → 몇 번을 돌려도 같은 결과. 자동으로 다시 받아도 안전
```

처음엔 둘 다 막아뒀는데, **구멍을 찾고도 아무도 안 채우는 상태**가 됐습니다.
지금은 경락가만 배치가 스스로 다시 받습니다 (아래 §3).

## 3. 배치 안에서 — `run_batch.py`

### 단계

```
collect_auction → collect_price → collect_weather → collect_volume → collect_econ
      ↓
rebuild(v5 재생성) → predict(3타겟 추론) → load(prediction_log) → score(채점) → push(전달표)
```

### ★ collect_auction 뒤에 붙은 구멍 검사

```python
if ok and name == "collect_auction":
    ok2, gap_msg = check_auction_gap(conn, log, today)
```

**수집기의 종료코드를 믿지 않고 표를 직접 봅니다.**

```
1. ref_calendar 에서 최근 14일 중 개장일을 뽑는다
2. auction_prices_daily 에 그 날 행이 있나 본다
3. 없으면 → conn.commit() 으로 잠금을 놓고
            수집기를 --force 로 다시 부른다 (캐시 무시)
4. 다시 표를 본다. 채워졌으면 통과
5. 그래도 비었으면 실패로 알린다
   · 그날 실제로 쉬었다  → ref_calendar override 에 넣으세요
   · 원천 API 가 늦었다  → 내일 배치가 다시 시도합니다
```

> **`conn.commit()` 이 왜 있나.** 없이 만들었다가 교착을 겪었습니다.
> 검사가 트랜잭션을 열어둔 채 수집기를 불렀고, 수집기가 같은 표에 잠금을
> 걸려다 12분 넘게 멈췄습니다. 읽기만 했으니 커밋해도 바뀌는 건 없고
> 잠금만 놓습니다.

> **왜 표를 보나.** "실패했다는 말" 보다 **"결과가 없다는 사실"** 이 더
> 믿을 만합니다. 08-31 사고가 정확히 그것이었습니다 — 수집기는
> `status: ok` 라고 했는데 API 호출이 0회였습니다.

### 실패로 끝나면

```
notify()      → ALERT.txt 생성
call_agent()  → agent/batch_agent.py --run-id N --append-alert
                결과를 ALERT.txt 에 덧붙임
```

**도우미가 실패해도 배치 결과는 안 바뀝니다.** 통째로 감싸고 시간 제한(300초)을
둡니다. 알리다 죽으면 본말전도입니다.

## 4. ① 배치 장애 조사 — `batch_agent.py`

두 층입니다.

### 1층 · 규칙 (`gather`) — 항상 돕니다

```
· 어느 단계에서 실패했나 + 오류 원문 첫 줄
· 몇 번 연속 실패인가 (★ 아래 주의)
· 일시적인가 구조적인가 (문구에 낱말이 있나만 봄)
· 매입 파트 전달표가 멈췄나
```

**★ 연속 세기는 08-31 에 고쳤습니다.**

```
전   기록 전체에서 그 단계 실패를 그냥 셈 → "연속 5회" (실제로는 원인 3가지·중간에 성공 2번)
후   최근 실행부터 거꾸로 훑어 성공을 만나면 멈춤 + 오류 첫 줄이 같은 것만 따로 셈
```

**★ 전달표 신선도도 고쳤습니다.**

```
전   MAX(base_dt) 와 MAX(created_at) 을 각각 따로 뽑음
     → 8개월 전 백필을 넣었더니 "오늘 적재됨 · 정상" 이라고 함
후   가장 최근 기준일의 행만 보고, 그 행이 언제 적재됐는지 잼
```

### 2층 · AI (`investigate`) — 선택입니다

Gemini 에게 도구 6개를 주고 스스로 조사시킵니다
(`agent/tools.py`: `batch_recent` · `batch_stages` · `recent_changes` ·
`read_file` · `search_code` · `db_query`).

**밖으로 나가기 전에 `agent/mask.py` 가 비밀을 가립니다** — 접속 문자열 ·
API 키 · `.env` 내용. `read_file` 은 이름 기반으로 `.env` 를 막습니다
(`Path(".env").suffix` 가 빈 문자열이라 확장자 검사로는 못 막습니다).

**키가 없으면 `(AI 조사 실패)` 만 붙고 1층 결과는 그대로 나옵니다.**

## 5. ③ 데이터 품질 감시 — `quality_agent.py`

**"당연히 성립해야 하는 것" 넷만** 봅니다. 넷 다 우리가 실제로 당한 사고입니다.

| 검사 | 무엇을 보나 | 사고 때 | 지금 |
|---|---|---|---|
| ① 등급 순서 | 특등급이 상등급보다 싼 날 | 배추 90% | 4% |
| ② 일중 분산 | 위10% ÷ 아래10% | 섞이면 3.5배 | 1.6배 |
| ③ 계열 건전성 | 어제→오늘 연결(자기상관) | 0.085 | 0.625 |
| ④ 정답-앵커 일치 | 같은 규격에서 나왔나 | 96% 어긋남 | 0% |

### ★ ② 는 08-31 에 오탐을 고쳤습니다

```
전   그날 최고가 ÷ 그날 최저가        → 배추 10.5배 "이상"
     원인은 규격이 아니라 헐값 처분 한 건 (최저 30~50원/kg)
후   위 90% ÷ 아래 10% · 물량 1퍼센트 미만 거래 제외
```

**기준선은 짐작이 아니라 10년 실측으로 잡았습니다.**

```
규격 고정 정상값   1.19 ~ 2.23배 (2017~2026 · 연도×품목 30개)
규격 안 걸면       배추 3.5배
기준선            주의 2.5배 · 이상 3.0배   ← 그 사이
```

**잘못된 경보가 매일 뜨면 사람이 무시하게 되고, 그러면 진짜 이상도 같이
묻힙니다.** 그래서 오탐을 없앤 뒤 **진짜 이상은 여전히 잡히는지** 확인했습니다
(규격 조건을 빼고 재보니 배추 3.5배로 이상 판정에 걸림).

## 6. ⑤ 예측 설명 — `forecast_agent.py`

화면에서 그래프 점을 누르면 뜹니다. **AI 를 안 부릅니다.**

```
① 무엇을 얼마로 봤나   예측값 · 범위 · (실제값)
② 출발점이 무엇인가    0.4 × 824.0(어제값) + 0.6 × 803.6(7일평균) = 811.8
③ 얼마나 움직였나      −6.2% · 내린다고 봤습니다
④ 그날 본 값들        중요도 상위 8개 + 그날의 실제 값
⑤ ★ 한계             (명령줄만 · 화면에서는 뺌 — 2026-08-31 지시)
```

### 스위치 둘

```
with_limit=False    화면에서는 한계(지난 오차)를 뺀다
with_actual=False   실제값을 뺀다 — 운영에서는 예측 시점에 정답이 없다
```

`--no-actual` 은 시연용입니다. 지금은 지난 날짜로 돌려 정답이 이미 있지만,
**실제 운영에서는 예측을 낼 때 정답이 없습니다.** 켜 둔 채로 보면
"이만큼 맞힌다" 로 읽히는데 실제로 쓸 때의 모습이 아닙니다.

### 값을 지어내지 않습니다

| 조각 | 출처 |
|---|---|
| 예측·범위·실제 | `prediction_log` |
| 어제값·7일평균·feature 값 | `crop_price_train` |
| 섞는 비율 α | `ops_*/meta.json` |
| 중요도 | `ops_*/model_seed*.txt` |

`어제` 가 며칠인지도 **달력으로 빼서 추측하지 않습니다.** 기준일 직전 30일의
실제 가격을 뽑아 **앵커 값과 맞아떨어지는 날만** 찍고, 못 찾으면 날짜를
안 씁니다.

```bash
  --append-system-prompt "너는 무인 점검 담당이다. 파일을 고치거나 배치를
                          재실행하지 마라. 조사하고 보고만 한다." \
  "(1) batch_agent 로 배치 결과 확인 (2) quality_agent 4검사
   (3) 전달표에 오늘 기준일이 들어갔나"
```

### 왜 이 창의 예약이 아니라 작업 스케줄러인가

```
Claude Code 안의 예약   세션이 살아 있을 때만 · 7일 만료 · 창 닫으면 사라짐
작업 스케줄러           창과 무관 · 재부팅해도 살아남음 · 이미 배치가 쓰는 방식
```

### 결과 파일이 없으면 실패로 봅니다

```bat
if not exist "%OUTDIR%\%TODAY%_claude_check.md" (
  echo [경고] 점검 결과 파일이 없습니다
  exit /b 9
)
```

**종료코드만 믿지 않습니다.** 로그인이 끊기면 `claude` 가 1 을 돌려주는 걸
확인했지만, 그것 하나에 기대지 않습니다.

### 로그인 관리

```
accessToken   몇 시간마다 만료 → 재발급권으로 자동 갱신 (실측 확인)
refreshToken  한참 뒤 한 번 → 그때만 사람이 다시 로그인
```

별도 토큰(`claude setup-token`)은 만들지 않았습니다. 같은 PC · 같은 계정이라
지금 로그인 상태를 그대로 씁니다.

## 8. 화면 — `localhost:3100`

```
화면(Next.js 3100)  ──/api──▶  백엔드(FastAPI 8102)  ──▶  DB · 모델 파일
```

브라우저가 DB 에 직접 붙으면 접속 정보가 사용자 컴퓨터까지 나갑니다.
그래서 **DB 는 파이썬만 붙고, 화면은 파이썬에게 묻습니다.**

| 탭 | 부르는 것 |
|---|---|
| 예측가 그래프 | `/forecast` · 점 클릭 시 `/agent/explain` |
| 지금 상태 | `/agent/batch` + `/quality` |
| 날짜별 기록 | `/agent/history` · `/agent/report` |

**기록은 파일이 원본입니다** (`진행기록/agent_logs/`). DB 에 또 넣지 않습니다 —
두 곳에 있으면 갈라지고, 어느 쪽이 맞는지 아무도 모르게 됩니다.

`/agent/report` 는 파일 이름 모양을 통째로 못박아 경로 공격을 막습니다
(`../../.env` 같은 것이 들어오면 400).
