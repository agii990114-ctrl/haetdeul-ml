## 0. 한 장 요약

**저장 트레이딩**을 위한 가격 예측 시스템입니다.

```
산지 → [경매] → 중도매인 → [판매] → 식당·소매상 → [소매] → 소비자
        ↑                    ↑                        ↑
  경락가 예측          중도매가 예측             소매가 예측
  (싸게 매입)                                  (비쌀 때 매도)
```

**우리 파트는 예측 모델만** 담당합니다. 저장 비용·감모율·발주 수량은 다른 파트입니다.
사용자는 사내 트레이딩 판단이지, 구매 담당자 대상 서비스가 아닙니다.

| 단계 | 상태 |
|---|---|
| 데이터 파이프라인 | 완료 — SQL 한 파일로 재생성 |
| 3-타겟 모델 | 완료 — 세 모델 모두 baseline 초과 |
| feature 확정 | 완료 — ablation 3차까지. 학사일정 기각 |
| 테스트 봉인 | 완료 — 검증 2023 / 테스트 2024~ |
| 추론 입력(`predict_input`) | 완료 — v5 STEP 8 |
| **RAW 수집 재개** | **경락가·도소매·반입량 완료 · 기상만 남음** |
| 배치 파이프라인 | 미착수 |

**지금 위치**: 모델과 배관은 다 됐고, 기상 수집기 하나가 배치 가동을 막고 있습니다.

## 2. 모델 구조

### 2.1 타겟과 앵커

**타겟마다 짝이 되는 앵커가 있습니다.**

| 타겟 | 앵커 | 필터 |
|---|---|---|
| `target_auc_prc` | `auc_prc_lag1` | 서울가락(110001) · 특등급(11) |
| `target_whsl_prc` | `whsl_prc_lag1` | 가락도매 · 상품(04) |
| `target_rtl_prc` | `rtl_prc_lag1` | **서울(1101)** · 상품(04) |

### 2.2 앵커 변환 — 이 프로젝트의 핵심 설계

```
학습: y = log(target / anchor)
예측: pred = anchor × exp(model_output)     ← 역변환 필수
```

절대가격을 학습하면 모델이 리드타임을 무시하고 평균 가격만 배웁니다.
실측으로 `lead_biz_d` 중요도가 1.5%까지 떨어졌고 LT1 성능이 baseline 대비 −95%였습니다.

비율로 바꾸면 모델이 0을 출력할 때 자동으로 baseline 과 같아지므로
**baseline 아래로 떨어질 위험이 구조적으로 줄어듭니다.** 트리의 외삽 한계도 완화됩니다.

타겟 3종은 서로의 정답이므로 모두 입력에서 제외합니다.

### 2.3 성능 (검증 2023 · 2026-08-24 재측정)

학습 2017~2022 / 배추·양파·무 / 시드 42~46 / 게이트 미적용

| 타겟 | feature | WMAPE | 개선율 | 테스트 2024~25 ※ |
|---|---|---|---|---|
| 경락가 (매입) | 31 | 0.1767 | **+5.4%** | +11.8% |

**※ 테스트 열은 자연키 정렬 수정 이전 값입니다.** 다시 재려면 봉인을 열어야 하므로
배치 착수 때 최종 확인과 함께 한 번만 갱신합니다.

**품목별 편차가 큽니다. 통합값으로 판단하지 마세요.**

## 3. 확정된 결정

바꾸려면 근거를 뒤집는 실험이 먼저 필요합니다.

| # | 결정 | 핵심 근거 |
|---|---|---|
| 1 | **학습 시작 2017년** | 데이터를 줄였는데 성능이 올랐다. 2015 +5.9% / 2016 +6.6% / **2017 +6.8%**. 시드 표준편차도 2017이 최소(0.0007) |
| 2 | **경제 변수 제외** | 세 타겟 모두 손실 음수. 월·분기 갱신이라 한 달간 같은 값 → 시점 식별자로 오용. 제거 후 `best_iter` 가 33~51 → 102~140 으로 3배 |
| 3 | **소매가에서 주산지 기상 제외** | 소매가에서만 해롭다 (+12.7% → +17.1%). 유통 마진이 산지 작황을 완충. 경락·중도매에서는 기여 |
| 4 | **마늘 제외** | 중도매가가 94%의 날에 전일과 동일. 경락가 결측 11%. 서울 소매 없음 |
| 5 | **소매가 서울 한정** | 전국 평균은 2023년에 조사 점포가 44→59개로 늘어 학습·검증 집계 기준이 달라짐 |
| 6 | **KREI 재배면적 제외** | 결측 75%. 품목별로 배추·무·마늘 100%, 양파 1.4% → 사실상 품목 식별자 |
| 7 | **3분할 + 2폴드 규칙** | 검증을 2023 한 해로 좁히자 ablation 판정이 연도마다 뒤집혔다 |
| 8 | **리드타임 게이트 `--gate-lt 3`** | LT<3 은 모델 대신 앵커. 3타겟×2폴드 6조합 모두 개선 또는 동일 |
| 9 | **변동성 게이트 기각** | 저변동 분위 개선율이 폴드마다 부호 반대 |
| 10 | **학사일정 기각** | 3폴드 9조합 중 O 하나뿐. 세 타겟 모두 부호 불일치 |

### 3.1 판정 규칙 ★

> **feature 채택·제거는 폴드 두 개 이상에서 손실의 부호가 같고,
> 합산이 시드 편차×2 를 넘을 때만 합니다.**

이 규칙이 실제로 결정을 두 번 바꿨습니다.

- `auction` 그룹 — 검증 2023 에서 X, 검증 2022 에서 O
- **학사일정** — 검증 2023 에서 O(+1.9%p), 검증 2022 에서 △(음수)

`volume` 그룹은 3폴드로 재판정해 유지했습니다. 음수는 폴드 B 하나뿐이었습니다.

### 3.2 달력은 축이 두 개입니다 ★

v1 은 축이 하나였고 경매 거래일로만 검증돼 있었는데, `lead_biz_d` 는
**중도매가 조사일** 축입니다.

```
가락 경매 거래일  2015~2025   3,348일
중도매가 조사일               2,700일     ← lead_biz_d 는 이쪽
```

648일 차이는 토요일 544 + 공휴일 약 124 + 12월 첫째 금요일 11 + 역방향 16 입니다.
v2 에서 `is_open`(경매) · `is_survey`(조사) 로 분리했습니다.

```
조사 축  휴무 = 토·일 + ref_holiday + 5/1 + 12월 첫째 금요일 + override
경매 축  휴장 = 일 + 신정 1/1~2 + 명절 당일~+2일 + 8월 첫 토요일 + override
```

**비정기 휴장의 정답은 게시판이 아니라 실거래일입니다.** "규칙상 개장인데 거래 0건"
을 뽑아 14건을 찾았고 오탐 0 · 미탐 0 입니다. 다만 그 방법은 **원리적으로 과거만**
채웁니다 — 2026-08-24 에 공고를 대조해 미래 시범휴업 3건(10/10 · 11/7 · 12/12)이
개장으로 잡혀 있던 것을 찾아 넣었습니다.

## 4. 파이프라인

### 4.1 실행 순서 — 지키지 않으면 조용히 틀립니다

```
① 데이터 수집/휴일 달력/ref_holiday.sql      공휴일
② SQL/25_ref_calendar.sql                    달력 2축      (① 필요)
③ SQL/29_ref_school_day.sql                  학사일정      (독립)
④ SQL/DBEAVER_run_v5.sql   ★ 통합본           학습 테이블 + predict_input  (②③ 필요)
⑤ SQL/27_ref_prediction_band.sql             예측 구간
⑥ SQL/28_prediction_log.sql                  예측 저장
```

**`DBEAVER_run_v5.sql` 이 맨 앞에서 `TRUNCATE` 합니다.** 그보다 먼저 실행한
UPDATE 는 모두 사라집니다. 후처리는 반드시 v5 다음에. 실제로 소매가가 100% NULL 이
됐던 적이 있습니다.

`STEP -1` 이 TRUNCATE 전에 선행 조건을 확인합니다 — `ref_calendar` 가 없으면
멈추고, `ref_school_day` 가 없으면 경고합니다.

### 4.2 v5 구조

```
STEP -1  선행 조건 확인
STEP  0  TRUNCATE
STEP  1  스키마·기준정보
STEP  2  feature 생성 (INSERT)
STEP  3  평년기온 UPDATE
STEP  4  반입량 UPDATE
STEP  5  경락가 feature UPDATE
STEP  6  타겟 3종 UPDATE
STEP  8  predict_input          ← 추론 입력 (2026-08-24 추가)
검증     결과 탭 14개
```

전체 실행 약 95초입니다.

### 4.3 `predict_input` — 추론 입력

`crop_price_train` 은 **타겟이 있는 행만** 담습니다. 대상일 가격이 있는 행만
조인하기 때문에 미래 기준일 행이 원리적으로 생기지 않습니다.

STEP 8 은 같은 feature 계산을 그대로 쓰되 대상일만 달력에서 셉니다.

```sql
-- crop_price_train  대상일 = tmp_px 에 값이 있는 날        (미래 불가)
JOIN tmp_px t ON t.bn = b.bn + l.lead_biz_d
-- predict_input     대상일 = ref_calendar.survey_seq + 리드타임  (미래 가능)
JOIN ref_calendar c ON c.is_survey AND c.survey_seq = b.bn + l.lead_biz_d
```

v5.1 이 `bn` 을 `ROW_NUMBER()` 에서 `survey_seq` 로 바꾼 이유가 이것입니다.
관측이 없는 미래 날짜는 `ROW_NUMBER()` 로 셀 수 없었습니다.

**feature UPDATE 는 STEP 3·4·5 원문을 복제한 것**이라 갈라지면 학습과 추론의
계산식이 달라집니다. 검증 [14] 가 겹치는 구간을 전 컬럼 대조합니다 —
1,476행 불일치 0.

**신선도 가드**가 들어 있습니다. 기준일이 3일 이상 뒤처지면 WARNING 을 냅니다.
몇 달 전 가격을 앵커로 "오늘의 예측"을 내놓는 것이 가장 나쁜 사고이고,
그건 예외가 아니라 그럴듯한 숫자로 나오기 때문입니다.

### 4.4 수집기 현황

| RAW | 스크립트 | 방식 | 상태 |
|---|---|---|---|
| 경락가 | `auction_collector` 패키지 | 증분 + DB 적재 + 캐시 | ✅ 완성도 높음 |
| 도·소매 | `collect_kamis.py` | 증분 + DB 적재 | ✅ 2026-08-24 신규 |
| 반입량 | `농넷에서 일일산출량 적재.py` + `load_daily_volume.py` | 스크래핑 + 대조 후 적재 | ✅ |
| 기상 | **없음** | — | ❌ 키 필요 |

**반입량은 웹 스크래핑입니다.** 농넷 수급일보의 값이 HTML 표가 아니라 응답에 심어진
인라인 자바스크립트에 있습니다. 표가 "데이터가 없습니다" 여도 차트 데이터는 살아
있어 2015년까지 소급됩니다.

**적재 전에 대조합니다.** 기존 `daily_volume` 도 같은 스크래퍼로 받은 것이라,
지금 긁은 값이 다르면 경계를 기준으로 성격이 다른 데이터가 이어붙습니다.
실측 결과 겹치는 215행·65행 모두 **불일치 0** 이었습니다.

### 6.1 통합 WMAPE 착시 (2026-08-21)

품목을 2종 → 4종으로 늘리자 baseline 이 0.2114 → 0.0781 로 좋아졌습니다.
원인은 마늘(6,244원/kg)이 분모의 66%를 차지한 것이었습니다.

**개선처럼 보이는 수치를 먼저 의심합니다.** 접근은 옳았지만 원인 추정(구조적 누수)이
빗나갔고, 품목별 분해라는 한 단계를 거쳤어야 했습니다.

### 6.2 한 폴드 착시 (2026-08-24)

학사일정 feature 가 검증 2023 에서 경락가 +3.7% → +5.6% (+1.9%p, 판정 O)로
나왔습니다. 가설("중도매가 사용자 = 급식 구매담당")도 그럴듯했습니다.

폴드를 셋으로 늘리자 부호가 갈렸고, **정작 중도매가가 가장 나빴습니다.**

### 6.3 결측이 시점 식별자가 된다

세 번 겪었습니다.

| feature | 결측 패턴 | 결과 |
|---|---|---|
| 경제 변수 | 월·분기 갱신 → 한 달간 같은 값 | 제거 |
| KREI 재배면적 | 발간 일정 의존, 75% | 제거 |
| 학사일정 | 2020-09 이전 전부 (학습 63%) | 규칙으로 우회 |

학사일정은 **실측 5년으로 (월,일) 중앙값 프로파일**을 만들어 전 구간에 같은
규칙을 적용했습니다. LOYO 검증에서 MAE 0.0315 · 급식일 이진 일치 96.7%.
결과적으로 feature 는 기각됐지만, 미래 리드타임까지 값이 있는 구조는 남겼습니다.

### 6.4 과거에 완벽한 검증이 미래를 보장하지 않는다

`ref_calendar` 는 실거래 대조에서 오탐 0 · 미탐 0 이었습니다. 그런데 공고와 대조하니
미래 시범휴업 3건이 빠져 있었습니다. 휴장을 '거래 기록이 없는 날'에서 역산했으니
**원리적으로 지나간 날만** 채워집니다.

**검증 결과에는 적용 범위를 함께 적어야 합니다.**

### 6.5 자동화가 안 되는 구간은 안 된다고 말해야 한다

가락시장 공고 본문이 대부분 이미지입니다. `alt` 속성에 내용이 있는 경우도 있지만
공고마다 다릅니다. 파서가 0건을 반환하면 "휴업 없음"으로 읽힙니다.
그래서 못 뽑은 공고를 **URL 과 함께 "사람이 봐야 함"으로 따로 출력**합니다.

### 6.6 그 밖에

- **역변환 누락** — `pred = anchor * np.exp(...)` 를 빼먹으면 로그비율이 그대로 저장
- **앵커·타겟 기준 불일치** — 한쪽만 서울로 바꾸면 어긋난 문제가 됨
- **품목명 매칭** — 깐마늘이 `깐마늘(국산)` 이라 `item_nm IN ('마늘')` 에 안 걸림. `item_cd` 로 필터
- **검증 스크립트의 전제** — `validate_train_table.py` 는 배추 단일 기준이라 4품목에서 오탐
