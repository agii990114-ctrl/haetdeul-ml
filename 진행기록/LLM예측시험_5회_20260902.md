# LLM 에게 직접 예측을 시켜봤다 — 5회 시험

작성 2026-09-02 11:32:30 · 원가 캣쳐 ML 파트

---

## 결론 먼저

**LLM 은 단순 평균(앵커)보다 확실히 낫습니다. LightGBM 과는 통합으로 구분이
안 됩니다. 품목별로는 배추에서 앞서고 양파에서 뒤집니다.**

**운영에는 넣지 않습니다.** 같은 질문에 매번 3~7% 다른 답을 내기 때문입니다.

| | WMAPE (LT≥3) | 앵커 대비 |
|---|---|---|
| 앵커 (어제값 40% + 최근7일평균 60%) | 0.1893 | — |
| LightGBM (운영) | 0.1809 | +4.4% |
| **LLM 5회 평균** | **0.1774** | **+6.3%** |
| | 회차 편차 | 0.0025 |

---

## 1. 왜 했나

사용자 질문에서 출발했습니다 — **"너한테 예측을 맡기는 거 어떻게 생각해?"**

처음에 저는 **"성적을 잴 방법이 없어서 안 된다"** 고 답했습니다.
LLM 학습이 2026년 5월까지라 2022~2025 검증 구간의 결과를 이미 읽었을
수 있고, 그러면 예측인지 기억인지 구분할 수 없기 때문입니다.

**그런데 사용자가 짚었습니다** — "6월~현재는 학습 이후니 재면 되잖아".
**맞는 지적이었고 제가 놓친 것입니다.**

```
시험 구간   2026-06-01 ~ 2026-08-31
            학습 이후라 결과가 LLM 안에 없다
```

---

## 2. 어떻게 쟀나

### 준 것 · 안 준 것

```
준다      모델이 받는 feature 31개 그대로. 숫자만
안 준다    실제 결과 · 뉴스 · 날짜 · "지금 배추가 비싸다" 같은 힌트
```

**날짜를 통째로 가렸습니다.** `base_dt`·`target_dt` 를 안 주고 "B01" 처럼
블록 번호만 줬습니다.

**완전히 가릴 수는 없습니다** — 주산지 이름(대관령·해남)과 기온이 계절을
드러냅니다. 이건 모델도 받는 입력이라 빼면 비교가 불공정해집니다.
**"여름쯤" 을 아는 것과 "그때 값이 얼마였나" 를 아는 것은 다릅니다.**

### 규모

```
블록 30개 = 기준일 10개 × 3품목
기준일     2026-06-01 ~ 08-10 에 고르게 (6/01 · 6/09 · 6/17 · 6/24 ·
           7/01 · 7/09 · 7/16 · 7/27 · 8/03 · 8/10)
블록당     18칸 (1~18영업일 뒤)
채점       LT≥3 만 450행 (LT<3 은 운영에서 모델을 안 씁니다)
```

`ML/20260824/ml_train_kit_2/make_llm_prompt.py` · `llm_summary.py`

### ★ 1차에 조건이 어긋났다 — 그대로 기록한다

1차 회차에서 프롬프트 앞에 **"2026년 7월 1일 ~ 7월 18일까지의 가격을
예측해줘"** 를 붙여 넣었습니다.

```
① 날짜를 가린 것이 풀렸다 — 그게 이 실험의 핵심이었다
② 게다가 틀린 날짜였다. 실제는 6/1~8/10 에 걸쳐 있고
   30블록 중 7월 1~18일은 9개뿐이다
```

**안내를 안 쓴 것은 만든 쪽(저) 잘못입니다.** 프롬프트만 드리고 쓰는 법을
안 알려드렸습니다. `llm_prompt_사용법.txt` 를 따로 만들어 고쳤습니다.
(프롬프트 **안**에 넣으면 답하는 쪽이 그것까지 읽어 또 다른 실험이 됩니다.)

**1차를 버리지 않고 남겼습니다.** 회차끼리 비교하면 1차가 나머지와 더 다르게
나오는데(상관 0.971~0.989 vs 나머지끼리 0.966~0.994), 조건이 달랐다는 것이
숫자로도 보입니다.

### ★ 품목별 순서가 5회 내내 안 바뀐다

```
배추   5/5 회에서 LLM 이 LightGBM 을 이김   (0.1994~0.2221 vs 0.2267)
양파   5/5 회에서 LightGBM 이 LLM 을 이김   (0.1157 vs 0.1180~0.1292)
무     구분 안 됨
```

**우연으로 보기 어렵습니다.** 그리고 우리가 아는 사실과 맞습니다 —
배추는 제일 어려운 품목(오차 20~23%)이고 양파는 제일 쉬운 품목(12%)입니다.

**그럴듯한 이유**: 양파처럼 잔잔한 값은 최근 평균에서 조금 조정하면 되는
문제라 기계가 정확히 합니다. 배추처럼 뛰는 값은 판단이 들어갈 여지가 있습니다.

### 치우침


그런데도 LightGBM 은 +6.3% 로 과하게 높게 봤고, LLM 은 +0.8% 로 거의
맞췄습니다.

## 4. ★ 조건 차이가 크다 — 이게 이 실험의 핵심

| | LightGBM | LLM |
|---|---|---|
| **우리 자료로 배운 것** | **119,124행 · 9년치** | **없음** |
| 예측할 때 보는 과거 | 9년 전체 (배웠으니까) | **최근 14일 + 작년 한 점** |

LLM 이 본 "과거" 는 이게 전부입니다.

```
경락가     3일 전 하루 · 최근 7일 평균
중도매가    어제 · 3일 전 · 7일 전 · 7일 평균 · 14일 평균 · 7일 흔들림
반입량     어제 · 최근 7일 평균
작년       중도매가 한 점 · 반입량 한 점
```

**제일 먼 과거가 "최근 14일 평균" 입니다.**

### 두 가지로 읽힌다

**① LLM 이 대단하다.** 틀린 읽기는 아닙니다. 다만 조건을 붙여야 합니다 —
LLM 이 **우리 자료로 안 배웠을 뿐, 아무것도 안 배운 게 아닙니다.**
인터넷 글로 배우면서 "가격은 평균으로 되돌아간다" 같은 일반 상식을 갖고
있고, 그걸 갖다 씁니다.

**② ★ 우리 자료에 9년치를 배울 만한 게 별로 없다.**
**이쪽이 더 중요합니다.** 9년을 봤는데 14일 요약 + 일반 상식과 구분이
안 되는 건, **그 9년에서 건진 게 많지 않다**는 뜻입니다.

**이번 주에 같은 신호가 여섯 번 나왔습니다.**

```
9/01  실질 표본이 고유 기준일 1,475개뿐
9/01  트리를 늘리면 나빠짐 (50그루 0.1665 → 1200그루 0.1855)
9/01  입력 28개 중 17개가 한 기준일 안에서 전부 같은 값
9/01  MLP 는 키울수록 헤맴
9/02  오토리서치가 "덜 외우게" 를 찾음 · "더 외우게" 는 확인 폴드에서 탈락
9/02  9년 배운 모델이 14일 요약과 구분 안 됨          ← 이 문서
```

**그리고 CLAUDE.md §5.1 에 이미 같은 것이 있습니다** —
학습 시작을 2015 → 2017 로 **줄였는데 성능이 올랐습니다** (+5.9% → +6.8%).

## 5. 그래서 운영에 넣지 않는 이유 넷

**① 흔들립니다.** 같은 질문에 매번 3~7% 다른 답을 냅니다.
매입 파트가 "왜 어제와 다르냐" 고 물으면 답할 수 없습니다.

**② 표본이 얇습니다.** 기준일 10개입니다. 우리 폴드 하나가 245개입니다.

**③ 비용.** 하루 162개를 물어야 합니다. LightGBM 은 2초입니다.

**④ 재현이 안 됩니다.** 우리 첫 원칙이 "조건 없는 수치는 기록하지 않는다"
인데, **같은 조건에서 같은 답이 안 나오면 그 원칙이 성립하지 않습니다.**

### 다만 어제 기각한 MLP 와는 완전히 다릅니다

```
MLP    시드마다 0.24 · 0.28 · 0.22      앵커에 매번 크게 짐
LLM    5회 다 앵커를 이김 · 회차끼리 상관 0.966~0.994
```

**무작위로 흔들리는 게 아니라 같은 답 주변에서 흔들립니다.**

## ★ 원인을 찾았습니다 — 추세를 과하게 늘립니다

블록 안에서 첫 칸 대비 마지막 칸이 얼마나 기울었는지 쟀습니다.

| 조건 | 평균 기울기 | WMAPE |
|---|---|---|
| LightGBM | **2.1%** | 0.1809 |
| 기본 (14일 요약) | 7.6% | 0.1774 |
| + 중기예보 | 10.3% | 0.1868 |
| + 경락가 60일 | **15.2%** | 0.2005 |
| *(실제)* | *30.1%* | |

**기울기와 성적이 정확히 반비례합니다.**

**정보를 더 주면 LLM 은 "그래서 이렇게 될 것" 이라고 이야기를 만듭니다.**
60일 곡선을 보여주면 "계속 오르는 중이니 더 오르겠다", 기온 예보를 보여주면
"추워지니 오르겠다". **그 이야기가 우리 문제에서는 대체로 틀립니다.**

배추 경락가는 어제-오늘 관계가 0.795 인 계열이라 **하루 이틀은 이어지지만
2~3주는 안 이어집니다.** 60일 흐름이 다음 18일을 알려주지 않습니다.

**그래서 14일 요약이 제일 나았습니다** — 이야기를 만들 재료가 적으니
출발점 근처에 머물렀습니다.

**틀린 방향으로 크게 기울인 예 (60일 원자료)**

| 블록 | 품목 | LLM 기울기 | 실제 |
|---|---|---|---|
| B10 | 배추 | +44.1% | **−1.1%** |
| B14 | 무 | +29.2% | **−74.1%** |

### ★ 뉴스에 대한 답이 여기서 나옵니다

**"뉴스가 필수" 라는 가정을 세 번 시험했고 세 번 다 반대로 나왔습니다.**
뉴스는 이야기 재료의 극단입니다. "배추값 급등세" 를 주면 더 크게 올릴 것으로
보입니다.

**그리고 뉴스는 잴 수도 없습니다** — 빅카인즈 외부 발급 불가 · 네이버
2026-07-31 신규 중단 · KAMIS/가락/농넷은 전부 숫자. 게다가 기준일 이후
기사가 섞이면 답을 주는 것이 됩니다.

**중기예보로 "앞을 보는 자료" 를 공짜로 대신 시험했고 나빠졌습니다.**
(kma_mid_temp_raw · 477,837행 · 2015~ · 기준일 06시 발표분만 사용)
단, 중기예보는 **리드타임 1~8 까지만 덮습니다** (달력 D+3~D+10).
LLM 이 제일 잘하는 LT13~18 은 비어 있었습니다.

# ★ 여러 번 돌려 평균 내면 좋아진다

**흔들림이 문제가 아니라 재료였습니다.**

| 회수 | 평균 WMAPE | **최악** | 앵커 대비 |
|---|---|---|---|
| 1회 | 0.1772 | **0.1806** | +6.4% |
| **2회** | **0.1754** | **0.1772** | +7.3% |
| 3회 | 0.1748 | 0.1761 | +7.7% |
| 4회 | 0.1744 | — | +7.8% |
| *LightGBM* | *0.1809* | | *+4.4%* |

**"최악" 칸이 핵심입니다.** 1회는 도박입니다 — 4회 중 하나(0.1806)를 뽑으면
LightGBM 과 차이가 없습니다. **2회면 어떤 조합이든 LightGBM 보다 낫습니다.**

그리고 **2회에서 이득의 3분의 2를 얻고 그 뒤론 거의 안 늘어납니다.**
비용으로 보면 2회가 답입니다. (LightGBM 을 시드 5개로 앙상블하는 것과
같은 원리입니다.)

# ★★ LLM 답이 망가지는 두 가지 — 채점 전에 반드시 검사할 것

## ① 밀어쓰기 (2026-09-02 발생)

배추만 27블록을 **한 번에** 시켰더니, 블록마다 새로 답한 게 아니라
**하나의 긴 숫자 줄을 2칸씩 밀어가며** 잘라 썼습니다.

```
B01  471, 544, 570, 579, 555, 574, 414, 380, …
B02            570, 579, 555, 574, 414, 380, …   ← B01 을 2칸 민 것
B03                      555, 574, 414, 380, …   ← 또 2칸
```

B01→B05 가 전부 "앞 2칸을 밀면 완전히 같음" 이었습니다.
그리고 뒤쪽 블록은 한 칸에 3~4원씩 오르는 직선으로 바뀌었습니다.

**원인**: 블록이 많고 다 비슷하게 생긴 것. 그전까지 잘 되던 프롬프트는
배추·무·양파가 번갈아 나와 구분이 됐는데, **배추만 27개를 연속으로 놓으니
어느 블록인지 놓쳤습니다.** 표본을 늘리려다 만든 문제입니다.

**고친 것 셋**

```
① 블록 제목에 출발점을 바로 적음   ## B01 · **배추** · 출발점 445.7원
② "앞 블록 답을 밀거나 베껴 쓰지 마세요" 지시 추가
③ 26블록씩 나눠 받음 (split_prompt.py)
```

**세 번 연속 정상**으로 확인했습니다. 덤으로 **회차끼리 흔들림도 줄었습니다**
(3.2~7.4% → 2.7%). 어느 블록인지 헷갈릴 여지가 줄어서로 보입니다.

## ② 전부 상승 (2026-09-02 발생)

다른 회차에서는 밀어쓰기는 없었는데 **25블록 전부가 올랐습니다.**

```
1회차   첫칸→끝칸 평균 +1.8% · 오르는 블록 14/25
2회차   첫칸→끝칸 평균 +35.3% · 오르는 블록 25/25 · 최대 +120.6%
```

출발점이 945~1158 로 제각각인데 **끝은 전부 1134~1186 으로 수렴**했습니다.
서로 다른 날짜인데 같은 곳으로 갑니다. 배추값이 3주 만에 두 배가 된다고
한 셈입니다.

**이건 위 "추세 과대 연장" 이 극단으로 나타난 것**입니다. 지시로는 안 잡혔습니다.
