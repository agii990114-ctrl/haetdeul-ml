# 하루에 셋 — **"있는데 아무도 안 본다"**

작성 2026-09-04 · 햇들농산 ML 파트 (지환)

---

## 한 줄로

**오늘 찾은 셋이 전부 같은 모양이었습니다. 값이 틀린 게 아니라,
틀렸다고 말해 주는 자리가 아무도 안 보는 곳에 있었습니다.**

```
검증 [14]       일주일째 100% 불일치     아무도 안 봄
기준일 하루 지연  여덟 달째                매입 파트가 재서 알려 줌
채점 누락        하루                    프론트 보고 알아챔
```

**셋 다 사람이 우연히 발견했습니다.**

## 1. 검증 [14] 가 일주일째 울고 있었습니다

`DBEAVER_run_v5.sql` 안에 검증 쿼리가 여럿 있습니다. 그런데 배치는 이렇게
돌립니다.

```python
cur.execute(sql)
while cur.nextset():
    pass          # <- 검증 결과가 여기서 사라집니다
```

**사람이 DBeaver 로 볼 때만 보입니다.**

2026-08-27 에 파생 컬럼 10종을 더하면서 STEP 8(추론 입력)을 안 고쳤습니다.
그래서 `predict_input` 의 7칸이 **통째로 NULL** 이었고, [14] 는 그날부터
**대조행 1,404 중 1,404 불일치**를 냈습니다.

**예측값에는 영향이 없습니다** — 그 10종은 모델 입력에서 뺀 것들입니다
(백로그 M-16: 잣대로는 최강인데 입력으로는 해롭다).

**문제는 검사 쪽입니다.** 늘 100% 불일치라 **진짜 갈라짐이 묻힙니다.**

### 고친 것

`SQL/verify_after_rebuild.sql` 을 만들었습니다. **배치가 읽고 판단합니다.**

```
결과   (검사이름, 등급, bad, total, 설명)  다섯 칸 고정
BAD    이대로 내보내면 안 되는 것만   -> 배치 정지
WARN   알림용                      -> 계속
```

검사 여섯 — 추론입력 계산식 대조 · 대조행 있음 · 소매 타겟 서울 기준 ·
품목 끊김 · 추론입력 신선도 · 앵커 결측.

**시험했습니다.**

```
① 가짜 BAD 를 넣으면      -> 배치가 선다        (맞음)
② 검사가 깨지면(1/0)      -> 배치는 계속한다    (맞음 · 알리다 죽으면 본말전도)
③ 검사 파일이 없으면       -> 배치는 계속한다    (맞음 · 다만 눈에 띄게 찍는다)
```

**②③ 에서 조용히 통과한 것처럼 보이면 안 됩니다.** 그 사실 자체를 찍습니다.

## 2. 기준일이 하루 늦고 있었습니다

`base_dt = D` 행은 **D−1 까지만** 봅니다 — 앵커가 `whsl_prc_lag1` 이라서요.
**D 자신의 값은 한 칸도 안 씁니다.**

```
base_dt 2026-09-03 의 앵커 = 1,440원
   실제 중도매가  09-02  1,440   <- 이 값
                09-03  1,460   <- 안 씁니다
```

그런데 STEP 8 이 기준일을 **`tmp_px`(관측이 있는 날)** 에서만 뽑았습니다.
**D 의 조사값이 들어와야 `base_dt=D` 를 만드는데, 정작 그 값을 안 씁니다.**

```
9/4 아침 배치   자료는 9/3 까지
   나온 것      base_dt 9/3   앵커 9/2 값   daily[0] = 9/4 = 오늘
   될 것        base_dt 9/4   앵커 9/3 값   daily[0] = 9/5 = 내일
```

**손해가 두 칸입니다** — 앵커도 하루 묵고, 쓸 수 있는 지평도 하루 짧습니다.

매입 파트 계약이 `daily[0] = as_of + 1` 인데 `as_of` 가 되어
**248일 중 26일만 통과**했습니다. **여덟 달 동안 그랬습니다.**

### 고친 것

마지막 관측일 다음 조사일부터 오늘까지 **빈 기준일 행**(`prc` NULL)을
**STEP 8 안에서만** 끼웁니다. 창 함수가 알아서 한 칸 밉니다.

```
LAG(prc,1)                                -> 마지막 관측값 = 원하는 앵커
AVG(...ROWS 7 PRECEDING AND 1 PRECEDING)  -> 현재 행은 애초에 뺀다
```

**`tmp_px` 는 안 건드립니다** — 건드리면 학습표가 바뀝니다.

**확인**: 검증 [14] 불일치 0(1,404행) · `crop_price_train` 201,178행 그대로 ·
`base_dt 2026-09-04` 앵커 1,460 = 09-03 실제값 · 저쪽 표에 대상일
09-05~09-22 로 적재됨.

## 3. 채점을 안 돌렸습니다

1월 기준일을 백필하면서 `load` 만 하고 `score` 를 빠뜨렸습니다.
배치는 둘이 붙어 있는데 손으로 할 때 뒤엣것을 안 했습니다.

**프론트에서 1/14 부터 실제값이 안 나온다**는 이야기를 듣고 알았습니다.
1,603행을 채웠습니다.

### 남은 몇 행은 이유가 둘입니다

```
① 아직 자료가 안 옴 (정상)     9/3·9/4 대상일
② ★ 경락가 예측이 "경매 안 서는 날" 에 떨어짐
     2026-01-02 · 02-19 · 07-08  (조사는 하는데 경매는 안 서는 날)
     -> 실제값이 아예 없어 영영 채점 못 합니다
```

**②는 어제 찾은 토요일 문제와 같은 뿌리입니다.**

```
경매 안 서는데 경락가를 예측하는 날    3일 / 244일  (1.2%)
경매 서는데 예측이 없는 날            57일         (대부분 토요일 · 물량 13.7%)
```

**어긋남이 한쪽으로 훨씬 큽니다.** 매입 파트 답을 기다리는 중입니다.

## 4. 배운 것

> **검사가 있는 것과 검사가 읽히는 것은 다릅니다.**

이건 오늘 처음이 아닙니다.

```
2026-08-27  경보 파일이 안 지워져 성공해도 "실패 중" 으로 보였다
2026-09-03  ingest_agent 를 만들며 검사 하나가 죽으면 나머지가 조용히 다 죽었다
2026-09-03  표 전체 최신일만 봐서 세 품목이 10일 멈춘 것을 "정상" 으로 찍었다
2026-09-04  v5 검증 결과를 배치가 통째로 버리고 있었다
```

**네 번 다 "검사는 돌았는데 아무도 못 봤다" 입니다.**

그래서 새 검사를 만들 때 **"이게 실패하면 누가 언제 알게 되나"** 를 먼저
적습니다. 답이 *"사람이 파일을 열어 보면"* 이면 그건 검사가 아닙니다.
