작성 2026-09-01 16:22:32 · 원가 캣쳐 ML 파트

## 결론 먼저

**바꾸지 않습니다. LightGBM 을 그대로 씁니다.**

그리고 이 실험에서 **모델 종류보다 훨씬 중요한 걸 하나 찾았습니다.**

```
모델 종류를 바꿔서 생긴 차이      0.1670 → 0.1688   (1%)
트리 개수를 잘못 잡아 생긴 차이   0.1665 → 0.1855   (11%)
```

**같은 모델이라도 트리를 몇 그루 쌓느냐가 10배 크게 작용합니다.**

그리고 **저는 이 실험에서 한 번 틀렸다가 정정했습니다.** 처음에 트리 300그루로
재고 "XGBoost 가 낫다" 고 보고했는데, 운영은 76그루를 씁니다. 운영이 쓰는
자리에서 다시 재니 결론이 뒤집혔습니다. 그 과정을 아래에 남깁니다.

**하이퍼파라미터는 최대한 맞췄습니다.** 학습률 0.03 · 잎 31개(또는 깊이 6) ·

## 3. ★ 제가 틀렸던 지점 — 트리 300그루로 쟀습니다

**첫 실행 (트리 300그루 · 제가 임의로 고른 값)**

| 모델 | 폴드 A | 폴드 B | 학습 시간 |
|---|---|---|---|
| LightGBM (지금) | 0.1785 | 0.1977 | 5초 |
| **XGBoost** | **0.1760** | **0.1960** | 18초 |
| CatBoost | 0.1761 | 0.2069 | 55초 |
| *앵커(비교 기준)* | *0.1730* | *0.2096* | |

두 폴드 모두 XGBoost 가 앞섰습니다. 부호가 같고 합산(0.0042)이 편차×2(0.0021)를
넘어 **§5.7 규칙상 통과**였습니다. 그래서 "XGBoost 가 조금 낫다" 고 보고했습니다.

**그런데 조건 하나가 어긋나 있었습니다.**

```
제가 잰 자리   트리 300그루   ← 근거 없이 고른 값
운영이 쓰는 값  트리 76그루    ← ops_auc/meta.json 의 fixed_iter
```

**그리고 폴드 A 에서 세 모델 다 앵커(0.1730)에게 지고 있었습니다.**
그게 이상해서 트리 개수를 바꿔가며 다시 쟀습니다.

## 4. 트리 개수를 바꿔 다시 쟀더니 결론이 뒤집혔습니다

**경락가 · 시드 3개 · WMAPE (낮을수록 좋음)**

| 트리 | 폴드 A LightGBM | 폴드 A XGBoost | 폴드 B LightGBM | 폴드 B XGBoost |
|---|---|---|---|---|
| **50** | **0.1665** | 0.1686 | 0.1993 | 0.1996 |
| **76 (운영값)** | **0.1670** | 0.1688 | **0.1968** | 0.1971 |
| 100 | **0.1682** | 0.1686 | **0.1950** | 0.1965 |
| 150 | **0.1710** | 0.1698 | 0.1960 | 0.1944 |
| 200 | 0.1744 | **0.1713** | 0.1967 | 0.1955 |
| 300 | 0.1785 | **0.1760** | 0.1977 | **0.1960** |
| 600 | 0.1823 | **0.1808** | 0.2000 | 0.2001 |
| 1200 | 0.1855 | **0.1845** | 0.2049 | 0.2055 |
| *앵커* | *0.1730* | | *0.2096* | |

**세 가지가 보입니다.**

**① 운영이 쓰는 자리(50~100그루)에서는 LightGBM 이 이깁니다.**

```
폴드 A 76그루   LightGBM 0.1670  vs  XGBoost 0.1688   → LightGBM 1.1% 우세
폴드 B 76그루   LightGBM 0.1968  vs  XGBoost 0.1971   → 사실상 동률
```

**② 300그루에서 XGBoost 가 이긴 건, 둘 다 이미 망가진 구간에서
XGBoost 가 조금 늦게 무너지기 때문입니다.**

```
폴드 A 최선     LightGBM 0.1665 (50그루)
폴드 A 300그루   LightGBM 0.1785 · XGBoost 0.1760
```

**둘 다 최선보다 나쁩니다.** 낙제점 둘을 놓고 "38점이 35점보다 낫다" 고
한 셈입니다.

**③ 트리를 늘릴수록 나빠집니다.** 이게 우리 자료의 성격입니다.
실질 표본이 고유 기준일 1,475개뿐이라 모델을 키우면 외워버립니다(과적합).

## 5. CatBoost — 폴드 B 에서 학습이 거의 안 됩니다

**경락가 · 시드 3개**

| 트리 | 폴드 A | 폴드 B |
|---|---|---|
| 50 | 0.1695 | 0.2095 |
| 76 | **0.1687** | 0.2103 |
| 100 | 0.1694 | 0.2115 |
| 150 | 0.1698 | 0.2132 |
| 300 | 0.1761 | 0.2069 |
| *앵커* | *0.1730* | *0.2096* |

**폴드 B 에서는 앵커(0.2096)를 한 번도 못 이깁니다.** 그리고 트리를 늘릴수록
더 나빠집니다.

```
50그루  0.2095  (앵커 대비 +0.1%)
76그루  0.2103  (−0.3%)
100그루 0.2115  (−0.9%)
150그루 0.2132  (−1.7%)
300그루 0.2069  (+1.3%)
```

**어느 자리에서도 의미 있게 못 배웁니다.** 300그루가 그나마 나은 것도
+1.3% 로, 같은 자리 LightGBM(+5.7%)의 4분의 1입니다.

**같은 재료를 주고 한쪽만 배우지 못했습니다.** 운영 자리(76그루)에서
LightGBM 은 0.1968 로 앵커 대비 6.1% 앞서는데, CatBoost 는 0.2103 으로
오히려 뒤집니다.

**원인은 확인하지 않았습니다.** CatBoost 는 트리를 좌우대칭으로 키우고
(`depth=6` 고정) 범주형을 자체 방식으로 다룹니다. LightGBM 은 잎 단위로
자유롭게 키웁니다(`num_leaves=31`). 구조 차이로 짐작하지만 **재보지 않았으므로
추측입니다.**

**어느 쪽이든 채택 후보가 아닙니다.** 폴드 하나에서 앵커 수준으로 무너지는
모델은 쓸 수 없습니다.

## 6. 비용

| 모델 | 폴드 A 76그루 · 시드 3개 | 배수 |
|---|---|---|
| LightGBM | 2초 | 1× |
| XGBoost | 5초 | 2.5× |
| CatBoost | 20초 | 10× |

운영은 매달 재학습합니다. **2초가 20초가 되는 건 큰 문제가 아닙니다.**
다만 **성능 이점이 없으므로 비용을 낼 이유도 없습니다.**

## 7. 결론과 근거

### 채택: 없음. LightGBM 유지

| 후보 | 이유 |
|---|---|
| **XGBoost** | 운영 트리 개수(50~100)에서 LightGBM 과 같거나 나쁨. 300그루에서의 우세는 과적합 구간의 착시. 비용 2.5배 |
| **CatBoost** | 폴드 B 에서 앵커 수준(0.2095~0.2103). 학습이 안 됨. 비용 10배 |

### 대신 확인된 것 — 트리 개수

```
운영 fixed_iter 76 은 좋은 자리에 있습니다

  폴드 A   50그루 0.1665 · 76그루 0.1670 · 100그루 0.1682
  폴드 B   50그루 0.1993 · 76그루 0.1968 · 100그루 0.1950
```

폴드 A 는 50~76이 최선, 폴드 B 는 100이 최선입니다. **76은 두 폴드의
타협점으로 적절합니다.** 바꿀 근거가 없습니다.

## 8. ★ 이 실험에서 배운 것 — 규칙으로 남깁니다

> **비교 실험은 반드시 운영이 쓰는 자리에서 하세요.**

임의로 고른 하이퍼파라미터에서 재면 **결론이 뒤집힙니다.** 이번이 실례입니다.

```
트리 300그루에서 잼   "XGBoost 가 두 폴드 모두 낫다"   (§5.7 규칙 통과)
트리 76그루에서 잼    "LightGBM 이 같거나 낫다"
```

**§5.7 규칙(두 폴드에서 부호가 같을 것)을 통과해도 안전하지 않습니다.**
두 폴드 모두 잘못된 자리에서 쟀다면, 두 폴드 모두 같은 방향으로 틀립니다.

**폴드를 나누는 것은 "연도가 특이한가" 를 막아줍니다.
"조건을 잘못 골랐나" 는 못 막아줍니다.**

이것을 CLAUDE.md §5.12 에 넣었습니다.

## 9. 남은 것

```
CatBoost 폴드 B 원인   구조 차이로 짐작만 함. 채택 후보가 아니라 안 팜
TFT (트랜스포머)       ② 순위. 분위수 회귀가 성공해 조건이 열림
GRU · LSTM            ④ 순위. "왜 딥러닝을 안 썼나" 에 답하는 용도
```

**GRU·LSTM 에 대한 이 실험의 시사점**: 우리 자료는 **모델을 키우면 나빠집니다**
(50그루 0.1665 → 1200그루 0.1855). GRU·LSTM 은 LightGBM 1200그루보다 훨씬
큰 모델입니다. **이길 가능성은 낮다고 봅니다. 다만 이번에 한 번 뒤집혔으므로
재보고 말하겠습니다.**
