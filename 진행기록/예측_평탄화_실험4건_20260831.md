# 예측이 일직선인 문제 — 실험 4건 전부 기각, 그리고 진짜 원인 (2026-08-31)

**결론 먼저.** 네 가지를 시도해 전부 기각했습니다. 그런데 **네 번 다 같은
자리에서 갈렸습니다.** feature 를 넣고 빼는 것으로는 안 풀리는 문제라는 것이
오늘의 결론입니다.

---

## 0. 무엇이 문제였나

한 기준일 안에서 리드타임 3~18 이 얼마나 움직이는지 재봤습니다 (152개 기준일).

| 타겟 | 품목 | 예측 변동폭 | 실제 변동폭 | 비율 |
|---|---|---|---|---|
| 경락가 | 배추 | 13.7% | **137.8%** | **0.10** |
| 경락가 | 무 | 14.0% | 47.7% | 0.29 |
| 경락가 | 양파 | 12.1% | 34.7% | 0.35 |
| 중도매가 | 배추 | 11.3% | 15.0% | 0.75 |
| 소매가 | 양파 | 2.5% | 15.6% | 0.16 |

**실제가 10 만큼 움직일 때 예측은 1~7 만 움직입니다.**

원인은 입력에 있었습니다.

```
모델 입력 28개 중
  17개  한 기준일 안에서 18행이 전부 같은 값
  11개  바뀌긴 하는데 그중 6개는 18행 중 1~2번만
```

18행 내내 진짜로 움직이는 입력의 **중요도 합계가 22.4%** 뿐입니다.
나머지 77.6% 는 "1월 2일이든 1월 27일이든 같은 이야기" 를 합니다.

그 작은 움직임이 방향이라도 맞는지도 쟀습니다.

| 타겟 | 품목 | 방향 상관 |
|---|---|---|
| 중도매가 | 배추 | 0.192 |
| 경락가 | 양파 | 0.007 |
| 경락가 | 무 | **−0.063** |

경락가 무는 **음수** — 오른다고 할 때 내렸습니다.

> **다만 이건 모델이 게을러서가 아닙니다.** 1월 14일에 무슨 일이 있을지
> 알려주는 입력이 없으면, 가진 정보로 낼 수 있는 가장 덜 틀리는 답이
> "오늘과 비슷" 입니다. 억지로 출렁이게 만들면 성적이 더 나빠집니다.
> 불확실성은 밴드가 지고 있고, 밴드는 실제로 76~85% 를 지킵니다.

## 1. 실험 넷

전부 같은 조건입니다.

```
품목    배추 · 무 · 양파
학습    2017-01-01 부터
시드    10개 (42~51)
폴드    A: 학습 →2022 · 검증 2023
        B: 학습 →2021 · 검증 2022
판정    §5.7 — 두 폴드 부호가 같고 합산이 편차×2 를 넘을 때만 채택
```

### ① 평년 기온을 대상일 기준으로

지금 `prod_area_clim_temp_avg10` 은 **기준일+1~+10 을 뭉친 한 값**이라
18행 내내 고정입니다 (2025-12-31 배추 = 1.557℃ 가 18번).

대상일 ±3일의 과거 연도 평균으로 바꿨습니다. 기준일당 서로 다른 값이
**1.14가지 → 15.91가지** 로 늘었습니다.

| 타겟 | 폴드 A | 폴드 B | 판정 |
|---|---|---|---|
| 경락가 | −0.0005 | +0.0015 | 부호 갈림 |
| 중도매가 | −0.0005 | +0.0002 | 부호 갈림 |
| 소매가 | −0.0015 | **+0.0033 (O)** | 부호 갈림 |

**9개 조합 중 유의미한 건 소매가 폴드 B 하나뿐.** 기각.

`SQL/30_clim_target_day.sql` · `train.py --clim-daily`

### ② 중기 기온예보 (기상청 API허브)

**새 자료를 수집했습니다.** 이건 남습니다.

```
kma_mid_temp_raw   477,837행 · 2015~2026 · 8개 관측소
발표 하루 2회(06·18시) · 발표+3~10일 · 최저/최고 기온
2017년 이후 빠진 날 0
```

★ **예보구역은 이름으로 고르지 않았습니다.** 563개 구역 중 시군(C등급)
208개만 기온을 줍니다. 이름만 봤으면 이렇게 틀렸습니다.

```
목포   → '영광-목포' · '목포구내' · '목포-홍도'   전부 바다 (기온 없음)
대관령 → '장평-대관령'                          도로 구간 (기온 없음)
```

코드마다 실제로 불러 **기온이 나온 것만** 매핑에 넣었습니다.

★ **닿는 구간이 좁습니다.** 예보는 달력 +3~10일인데 우리 리드타임은 영업일이라:

```
LT1~4  98~100%      LT5  92.7%
LT6    70.3% ⚠      LT7  43.4% ⚠      LT8~18  0%
```

**모델을 쓰는 16칸 중 LT3·4·5 세 칸만** 덮습니다. LT6·7 은 결측이
**달력 배치를 따라** 생겨(연휴 낀 주에 없음) 시점 식별자가 되므로 뺐습니다
(§5.2 경제변수와 같은 함정).

LT3~5 만 떼어 비교한 결과:

| 타겟 | 폴드 A | 폴드 B |
|---|---|---|
| 경락가 | +0.0002 | −0.0004 |
| 중도매가 | −0.0001 | −0.0000 |
| 소매가 | −0.0001 | +0.0004 |

**6개 조합 전부 판정 불가(ㅡ).** 편차 안에서도 안 움직였습니다.

**모델이 무시한 게 아닙니다** — 중요도 32개 중 22위, 1.83% 로 쓰긴 썼습니다.
**썼는데 도움이 안 됐습니다.**

왜인지는 둘로 짚입니다.

- **이미 아는 것과 겹칩니다.** 3~5일 뒤 기온은 오늘 기온+계절로 거의
  설명됩니다. 예보-실측 상관 0.976 인데, 그 정보를 `주산지 어제 기온` 과
  `평년 기온` 이 이미 갖고 있습니다.
- **날씨가 3~5일 만에 가격을 움직이지 않습니다.** 추위는 작황을 통해 몇 주에
  걸쳐 옵니다. 그 경로는 `주산지 생육 온도 30일 합`(4위·5.99%)과
  `최근 30일 비`가 이미 담당합니다.

`데이터 수집/중기예보/fetch_mid_temp.py` · `SQL/31_fcst_temp_target.sql` ·
`train.py --with-fcst --lead-min --lead-max`

### ③ 반입량 원본을 예측값으로 교체

8-26 캐스케이드 실험은 **원본에 예측값을 더한** 것이었습니다. 이번엔
**원본을 빼고 예측값으로 갈아끼웠습니다.**

| 타겟 | 폴드 A (2023) | 폴드 B (2022) |
|---|---|---|
| 경락가 | B −0.0008 · C −0.0010 | **B +0.0031 · C +0.0029** |
| 중도매가 | B −0.0018 · **C −0.0025 (X)** | B +0.0034 · **C +0.0042 (O)** |
| 소매가 | B −0.0001 · **C −0.0021 (X)** | **B +0.0067 (O)** · **C +0.0064 (O)** |

*(B = 빼고 예측값 넣음 · C = 빼기만)*

**6개 조합이 하나도 빠짐없이 부호가 갈립니다.** 방향도 완전히 일정합니다 —
폴드 A 는 전부 나빠지고 폴드 B 는 전부 좋아집니다.

★ **B 와 C 가 거의 같습니다** (차이 0.0002~0.0003). **예측값을 넣든 안 넣든
결과가 같습니다.** 8-26 결론(예측값은 있으나 마나)을 다시 확인해 줍니다.

### ④ 학습=실제 / 검증=예측 (엇갈림)

"학습 때는 실제 반입량을 쓰고, 예측할 때만 예측값을 던져주면?"
**검증 구간에 예측값만 주므로 나온 점수가 곧 실전 점수입니다.**

| 타겟 | 폴드 | 기준 | 엇갈림 | 오라클 | 이득 |
|---|---|---|---|---|---|
| 경락가 | A | 0.1607 | **0.1575** | 0.1556 | **+0.0033 O** |
| 경락가 | B | 0.1878 | 0.1915 | 0.1846 | **−0.0037 X** |
| 중도매가 | A·B | | | | −0.0004 · −0.0011 |
| 소매가 | A·B | | | | +0.0002 · +0.0003 |

**★ 제가 틀린 예측을 했습니다.** 앞서 "학습과 실전이 다르면 흐릿함을
증폭한다" 고 단정했는데, **폴드 A 에서는 반대였습니다.** 0.1607 → 0.1575 로
오라클(0.1556)에 꽤 다가갔습니다. 단정하지 말았어야 했습니다.

그런데 폴드 B 에서 정확히 반대입니다. 그 차이가 답입니다.

```
폴드 B   오라클 +0.0032 (도움됨)   엇갈림 −0.0037 (해로움)
```

**충격기에는 반입량 예측이 크게 틀립니다.** 평상시 패턴으로 배운 예측 모델이
태풍 때를 못 맞히는데, 가격 모델은 학습 때 "이 값은 정확하다" 고 배웠으니
그 틀린 값을 크게 믿습니다. **제일 필요한 순간에 제일 크게 틀립니다.**

오라클 상한도 다시 나왔습니다 — 경락가 +0.0083, **중도매가·소매가는 0**.
미래 반입량은 경락가에만 값이 있습니다.

`train.py --drop-volume --with-volpred --allow-oracle`

## 2. ★ 오늘의 진짜 발견 — 폴드 B 가 다섯 번째로 갈랐다

| 언제 | 무엇 | 폴드 B 만 |
|---|---|---|
| 08-24 | 학사일정 | 음수 |
| 08-24 | volume ablation | 음수 |
| 08-26 | 주산지 기상 제거 | 반대 (+0.0086) |
| **08-31** | **반입량 교체** | **반대 (6/6 전부)** |
| **08-31** | **엇갈림** | **반대** |

**폴드 B 의 검증 연도 2022 에는 태풍 힌남노(9/6 상륙)가 있습니다.**

8-26 에 이미 재둔 표가 답을 갖고 있습니다.

| 2022년 배추 | 반입량 | 가격 |
|---|---|---|
| 9월 | +47% | **+157%** |
| 11월 | +102% | **−41%** |

**11월은 정상적인 반대 관계(물량↑ 값↓)인데 9월은 뒤집힙니다.**
태풍이 밭에서 **품질**을 망가뜨렸고, 우리 타겟은 하필 특등급입니다.
같은 톤수라도 상품성이 다르면 값이 다릅니다.

### 그래서 결론

```
평상시   반입량 ↑ → 가격 ↓   (정상)
충격기   반입량 ↑ → 가격 ↑   (역전)
```

**모델이 하나뿐이라 두 상황을 같이 배웁니다.** 그게 폴드마다 부호가 갈리는
진짜 이유입니다. **feature 를 넣고 빼는 걸로는 안 풀립니다** — 충격기를
구분하는 무언가가 있어야 풀립니다.

**다음 사람에게**: 폴드가 갈리면 feature 를 의심하기 전에 **그 해에 무슨 일이
있었는지** 보세요. 다섯 번 중 다섯 번이 그것이었습니다.

## 4. 재현

```bash
# ① 평년기온
python train.py <csv> --target auc --train-start 2017-01-01 \
    --train-end 2022-12-31 --valid-end 2023-12-31 --gate-lt 3 \
    --seeds 42..51 [--clim-daily]

# ② 중기예보 (LT3~5 만)
python "데이터 수집/중기예보/fetch_mid_temp.py" --from 2015-01-01 --to 2026-08-31
psql < SQL/31_fcst_temp_target.sql
python train.py <csv> ... --lead-min 3 --lead-max 5 [--with-fcst]

# ③④ 반입량
python exp_volume_cascade.py <oracle.csv> <cascade.csv>
python train.py <cascade.csv> ... [--drop-volume] [--with-volpred]
python train.py <skew.csv> ... --allow-oracle
```

**주의**: `--allow-oracle` 은 `arr_qty_at_target`(대상일 실제 반입량)을
입력으로 엽니다. **검증 구간을 예측값으로 바꿔 넣은 CSV 가 아니면 점수가
통째로 거짓**이 됩니다. 켤 때마다 경고를 찍게 해뒀습니다.
