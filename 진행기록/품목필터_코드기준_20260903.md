## 2. 원인

`DBEAVER_run_v5.sql` 이 **이름으로** 걸고 있었습니다.

```sql
AND item_nm IN ('배추','양파','무','마늘')
```

**원천이 2026 부터 이름을 바꿨습니다.**

```
item_cd 244   2025 까지 '마늘'  ->  2026~ '피마늘'
item_cd 241   2025 까지 '고추'  ->  2026~ '건고추'
```

`'피마늘'` 은 저 목록에 없으니 **한 행도 안 걸립니다.**

### ★ 이게 세 번째입니다

```
2026-08-25  collect_kamis.py 가 item_nm 으로 DB 최신일을 찾다가
            "신규 0행" 으로 잘못 보고. 매번 8개월치를 다시 받았다
2026-08-25  깐마늘이 '깐마늘(국산)' 이라 item_nm IN ('마늘') 에 안 걸림

```

**CLAUDE.md 9절에 경고가 적혀 있었습니다.** *"품목을 세거나 최신일을
찾을 때 item_nm 을 쓰지 마세요."* **그런데 정작 SQL 은 안 고쳐져
있었습니다.** 파이썬만 고치고 SQL 을 안 본 것입니다.

## 3. 고친 것 — 네 곳

**코드로 거르고, 이름은 우리가 정합니다.**

```sql
AND item_cd IN ('211','245','231','244')
CASE item_cd WHEN '211' THEN '배추' WHEN '245' THEN '양파'
             WHEN '231' THEN '무'   WHEN '244' THEN '마늘' END AS item_nm
```

**원천이 또 이름을 바꿔도 안 흔들립니다.** 우리 표 안의 이름은
바깥 사정과 무관해집니다.

| 자리 | 무엇 | 전에는 |
|---|---|---|
| STEP 1 `tmp_px` | 중도매 원천 (앵커·타겟) | 이름 필터 |
| STEP 2 `tmp_rtl` | 소매 앵커 | 이름 필터 |
| STEP 6 `tmp_rtl_t` | 소매 타겟 | **필터 없음** |
| 검증 [12] | 소매 기준 검사 | **필터 없음** |

**소매 타겟에 필터가 없던 것도 같이 고쳤습니다.** 앵커는 걸고 타겟은
안 거는 상태였습니다 — 이름이 어긋나면 **조인이 통째로 비는** 모양입니다.
(9절 *"앵커와 타겟의 기준 일치"* 와 같은 이야기입니다.)
