## 4. ablation 재판정 — 8/24 판정이 만료돼 있었습니다

### 왜 다시 했나

사용자 지적으로 시작했습니다 — "feature 를 바꿀 거면 ablation 을 다시
해야 하지 않나". 확인해 보니 **바꾼 게 없어도 다시 해야 할 이유**가
따로 있었습니다.

```
8/24  ablation 2차 → "feature 변경 없음"
8/27  경락가 규격 고정          ← 타겟이 바뀜
8/28  앵커 수축 도입 (α)        ← 배우는 문제가 바뀜
9/01  트리 개수 실측            ← 잰 자리가 다름
```

**8/24 당시 배추 경락가는 ACF(1) 0.085 — 사실상 무작위였습니다.**
그러면 "변경 없음" 은 **"무작위는 아무도 못 맞힌다"** 였을 수 있습니다.

### 결과 — feature 변경 없음. 다만 판정이 여럿 바뀜

| 그룹 (경락가) | 8/24 | 오늘 |
|---|---|---|
| `weather` | **O 기여함** | ㅡ 판정 불가 |
| `auction` | **X 해로움** | ㅡ 판정 불가 |
| `calendar` | △ | **X 제거 후보** → 쪼개니 뒤집힘 |

**중도매가·소매가는 오히려 더 뚜렷해졌습니다** — `lag` · `weather` ·
(소매가) `calendar` 가 "유지(기여함)" 로 확정됐습니다.

### ★ 규칙의 구멍을 찾았습니다

`calendar` 6개를 통째로 빼니 두 폴드 모두 음수라 **제거 후보**로 나왔습니다.
쪼개니 거의 전부 `cal_holiday` 하나였고, 그건 **폴드 B 한 곳에서만** 나왔습니다.

```
뭉쳐서   A −0.0009 · B −0.0062   둘 다 음수 → 부호 같음 → 제거 후보
쪼개서   A +0.0004 · B −0.0056   부호 갈림  → 판정 불가
```

**작은 양수 여럿이 큰 음수 하나에 묻혀 부호가 같아 보였습니다.**
한 폴드로 결정하지 않는 것과 같은 이유로, **뭉친 그룹으로도 결정하지 않습니다.**

## 7. 조사만 한 것 — 수입 물량·가격 (사용자 착안)

**자료를 새로 모을 필요가 없습니다.** `auction_prices_daily.subclass_code`
에 이미 들어 있습니다 (`98` = 수입).

**그런데 세 품목 중 양파만 쓸 수 있습니다.**

| 품목 | 수입 물량 비중 | 거래된 날 |
|---|---|---|
| **양파** | **5.42%** (21만 톤) | 2,019일 |
| 배추 | 0.37% | 811일 |
| 무 | **0.04%** | **60일** |

배추는 수입이 없는 게 아니라 **김치 완제품**으로 들어와 도매시장을
안 거칩니다.

**★ 상관이 높은 게 오히려 위험합니다.** 수입 비중 vs 국산 가격이 **+0.572**
인데 **부호가 양수**입니다. **국산 값이 비싸니까 수입을 들여오는 것**이라
인과가 거꾸로입니다. 그대로 넣으면 모델이 "수입이 늘었으니 값이 오를 것"
이라고 배웁니다.

**그리고 2019~2021 에 수입 거래일이 30% 로 뚝 떨어집니다.** 진짜 안 들어온
건지 수집이 빠진 건지 모릅니다. **학습 구간이 정확히 그 구간을 걸칩니다.**

백로그 `[M-22]` 로 남겼습니다. 우선순위 낮음 — 양파는 이미 제일 잘 맞는
품목이고(오차 9.0%), 정작 나쁜 배추·무는 이 자료로 도울 수 없습니다.
