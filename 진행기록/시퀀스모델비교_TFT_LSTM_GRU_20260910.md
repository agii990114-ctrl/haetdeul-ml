## 1. 왜 했나

2026-09-01 MLP(신경망)는 LightGBM 이 받는 표 한 줄을 그대로 받아 **단순 평균에도
졌습니다.** 그런데 그건 «TFT 도 진다» 를 증명하지 않았습니다. TFT·LSTM·GRU 는

```
과거 흐름을 순서대로 읽고
미리 아는 미래(요일 · 명절까지 며칠)를 따로 받고
품목처럼 안 변하는 것을 또 따로 받습니다
```

MLP 는 이걸 한 줄로 뭉쳐 받았습니다. 이번엔 **그 모델들이 원래 쓰는 모양으로**
줬습니다. 「왜 딥러닝을 안 썼나」에 실측으로 답하는 것이 목적입니다.

## 3. 신경망에 준 것

```
한 칸       조사일 하루 (리드 k = k칸 뒤 · 134,862행 중 어긋남 0)
입력 창     56 조사일 (약 11주)
과거 입력   8개 — 그날 아침 아는 마지막 경매가 · 운영 앵커 · 중도매가 · 소매가
                  반입량 · 경매 물량 · 주산지 기온 · 강수
미래 입력   7개 — 요일 5 · 명절까지 며칠 · 김장철
고정 입력   품목 3
출력        19칸 (리드 0 ~ 18) 한 번에
라이브러리   neuralforecast 3.2.2 · torch 2.14 (RTX 3050)
```

**신경망에 유리한 쪽으로만** 전처리했습니다 — 창마다 눈금 맞춤(robust scaler),
빈 칸 가리기(available_mask), 운영 앵커를 입력으로 제공.

⚠️ 불리한 점 하나 — 조기 종료를 위해 학습 끝 61 조사일(약 3달)을 떼어 뒀습니다.
LightGBM 은 그 구간까지 배웁니다. 다만 아래 ②에서 **조기 종료를 꺼도 결론이 같습니다.**

## 4. ★ 짜다가 찾은 것 — 토요일

학습표를 조사일 줄로 세우니 **월요일의 95.6% 에서 앵커가 직전 칸 값과 달랐습니다.**

```
앞 조사일과 하루 차이   불일치 0.0%   (5,360칸)
월요일                 불일치 95.6%
예시 6개               lag1 = 토요일 경매가 · 6개 전부 정확히 일치
```

**경매는 토요일에도 열리는데 조사일 축에는 토요일이 없습니다.** 운영 앵커는
「직전 경매일」 값이라 월요일엔 토요일 가격을 씁니다. 그대로 두면 **신경망만 토요일
경매를 못 보는** 불공정한 비교였습니다. 「그날 아침 아는 마지막 경매가」를 입력으로
넣어 맞췄습니다 — 운영 LightGBM 이 보는 것과 같은 정보입니다.

★ 운영 쪽 문제는 아닙니다. LightGBM 은 `auc_prc_lag1` 로 토요일을 이미 봅니다.

시드 편차도 가장 큽니다 (±0.029 · ±0.040).

## 6. ★ 고장이 아닌지 먼저 의심했습니다

너무 크게 졌습니다. 신경망 입력에 **운영 앵커를 그대로 줬는데**, 리드 0~2 에서
LSTM 이 0.2174 로 앵커(0.1116)의 두 배였습니다. 받은 값을 베끼기만 해도 0.11 이
나와야 합니다. 그래서 두 가지를 쟀습니다 (GRU · 시드 42 · 폴드 A).

**① 날짜 맞물림** — 신경망이 들고 있는 정답(y)이 우리 채점 정답과 같은 행인가

```
100.00% 일치 — 전 행
```

**② 조기 종료가 너무 일찍 걸렸나**

```
조기 종료 켬    300걸음에서 멈춤 · 검증 손실 최저는 50걸음 (0.502 → 0.329 → 0.372)
               WMAPE 0.2464
조기 종료 끔    1,500걸음
               WMAPE 0.2294   ← 조금 나아졌지만 여전히 앵커(0.1730)보다 33% 나쁨
```

**50걸음 만에 과적합이 시작됩니다.** 고장이 아니라 **자료가 작아서**입니다.

```
실질 표본   고유 기준일 약 1,475개 (2017~2022)
LightGBM    50그루 0.1665 → 1,200그루 0.1855   모델을 키우면 나빠진다 (09-01)
신경망      그보다 훨씬 큰 모델
```

MLP 때 미리 밝힌 걱정이 그대로 나왔습니다.

## 7. 곁에서 나온 것 — 리드 0~2 에서 LightGBM 도 앵커에 짐

주 비교와 별개로, **리드 0~2 에서는 LightGBM 이 두 폴드 모두 가장 센 baseline 에
졌습니다.**

```
리드 0~2         폴드 A           폴드 B
LightGBM        0.1134           0.1176
가장 센 baseline  0.1116 (앵커)    0.1072 (어제)
                −1.6%            −9.7%
```

09-09 에 게이트를 끄면서 리드 0~2 가 모델 값으로 나가게 됐는데, **그 자리가 모델이
약한 자리**라는 신호입니다.

⚠️ **바로 결론 내지 않습니다.** 폴드는 학습이 5~6년이고 운영은 7년이라, 「모델이
앵커를 이기나」 같은 절대 질문은 폴드로 안 풀립니다 (M-14 에서 셋이 다른 답을 냈던
이유). 그리고 09-21 까지 매입에 값 동결을 약속했습니다. **발표 뒤 운영 조건으로
2026 실전에 대 보는 것**이 다음 걸음입니다.

## 8. 안 해 본 것 — 결론의 범위

**증명된 것:** 이 설정으로는 셋 다 두 폴드 모두 LightGBM·앵커에 크게 진다.

**증명 안 된 것:** «어떤 설정으로도 진다».

```
하이퍼파라미터 탐색     모델마다 한 설정만 (은닉 64 · 학습률 1e-3 · 창 56)
앵커 기준 학습          신경망은 가격 수준을 배움. LightGBM 처럼 «앵커에서
                       얼마나 움직일지» 를 배우게 하지 못함 (라이브러리 구조상)
폴드 C                 두 폴드가 다 기각이라 돌리지 않음
```

다만 **탐색으로 30% 넘는 차이를 뒤집을 가능성은 낮다고 봅니다** — 조기 종료를
꺼도 7%만 나아졌고, LightGBM 도 모델을 키우면 나빠지는 자료입니다.
