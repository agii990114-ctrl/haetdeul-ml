## 1. 매핑은 실제로 어긋나 있습니다

배추 반입량의 실제 1위 산지를 **순(旬) 단위**로 세어 현행 매핑과 견줬습니다
(2017~ · 날짜 수 기준).

| 월·순 | 실제 1위 | 비중 | 2위 | 현행 매핑 |
|---|---|---|---|---|
| **5월 하** | 전남 해남 | 59% | 경남 의령 | 홍성(충남) ✗ |
| **6월 상** | 충남 아산 | 43% | 경북 문경 | 대관령(강원) ✗ |
| **8월 하** | 강원 강릉 | 55% | 강원 평창 | 대관령 ✗ |
| **9월 하** | 강원 평창 | 45% | 강원 강릉 | 강릉 ✗ |
| **11월 상** | 강원 춘천 | 73% | 전남 해남 | 해남(전남) ✗ |

**나머지 31칸은 맞습니다.** 1~4월·12월은 해남 91~100%, 7월·10월은 평창
72~86% 로 아주 안정적입니다.

> **★ 백로그의 처방이 실측과 다릅니다.** 백로그에는
> *"11월은 상순=대관령 / 중하순=해남"* 이라고 적혀 있는데,
> **11월 상순 1위는 춘천(73%)** 입니다. 대관령·평창이 아닙니다.

### 고칠 재료는 있습니다

```
5월 하  -> 해남     있음
6월 상  -> 천안     있음 (아산 인접 · 아산은 관측소 없음)
8월 하  -> 강릉     있음
9월 하  -> 대관령   있음 (대관령은 평창군 안이다)
11월 상 -> 춘천     있음
```

**다섯 칸 다 고칠 수 있습니다.** 다만 `ref_item_station` 에 **순(旬) 축이
없어** SQL 구조를 바꾸고 학습표를 다시 만들어야 합니다.

## 2. 그래서 먼저 물었습니다 — **어긋남이 손해를 내고 있나**

**손해가 없으면 고칠 이유가 없습니다.** 대상일이 어긋난 순에 드는 행과
나머지 행의 오차를 견줬습니다 (배추 · 3폴드 · 시드 10 · LT≥3).

**소매가는 뺐습니다** — 주산지 기상을 안 씁니다 (5.3절).

| 타겟 | 구간 | 행수 | 모델 | 앵커 | 개선율 |
|---|---|---|---|---|---|
| 경락가 | 어긋난 순 | 1,712 | 0.2711 | 0.2896 | **+6.4%** |
| | 나머지 | 10,048 | 0.2334 | 0.2532 | **+7.8%** |
| 중도매가 | 어긋난 순 | 1,728 | 0.2177 | 0.2712 | **+19.7%** |
| | 나머지 | 10,096 | 0.2032 | 0.2368 | **+14.2%** |

**경락가는 1.4%p 나쁘고 중도매가는 5.5%p 좋습니다.** 방향이 갈립니다.

## 3. ★ 칸별로 보면 가설과 정반대입니다

| 칸 | 어긋남의 크기 | 경락가 | 중도매가 |
|---|---|---|---|
| **11월 상** (춘천↔해남) | **아주 큼** — 강원 vs 전남 | **+30.0%** | **+51.4%** |
| **5월 하** (해남↔홍성) | **큼** — 전남 vs 충남 | +20.4% | +50.1% |
| 6월 상 (아산↔대관령) | 큼 — 충남 vs 강원 | −6.2% | +3.8% |
| 8월 하 (강릉↔대관령) | **작음** — 강원 안 | −5.8% | −8.0% |
| **9월 하** (평창↔강릉) | **작음** — 강원 안 | **−20.5%** | +5.7% |

**어긋남이 클수록 잘 맞히고, 작을수록 못 맞힙니다.**

**매핑이 가장 크게 틀린 11월 상순(강원 춘천을 전남 해남으로 봄)에서
가장 잘 맞힙니다.** 매핑 가설이 맞다면 거기가 가장 나빠야 합니다.

반대로 **가장 나쁜 9월 하순은 강원 안에서 인접 관측소끼리(평창↔강릉)
바뀐 것**이라, 기상이 거의 같습니다. 매핑으로 설명이 안 됩니다.

## 4. 판정 — 안 고칩니다

```
매핑을 고쳐서 얻을 것이 있다는 증거가 없다.
SQL 구조 변경 + 학습표 재생성 + 전 성능 재측정이 필요한데
기대 이득이 확인되지 않았다.
```

### 이 검사의 한계 (그대로 적습니다)

**"어긋난 구간에서 더 나쁘지 않다" 와 "고쳐도 안 좋아진다" 는 다릅니다.**
모델이 다른 feature 로 메우고 있을 수 있습니다.

**직접 재려면** 그 다섯 칸의 기상을 올바른 관측소 것으로 바꿔 넣고
다시 학습해야 합니다. 그건 SQL 구조 변경이 필요합니다.
**11월 상순 결과(+30% · +51%)를 보면 그 작업의 기대 이득이 낮다**고 봅니다.

## 5. 곁들여 나온 것 — **계절별 약한 구간**

매핑과 별개로, **경락가 배추에 계절적으로 약한 자리가 있습니다.**

```
9월 하순   -20.5%    모델이 앵커에 크게 짐
8월 하순    -5.8%
6월 상순    -6.2%
```

**8~9월은 고랭지 끝물이고 산지가 강원 안에서 옮겨 다니는 때**입니다
(8하 강릉 55% · 9하 평창 45% — 둘 다 1위 비중이 낮습니다).

**M-14 에서 리드타임 축으로 게이트를 보다가 "폴드로 절대 판정을 하면
안 된다" 를 배웠습니다.** 계절 축도 같은 함정이 있으므로 **여기서는
관찰로만 남기고 게이트를 만들지 않습니다.**
