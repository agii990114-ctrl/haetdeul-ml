# 반입량 수집 — 농넷 수급일보

`daily_volume` 테이블을 채웁니다. `crop_price_train` 의 `arr_qty_lag1` ·
`arr_qty_avg7` · `arr_qty_prev_yr` · `arr_top1_region` 이 여기서 나옵니다.

```
농넷 수급일보 화면  →  농넷에서 일일산출량 적재.py  →  daily_volume.csv
                                                          ↓
                                              load_daily_volume.py
                                                          ↓
                                                    daily_volume (DB)
```

---

## 왜 스크래핑인가

농넷 수급일보 화면의 반입량은 **HTML 표가 아니라 응답에 심어진 인라인
자바스크립트**에 들어 있습니다. 표가 "조회된 데이터가 없습니다" 여도 차트
데이터는 살아 있어서, 이쪽을 읽으면 2015년까지 소급됩니다.

```js
function makeWeightChart() {
    tmpObj["dayStr"]      = "01/20";
    tmpObj["rank1Weight"] = "719";
    tmpObj["rank1Name"]   = "전남 해남군";
```

JSON 이 아니라 대입문 나열이라 정규식으로 블록 단위로 뜹니다.
한 응답에 8~9일치가 들어오므로 **8일 간격**으로 훑습니다.

## 실행

### 1. 확인 먼저

```bash
python "농넷에서 일일산출량 적재.py" probe --item 배추 --date 2026-08-20
```

`응답 품목명` 이 요청 품목과 같은지 보세요. 다르면 `ITEMS` 의 menu 코드가
틀린 것입니다. 2026-08-24 기준으로 배추 311 · 양파 312 · 무 313 은 확인됐습니다.

### 2. 수집

```bash
python "농넷에서 일일산출량 적재.py" run --start 2025-12-26 --end 2026-08-24
python "농넷에서 일일산출량 적재.py" merge
```

- 요청당 8초 + `--pause` 1.5초
- **백필은 오래 걸립니다** — 236일이면 약 25분 (8일 창 30개 × 5품목)
- **매일 증분은 40초**입니다. 배치가 DB 최신일 −5일부터만 받아 창 하나로 끝납니다
- `_done.txt` 로 이어받습니다. 중단 후 같은 명령을 다시 돌리면 됩니다
- 시작일은 마지막 적재일보다 **며칠 앞**으로 잡으세요. 8일 창이 겹쳐야
  아래 대조가 성립합니다

### 3. 적재 — 대조가 먼저입니다

배치는 CSV 를 거치지 않습니다.

```bash
python "농넷에서 일일산출량 적재.py" run --start ... --load-db --no-csv
```

CSV 로 적재하려면 (과거분 복구 등):

```bash
python load_daily_volume.py --check      # 대조만
python load_daily_volume.py              # 새 행만 적재
```

**최근 14일은 정정을 반영합니다.** 농넷이 수급일보라 최근 물량이 뒤늦게
올라옵니다 (실측: 8/18 양파 1,407 → 1,658톤). 그 이전 구간은 덮어쓰지 않습니다 —
오래된 값이 바뀌면 정정이 아니라 사고이기 때문입니다.

`--check` 는 겹치는 구간을 값까지 대조하고 아무것도 쓰지 않습니다.
불일치율이 2%를 넘으면 적재를 멈춥니다 (`--max-diff-pct` 로 조정).

**왜 대조를 먼저 하나.** 기존 `daily_volume` 도 같은 스크래퍼로 받은 것입니다.
지금 긁은 값이 그때와 다르면 **경계를 기준으로 성격이 다른 데이터가 이어붙고**,
모델은 그 경계를 "시점" 으로 학습합니다. 예외가 아니라 조용한 성능 저하로
나타나므로 넣기 전에 봐야 합니다.

농넷은 수급일보라 나중에 값이 정정될 수 있습니다. 불일치가 나오는 것 자체는
이상하지 않지만, **얼마나 어긋나는지 모르고 넣는 것**이 문제입니다.

> 실측 (2026-08-24): 2025-11-12~12-31 구간 215행을 다시 긁어 대조한 결과
> **일치 215 · 불일치 0**. 스크래퍼가 기존 데이터를 그대로 재현합니다.

기본은 **새 행만** 넣고 기존 행은 건드리지 않습니다. 덮어쓰려면 `--update`.

## 컬럼 매핑

| merge CSV | `daily_volume` | 비고 |
|---|---|---|
| `ymd` | `base_date` | PK(1) |
| `item` | `item_label` | PK(2) |
| `total_ton` `top1_ton` `top2_ton` `etc_ton` | 동일 | **integer · NOT NULL**. 스크래퍼는 실수로 주므로 반올림 |
| `top1_region` `top2_region` | 동일 | nullable |
| `req_date` | `req_date` | 수집 시점. `CHECK req_date >= base_date` |
| (없음) | `top1_raw` `top2_raw` | merge CSV 에 없어 NULL. 기존 값은 덮지 않음 |
| (없음) | `loaded_at` | DB default `now()` |

DB 제약을 넣기 전에 파이썬에서 먼저 걸러, 어느 행이 왜 걸리는지 보여줍니다.

```
total_ton · top1_ton · top2_ton · etc_ton  >= 0 이고 NOT NULL
top1_ton >= top2_ton
req_date >= base_date
```

## 알아둘 것

**`req_date` 가 `base_date` 보다 0~7일 늦습니다.** 8일 창으로 훑는 방식이라
그렇습니다. `crop_price_train` 은 이걸 그대로 살려 **as-of 결합**을 합니다 —
기준일까지 실제로 수집이 끝난 물량만 씁니다. 이 지연을 무시하고 결합하면
미래 정보 누수입니다.

**산지 칸에 `기타` 가 섞입니다.** merge 가 경고를 냅니다. 1·2위 산지가 없는
날(반입이 적은 날)에 나타납니다. `arr_top1_region` 은 진단용이라 모델
입력에서 제외돼 있어 학습에는 영향이 없습니다.

**menu 코드는 화면에서 확인한 값입니다.** 농넷이 개편하면 바뀔 수 있습니다.
`probe` 의 `응답 품목명` 이 그걸 잡아줍니다. 마늘(314)·고추(315)는 아직
대조하지 않았습니다 — 둘 다 학습에서 빠져 있어 급하지 않습니다.

**결측일이 있습니다.** 일요일·공휴일은 반입이 없어 응답에도 없습니다.
50일 구간에 7일 결측이 정상 범위입니다.
