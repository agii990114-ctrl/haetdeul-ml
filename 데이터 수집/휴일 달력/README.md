# 휴일 달력 수집

한국천문연구원 특일 정보에서 공휴일을 받아 `ref_holiday` 테이블로 만듭니다.
`ref_calendar`(개장일 달력)의 입력이고, 운영 배치에서 미래 리드타임을 세기 위한 전제입니다.

---

## 준비

```bash
pip install requests
pip install "psycopg[binary]"      # --load-db 를 쓸 때만
```

1. [공공데이터포털](https://data.go.kr)에서 **'특일 정보'** 검색 → 활용신청 (자동 승인)
2. 발급된 서비스키를 `.env` 의 `DATA_GO_KR_SERVICE_KEY=` 뒤에 붙여넣기

인코딩 키·디코딩 키 어느 쪽이든 그대로 넣으면 됩니다. 따옴표는 붙이지 마세요.

---

## 실행

```bash
# 1) 연결 확인 — 한 해만, 캐시 무시
python fetch_holidays.py --start-year 2026 --end-year 2026 --no-cache

# 2) 전 구간 (2015 ~ 올해+2년)
python fetch_holidays.py

# 3) PostgreSQL 직접 적재
python fetch_holidays.py --load-db
```

`--load-db` 를 쓰지 않으면 `ref_holiday.sql` 을 DBeaver 에서 **Alt+X** 로 실행하면 됩니다.
파일 안에 `CREATE TABLE` · `TRUNCATE` · `INSERT` · 확인 쿼리가 모두 들어 있습니다.

| 산출물 | 내용 |
|---|---|
| `ref_holiday.csv` | 적재용 |
| `ref_holiday.sql` | DBeaver 실행용 |
| `work/YYYY.json` | 연도별 원본 응답 캐시. 재실행 시 API 를 다시 부르지 않음 |

연 1회만 갱신되는 데이터라 캐시가 기본입니다. 다시 받으려면 `--no-cache`.

## 왜 필요한가

우리 학습 테이블의 `lead_biz_d` 는 **중도매가 조사일** 축입니다.
그런데 `ref_calendar` 는 **경매 거래일** 로 검증돼 있어 두 축이 다릅니다.

```
경매 개장일   2015~2025   3,348일
중도매 조사일               2,700일
```

648일 차이를 분해하면 이렇습니다.

| 차이 | 건수 | 처리 |
|---|---|---|
| 토요일 | 544 | 조사 규칙 (조사일 중 토요일 0건 / 2,700일) |
| 공휴일 | 약 124 | **이 API** |
| 12월 첫째 금요일 | 11 | 시장 자체 휴장. 별도 규칙 (11년 연속) |
| 역방향(신정 1/2 등) | 16 | 경매는 휴장인데 조사는 함 |

명절 처리도 두 축이 하루씩 어긋납니다.

```
경매      D-1 거래  │ D0  D+1 D+2 휴장
중도매 조사  D-1 휴무 │ D0  D+1 휴무          ← 법정 연휴 그대로
            (D-1 미조사 17/17 · D0 16/16 · D+1 14/14 — 예외 0건)
```

중도매 조사일의 명절 처리는 특별한 시장 규칙이 아니라 **법정 공휴일 그대로**입니다.
그래서 이 API 하나로 조사일 축의 공휴일 부분이 전부 설명됩니다.

최종 규칙 (2015~2025 실측 대조 **미탐 0 · 오탐 0**, 2,700일 완전 일치):

```
조사일 휴무 = 토·일 + ref_holiday + 5/1 근로자의 날
              + 12월 첫째 금요일 + override(2015-08-14)
경매  휴장 = 일 + 신정 1/1~1/2 + 명절 당일~+2일 + 8월 첫 토요일 + override
```

두 축 모두 `ref_holiday` 를 입력으로 쓰되, 그 위에 얹는 시장 규칙이 다릅니다.

**5/1 근로자의 날이 API 에 없습니다.** 법정공휴일이 아니라 근로자의 날 제정에 관한
법률에 따른 유급휴일이라 `getRestDeInfo` 가 주지 않습니다. 그런데 KAMIS 조사는 쉽니다.
이 8건과 2015-08-14(광복 70주년 임시공휴일, API 미수록) 1건을 더하면 잔여가 0 이 됩니다.

## 한계 — 알고 쓸 것

**1. 현재연도 +2년까지만 확정됩니다.**
과기부 월력요항 발표(6~8월) 이후 차차년도가 올라옵니다.
2026년 기준으로 2028년까지이며, `25_ref_calendar.sql` 에 하드코딩된
**2029·2030 명절 날짜는 여전히 미검증**입니다. 매년 갱신하는 배치가 필요합니다.

**2. 임시공휴일은 사후 반영입니다.**
지정 후 최대 1일 이내 반영되고, 대체공휴일은 대통령령 시행 이후 반영됩니다.
즉 **예측 시점에 알 수 없는 휴일이 원리적으로 존재합니다.**
과거 재현에는 문제가 없고, 미래 추론에서만 리드타임이 어긋날 수 있습니다.
실측 사례: 2024-10-01 국군의날 임시공휴일, 2020-08-17 임시공휴일.

**3. API 에 없는 휴무일이 두 종류 있습니다.**
12월 첫째 금요일(시장 자체 휴장, 11년 연속)과 5/1 근로자의 날(법정공휴일이 아님).
둘 다 조사일 축에서 별도 규칙으로 처리해야 합니다.

**4. 2028 설날 하드코딩이 틀렸습니다 — API 로 발견.**
`25_ref_calendar.sql` 의 `ref_lunar_holiday` 는 2028 설날을 `2028-01-26` 으로 적었으나
실제 당일은 `2028-01-27` 입니다(연휴 01-26~01-28 중 가운데). 하루 어긋나 있어
경매 휴장 규칙(당일~+2일)이 통째로 밀립니다. 2015~2027 은 전부 일치했습니다.

## 가락시장 비정기 휴장 — `watch_garak_notice.py`

`ref_holiday` 로는 안 잡히는 휴장이 있습니다. 토요일 시범휴업, 징검다리 휴업,
선거일 같은 것들입니다. 연 1.3회꼴이고 `ref_calendar_override` 로 처리합니다.

### 과거는 게시판을 보지 마세요

**정답은 `auction_prices_daily` 실거래일입니다.** "규칙상 개장인데 거래 0건"을
뽑으면 그게 비정기 휴장입니다. 이 방법으로 14건을 찾아 오탐 0 · 미탐 0 을
달성했습니다 (`25_ref_calendar.sql` 검증 [2]). 공고문보다 실거래가 확실합니다.

배치에도 이 자가교정을 넣으세요. 매일 경락가 수집 후 검증 쿼리를 돌려
"규칙 개장인데 거래 없음"이 나오면 override 후보로 로그에 올립니다.
그러면 과거는 저절로 계속 정확해집니다.

### 게시판이 필요한 건 앞으로 3~4주뿐

리드타임이 18영업일이니 그만큼만 알면 됩니다. 월 1회로 충분합니다.

```bash
python watch_garak_notice.py --future-only
```

공지 게시판에서 '휴업' 공고를 긁어 날짜 후보를 뽑고 `ref_calendar_override`
목록과 대조합니다. override 에 없는 미래 날짜가 나오면 INSERT 문까지 만들어 줍니다.

### 완전 자동은 안 됩니다 — 본문이 이미지입니다

공고 본문이 대부분 이미지입니다. 접근성용 `alt` 속성에 내용을 적어두는 경우가
있어 거기서 건지는데, 공고마다 품질이 다릅니다.

| 공고 | alt | 결과 |
|---|---|---|
| 시범휴업 (`’26.6.3.(수), ’26.7.8.(수) …`) | 전문 수록 | **날짜 추출 가능** |
| 하계·추석 (`채소 7.31 저녁 종료, 8.3 저녁 시작`) | 전문 수록 | 경계일만 — 사람이 판단 |
| 정기·설·신년 | "자세한 내용은 이미지를 확인해 주세요" | 사람이 봐야 함 |

**시범휴업 공고만 개요에 휴업일 자체가 나열됩니다.** 나머지는 경매 종료/시작
경계일이라, 그 사이 어느 날이 휴장인지는 부류별 경매 시간까지 따져야 알 수
있어 기계가 판정할 수 없습니다. 스크립트는 이런 공고를 **후보로 올리지 않고
"사람이 봐야 하는 공고"로 따로 표시합니다.** 조용히 0건을 내놓는 게 가장
나쁩니다.

### 실적 (2026-08-24)

「가락시장 개장일 탄력적 운영 4차 시범휴업」 공고 5회 중 **3회가 달력에 개장으로
잡혀 있었습니다.**

```
2026-10-10(토) · 2026-11-07(토) · 2026-12-12(토)
```

토요일은 경매 축 규칙상 개장이라 override 없이는 미래 리드타임이 틀어집니다.
학습 테이블은 `target_dt` 가 2026-02 까지라 영향이 없었고, **배치에서만 터질
오류**였습니다. 세 건 모두 override 에 넣었습니다 (공고 기준이라 `미검증` 표시).
날짜가 지나면 실거래일로 확정하세요.
