````markdown
## 1. LangGraph 상태머신 재학습 파이프라인 (No-LLM)
재학습 흐름을 표준 스펙으로 정립하고 LangGraph 기반 상태머신으로 재구축했다.
- **설계 원칙**: 상태머신의 어떤 노드에서도 **LLM을 호출하지 않는다**. 모든 판단(지표 악화 판정, 모델 빌드, 2폴드 검증, 교체 여부)은 엄격한 수치 규칙과 코드로 실행된다.
- **흐름**: `판정(judge) → 후보 빌드(build) → 검증(verify) → [사람 승인 대기] → 적용(apply)`
- **UI 연동**: `/retrain/graph/status`(상태 조회) 및 `/retrain/graph/act`(실행 명령) API를 연동하여 웹 대시보드에서 상태를 한눈에 보고 승인할 수 있도록 연결했다.

## 2. 죽은 서버의 포트 점유 트러블슈팅 (D8)
API 코드를 정상 수정했음에도 404가 지속 발생하여 추적한 결과, `uvicorn --reload` 옵션으로 뜬 두 개의 프로세스 중 리로더가 죽었음에도 백그라운드 워커 프로세스가 포트를 계속 잡고 예전 코드로 응답하고 있었다. 프로세스 강제 종료 및 기동 스크립트를 보강하여 해결했다.

## 3. 구매 파트 연동 및 리드 0일차 준비
구매 파트의 D+14 상한 초과 리스크 산출을 위해 단방향 초과 분위수 테이블을 제공하였으며, 당일 밤에 열리는 가락시장 경매가를 아침 배치에서 예측할 수 있도록 리드 0일차 데이터를 설계했다.
````
