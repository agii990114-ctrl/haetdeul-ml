## 1. 대시보드 로딩 속도 대폭 개선 (1.79초 → 0.39초)
콘솔 대시보드 API 로딩이 1.79초로 지연되던 병목을 해결했습니다.
- **원인 분석**: 5개 파트의 7개 쿼리가 직렬로 실행되었고, 파트별로 DB 커넥션을 개별 오픈하여 페이지 로드당 총 35개의 커넥션이 발생함. 물류 섹션에서 동일한 일정 쿼리를 2회 중복 실행함.
- **해결 방안**: 8개 워커 스레드 풀(Thread Pool)을 도입해 7개 쿼리를 동시 병렬 처리하고, 요청당 1개의 읽기 전용 DB 커넥션을 재사용하며 중복 쿼리 결과를 캐싱함. (DB 드라이버가 블로킹 방식이라 Async 대신 스레드 풀 선택)
- **개선 성과**: 응답 시간 **1.79초 → 0.39초**(78% 단축), DB 커넥션 **35개 → 10개** 감소 (PR #804 병합).

## 2. 채팅 스크롤 동작 및 UI 개선
- **문제점**: 사용자가 이전 메시지를 읽는 도중 새 답장이 오면 무조건 최하단으로 강제 스크롤되는 UX 결함 발생.
- **수정 로직**: 사용자가 메시지를 보낼 때만 최하단으로 스크롤하고, 상대방 답장 수신 시에는 현재 스크롤 위치를 유지하며 '새 메시지' 알림 버튼을 표시하도록 개선 (PR #809 병합).
- **UI 보정**: 가독성 향상을 위해 프론트엔드 전체 기본 폰트 크기 4px 확대 (PR #815 병합).

## 3. Q&A 해석기: 로컬 LLM 대체 가능성 벤치마크 평가
Gemini 유료 API 의존도를 낮추기 위해 로컬 GPU(RTX 3050 6GB) 환경에서 로컬 LLM(Ollama, Q4 양자화) 벤치마크를 수행했습니다 (17개 질문, 132개 슬롯 평가).
- **측정 결과**:
  - **Gemini Flash-Lite**: 정답률 **98.5%** / 질문당 **1.5~1.8초**
  - **gemma4:e2b**: 정답률 **87.9%** / 질문당 **12.3초** (17개 중 8개 질문에서 일관성 결여)
  - **exaone3.5:2.4b**: 정답률 **72.7%** / 질문당 **1.9초**
- **기각 사유**: 경량 로컬 모델은 지원하지 않는 품목(대파, 마늘 등) 문의 시 배추·무·양파 등으로 강제 분류하는 심각한 도메인 스코프 왜곡이 발생함. 운영 환경에서는 **Gemini를 유지**하고 로컬 모델은 비상용 백업으로만 설정.

## 4. WBS 작업 백로그 및 최종 산출물 완성

- **최종 발표 자료 준비**: 한국어 상세 문서(모델별 하이퍼파라미터, 31개 피처 중요도, 알고리즘 비교 등) 및 영어 1분 발표 스크립트(2개 슬라이드, 107단어 대본 및 Q&A 대응) 작성 완료.
