# 우리 시스템을 지켜볼 도우미 프로그램 3개 만들기

## 한 줄 요약

**매일 아침 자동으로 도는 우리 시스템이 고장 나도 아무도 모릅니다.
그걸 대신 봐주고 설명해 줄 프로그램 3개를 만듭니다.**

---

## 1. 왜 만드나 — 오늘 실제로 있었던 일

우리 시스템은 매일 아침 9시에 혼자 돌면서 농산물 가격을 예측합니다.
그런데 오늘 확인해 보니 **사흘째 예측을 못 만들고 있었습니다.**

```
8월 29일 아침 9시   실패
8월 30일 아침 9시   실패
8월 31일 아침 9시   실패   ← 오늘
```

매입 담당 파트가 보는 표는 **8월 28일 이후로 멈춰 있습니다.**

### 더 문제인 것

**실패했다는 알림은 떴습니다.** 그런데 사흘 동안 아무도 그 파일을 안 열어봤습니다.

지금까지 이런 고장은 사람이 직접 찾아야 했습니다. 기록 파일을 뒤지고,
데이터베이스를 열어보고, "최근에 뭘 바꿨더라" 를 되짚는 일입니다.
**그걸 대신해 줄 프로그램을 만들자는 것**입니다.

---

## 2. 먼저 — 지금 멈춘 것부터 고칩니다

도우미를 만들기 전에 **당장 예측이 안 나가는 것**부터 살립니다.

### 무엇이 잘못됐나

우리 예측은 이런 식으로 합니다.

```
출발점(어제 가격) 에서  →  얼마나 움직일지 예측  →  최종 가격
```

8월 28일에 이 **출발점 계산법을 바꿨습니다.** 그때 출발점을 담을
새 칸을 하나 만들었는데, **그 칸이 실수로 "입력값" 목록에도 들어갔습니다.**

**비유하면 이렇습니다.** 요리 레시피에 "완성된 국물" 이 재료 목록에도
적혀 있는 상황입니다. 국물을 만들려면 국물이 있어야 한다는 말이 되니,
요리를 시작할 수가 없습니다.

그래서 예측을 돌릴 때마다 이렇게 멈춥니다.

```
입력에 feature 가 없습니다: ['_anchor_mix']
```

### 어떻게 고치나

```
1. 그 칸을 "입력값 목록" 에서 빼기        (코드 한 줄)
2. 모델 2개를 다시 학습                  (경락가 · 중도매가)
3. 예측부터 적재까지 끝까지 돌려서 확인
```

### 이번에 배운 것

8월 28일에 **예측 단계만 확인하고 넘어간 게 화근**이었습니다.
그때는 옛날 모델이었고, 새로 학습한 모델로는 한 번도 안 돌려봤습니다.

**이번에는 마지막 적재까지 이어서 확인합니다.**

---

## 3. 도우미 ① — 데이터가 이상한지 매일 살펴보기

**이미 만들었습니다.** 오늘 처음 돌려봤습니다.

### 무엇을 보나

**"당연히 맞아야 하는 것"** 네 가지만 봅니다.

| 검사 | 쉽게 말하면 | 예전 사고 때 | 지금 |
|---|---|---|---|
| 등급 순서 | 좋은 등급이 나쁜 등급보다 비싼가? | 90% 가 거꾸로 | 4% · 정상 |
| 하루 안 가격 차이 | 같은 날인데 값이 너무 벌어지나? | 132배 | 10.5배 · 확인 필요 |
| 어제-오늘 연결 | 어제 값이 오늘 값을 알려주나? | 0.085 (거의 무관) | 0.625 · 정상 |
| 정답-출발점 짝 | 둘이 같은 기준에서 나왔나? | 96% 어긋남 | 0% · 정상 |

**네 가지 다 우리가 실제로 당한 사고입니다.**

이 검사가 몇 년 전에 있었다면, 8월 27일에 찾은 큰 사고(가격 데이터에
서로 다른 상품 15종이 섞여 있던 것)를 훨씬 일찍 잡았을 겁니다.
그 신호는 **2015년부터 데이터에 그대로 보이고 있었습니다.**

### 고칠 점 하나

첫 실행에서 **잘못된 경보**가 하나 났습니다.

"하루 안 가격 차이" 검사가 **가장 싼 값 하나에 휘둘렸습니다.**
배추 1kg 이 50원인 날이 있었는데, 이건 규격이 섞인 게 아니라
**상품성이 떨어져 헐값에 넘긴 것**이었습니다.

```
지금    제일 비싼 값  ÷  제일 싼 값     ← 극단값 하나에 휘둘림
바꿀 것  위에서 10% 값  ÷  아래서 10% 값  ← 극단값 무시
```

**잘못된 경보가 매일 뜨면 사람이 무시하게 됩니다.**
그러면 진짜 이상도 같이 묻힙니다. 우리가 이미 겪은 실패입니다.

---

## 4. 도우미 ② — 고장 나면 원인을 찾아 설명하기

### 언제 도나

**실패했을 때만** 돕니다. 잘 돌아가면 아무 말도 안 합니다.
조용할 때 조용해야 진짜 신호가 눈에 띕니다.

### 무엇을 읽나

전부 **이미 있는 자료**입니다. 새로 만들 게 없습니다.

```
실행 기록표      몇 번 실행했고 어느 단계에서 멈췄나
단계별 기록표    ★ 오류 원문이 여기 그대로 들어 있습니다
로그 파일        그날 화면에 찍힌 것 전부
경보 파일        실패 알림
데이터 최신일    며칠째 새 자료가 안 들어왔나
```

### 무엇을 알려주나

```
[배치 실패 조사]

어느 단계     예측 만들기
며칠째        3일 연속 (8/29 · 8/30 · 8/31)
영향          매입 파트 전달표가 3일째 멈춤
오류 원문     입력에 feature 가 없습니다: ['_anchor_mix']

원인 추정     8월 28일 변경과 관련 있음
              그때 만든 새 칸이 입력 목록에 섞였음
성격          일시적 오류 아님 (다시 돌려도 같음)

해볼 것       train.py 의 해당 부분 확인
```

**이번 사고를 그대로 재현해서 시험합니다.** 우리가 손으로 찾은 것과
같은 결론이 나와야 합격입니다.

---

## 5. 도우미 ③ — "왜 그렇게 예측했나" 설명하기

### 무엇에 답하나

> **"배추가 2주 뒤에 왜 오른다고 봤어?"**

지금 매입 파트는 **숫자만 받습니다.** 이유를 못 받으니
믿어야 할지 말아야 할지 판단하기 어렵습니다.

### 무엇을 근거로 답하나

전부 **이미 측정된 값**입니다. 지어내지 않습니다.

```
예측값과 범위        전달표에서
모델이 중시하는 것    작년 같은 시기 8.8% · 명절까지 남은 날 6.7%
                    주산지 평년 기온 6.4% · 산지 생육 온도 5.9%
그날의 실제 입력값    주산지 기온 · 반입량 · 명절 남은 날
그 조합의 실제 오차   지난 9개월 채점 결과
```

### 반드시 같이 말해야 할 것

```
우리 경락가 오차는 16% 입니다.
1,000원짜리를 160원 틀립니다.
범위 안에 들어오는 건 10번 중 8번을 목표로 합니다.
```

**"왜" 만 말하고 한계를 안 말하면 과신을 부릅니다.**
이유가 그럴듯할수록 더 위험합니다.

## 6. 세 도우미의 공통 원칙

### 판단은 규칙이, 설명은 도우미가

```
규칙(코드)   이상을 찾아낸다      ← 매번 똑같은 답. 확실함
도우미       원인을 조사해 설명한다  ← 사람이 하던 일
```

**"AI 에게 판단을 맡기지 않는다"** 는 뜻입니다. 이유가 셋입니다.

**① 날짜 두 개 비교하는 데 AI 를 쓸 이유가 없습니다.**
코드 세 줄이면 되고, 매번 같은 답이 나옵니다.

**② 비싸고 느립니다.**

**③ 가장 위험한 것 — 도우미가 조용히 죽으면 "이상 없음" 처럼 보입니다.**

세 번째가 핵심입니다. 8월 27일에 경보 파일이 안 지워져서
**성공해도 계속 "실패 중" 으로 보이던 일**이 있었습니다.
반대 방향의 같은 함정입니다.

**그래서 모든 검사는 AI 없이 끝까지 돕니다.** AI 는 그 위에
사람 말로 요약을 얹는 선택지일 뿐이고, **없어도 보고서는 그대로 나옵니다.**

### 도우미에게 고치게 하지 않습니다

**조사하고 설명하는 데까지만** 합니다.

우리 작업 중에 **표를 통째로 비우고 다시 채우는 단계**가 있습니다.
도우미가 "일시적 오류 같으니 다시 해보자" 하고 재실행하면
**데이터가 날아갈 수 있습니다.**

## 7. 만드는 순서

| 순서 | 무엇 | 왜 이 순서인가 |
|---|---|---|
| **0** | **멈춘 배치 고치기** | 지금 예측이 안 나가고 있습니다. 제일 급합니다 |
| 1 | 도우미 ① 잘못된 경보 수정 | 이미 돌고 있어서, 오탐이 쌓이면 신뢰를 잃습니다 |
| 2 | 도우미 ② 만들기 | 이번 사고가 바로 이 도우미가 잡았어야 할 일입니다 |
| 3 | 도우미 ③ 만들기 | 다른 파트에 나가는 것이라 앞 둘이 안정된 뒤가 낫습니다 |
| 4 | 배치에 연결 | 셋 다 따로 확인한 뒤에 붙입니다 |

### 배치에 연결하는 방법

```
실패로 끝나면   도우미 ② 를 불러 원인 설명을 경보 파일에 덧붙임
성공으로 끝나면 도우미 ① 을 불러 데이터 이상만 확인 (정상이면 조용)
```

**도우미가 실패해도 배치 결과는 안 바뀝니다.**
알리다가 죽으면 본말전도이기 때문입니다.

## 8. 만들지 않을 것 — 미리 정해둡니다

| 안 할 것 | 이유 |
|---|---|
| 도우미가 스스로 고치기 | 표를 비우는 단계가 있어 위험합니다 |
| 도우미만 경보 내기 | 도우미가 죽으면 경보도 사라집니다 |
| 팀 공용 코드 건드리기 | 우리 몫은 `backend/app/ml/` 뿐입니다 |

## 9. 다 되면 무엇이 달라지나

**지금**

```
아침 9시 배치 실패  →  경보 파일 생성  →  아무도 안 봄  →  사흘 지남
```

**바뀐 뒤**

```
아침 9시 배치 실패
  → 경보 파일 생성 (규칙)
  → 도우미가 원인 조사해서 같이 적음
       "3일 연속 · 예측 단계 · 8월 28일 변경 관련 · 전달표 3일 정체"
  → 사람이 파일 하나만 열면 무슨 일인지 바로 알 수 있음
```

**사흘이 하루로 줄어듭니다.** 그리고 원인을 찾는 시간도 줄어듭니다.
