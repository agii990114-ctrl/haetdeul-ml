## 0. 왜 지금 이걸 하나

어제 매입 파트와의 논의에서 드러난 것입니다.

```
매입 파트가 필요한 것   "마진 버퍼 3.3%p 를 지킬 수 있나"
그건 점 예측이 아니라   **범위(밴드)의 문제**
```

실측입니다 (운영 모델 · 홀드아웃 2024~2025 · 486 기준일).

| | D+14 에서 실제가 예측보다 4.7% 넘게 비쌌던 비율 |
|---|---|
| 배추 | **57%** |
| 무 | 46% |
| 양파 | 38% |

**어떤 품목도 안정적으로 못 지킵니다.** 그리고 리드타임을 LT3(D+5)로 줄여도
45% 라, "며칠까지는 믿을 만하다" 는 선이 없습니다.

## 1. ★ 지금 밴드의 문제 — 고정표입니다

```sql
ref_prediction_band   (target_kind · item_nm · lead_biz_d) → ratio_q10 / q50 / q90
```

예: 무 · 경락가 · LT3 → `q10 0.6296` · `q90 1.6320`

**그날 상황과 무관하게 늘 같은 폭입니다.**

```
조용한 날    실제로는 ±5% 안에 들어올 텐데도 ±40% 를 냅니다
흔들리는 날   ±40% 로도 모자란데 같은 값을 냅니다
```

매입 파트가 "구간이 너무 넓어 쓸 수 없다" 고 한 것이 이것입니다.
**넓은 게 문제가 아니라, 좁아야 할 날에도 넓은 것이 문제입니다.**

## 2. ① 분위수 회귀 — **먼저 이것부터**

### 무엇을 하나

지금은 모델이 **가운데 값 하나**만 내고 밴드를 표에서 붙입니다.
분위수 회귀는 **모델이 상한·하한을 직접 배웁니다.**

```
지금    LightGBM(objective=regression_l1)  →  가운데 값
        + ref_prediction_band 고정표      →  ±폭

바꿀 것  LightGBM(objective=quantile, alpha=0.1)  →  하한
        LightGBM(objective=quantile, alpha=0.5)  →  가운데
        LightGBM(objective=quantile, alpha=0.9)  →  상한
```

**그날의 입력에 따라 폭이 달라집니다.** 반입량이 튀거나 기상이 나쁜 날은
넓게, 조용한 날은 좁게 나옵니다.

### 왜 이게 1순위인가

```
· TFT 가 주는 이점(분위수 학습)을 훨씬 싸게 확인할 수 있다
· 지금 코드(train.py · predict.py)를 거의 그대로 쓴다 — objective 만 바꾼다
· 여기서 밴드가 안 좋아지면 TFT 도 같은 벽에 부딪힐 가능성이 크다
```

### 판정 기준 — **점 예측이 아니라 밴드로 잽니다**

`WMAPE` 로 판정하면 안 됩니다. 목적이 다릅니다.

| 무엇 | 어떻게 | 목표 |
|---|---|---|
| **적중률** | 실제가 하한~상한 안에 든 비율 | **80%** (지금 76~85%) |
| **평균 폭** | (상한−하한) ÷ 예측값 | **지금보다 좁게** |
| **★ 조건부성** | 조용한 날 폭 vs 흔들리는 날 폭 | **갈라져야 함** |
| 버퍼 초과 | 실제가 예측보다 4.7% 넘게 비싼 비율 | 지금보다 낮게 |

**③이 핵심입니다.** 적중률만 맞추는 건 고정표도 합니다. **조용한 날에 좁아지지
않으면 이 실험은 실패**입니다.

### 채택 규칙

**§5.7 그대로** — 폴드 두 개(검증 2023 · 검증 2022)에서 부호가 같고
합산이 편차×2 를 넘을 때만 채택합니다.

### 예상되는 함정

- **분위수 교차** — 하한이 상한보다 커지는 행이 생길 수 있습니다.
  세 모델을 따로 학습하기 때문입니다. 나오면 세고, 정렬해서 씁니다.
- **앵커 변환과의 궁합** — 우리는 `log(target/anchor)` 를 학습합니다.
  분위수도 로그비율 공간에서 배우고 역변환해야 합니다.
- **게이트 구간** — LT<3 은 모델을 안 씁니다. 밴드도 앵커 기준으로 붙여야
  합니다. 지금과 같게 유지합니다.

## 3. ② TFT (Temporal Fusion Transformer)

### 왜 후보인가 — 우리 문제 모양에 맞습니다

```
정적 정보        품목 (배추·무·양파)
미리 아는 미래    명절까지 남은 날 · 대상일 요일 · 김장철   ← 이미 갖고 있다
과거 관측        가격 · 반입량 · 기상
여러 칸 동시 예측  18칸을 한 번에
분위수           밴드를 구조적으로 냄
```

**"미리 아는 미래" 를 구조로 구분합니다.** 지금 우리는 그걸 다른 입력과 똑같이
한 줄에 뭉쳐 넣습니다.

### ★ 그런데 이길 가능성은 낮습니다

**① 표본이 작습니다.**

```
학습에 쓸 고유 기준일   1,720개  (2017~2023)
일별 가격 시계열        품목당 2,900일쯤
```

행이 92,880개로 보이지만 한 기준일이 3품목 × 18리드타임 = 54행으로
복제되므로 **실질 표본은 1,720개**입니다. 부스팅에는 넉넉하지만
트랜스포머에는 얇습니다.

**② 긴 시계열 문제가 아닙니다.** 우리는 이미 과거를 `lag1`·`lag3`·`lag7`·
`avg7`·`avg14` 로 눌러놨습니다. 트랜스포머가 그걸 스스로 찾게 하려는 건데
2,900일로는 얇습니다.

> 시계열 분야에 "트랜스포머가 정말 효과적인가" 를 묻는 유명한 반례가 있습니다 —
> 단순한 선형 모델이 여러 벤치마크에서 트랜스포머를 이겼다는 결과입니다.
> **문헌 기억이므로 우리 데이터로 직접 확인해야 합니다.**

**③ 오늘 밝힌 것이 그대로 걸립니다.**

```
모델 입력 28개 중 17개가 한 기준일 안에서 전부 같은 값
18행 내내 진짜로 움직이는 입력의 중요도 합계 22.4%
```

**어떤 구조를 써도 없는 정보를 만들어내지는 못합니다.**
(2026-08-31 실험 넷이 전부 기각된 이유가 이것입니다 —
`진행기록/예측_평탄화_실험4건_20260831.md`)

### 그래서 언제 하나

**①에서 밴드가 좋아지면** TFT 로 갈 이유가 생깁니다. 안 좋아지면 TFT 도
같은 벽입니다. **①의 결과를 보고 정합니다.**

## 4. ③ 다른 부스팅 (XGBoost · CatBoost)

**기대치 낮음.** 같은 feature 로 부스팅만 바꾸면 보통 몇 % 차이입니다.
오늘 실험 넷이 기각된 이유(입력에 정보가 없다)가 모델을 바꿔도 그대로입니다.

**다만 싸고 빠릅니다** (반나절). "부스팅 종류는 봤나" 에 답이 필요할 때 합니다.

## 6. ★ 실험 기록 규칙 — 오늘 사고 때문에 정합니다

**비교 결과를 `prediction_log` 에 넣지 않습니다.**

2026-09-01 에 사고가 났습니다. 예전에 모델을 비교하며 남긴
`old-*` · `ung-*` · `bnd-*` · `ops-*`(붙임표)가 운영 기록 `ops_*`(밑줄)과
섞여 있었고, **한 글자 차이를 못 보고 다 섞어 평균을 내** 매입 파트에
틀린 수치를 보냈습니다. 배추 D+14 초과를 **9% 로 보고했는데 실제는 57%** 였고,
"배추만 공격안" 이라는 결론이 통째로 뒤집혔습니다.

```
실험 결과   실험결과/ 폴더에 CSV·txt 로만 남긴다
운영 적재   ops_* (밑줄) 하나뿐. 매일 배치만 넣는다
성능 측정   봉인 개봉 실행 출력에서 읽는다. prediction_log 로 재지 않는다
```

## 8. ★ 실험하며 추가된 규칙 (2026-09-01)

**① 비교는 운영이 쓰는 자리에서.**
임의로 고른 하이퍼파라미터에서 재면 결론이 뒤집힙니다. §5.7 2폴드 규칙을
통과해도 안전하지 않습니다 — **두 폴드 모두 잘못된 자리에서 재면 두 폴드 모두
같은 방향으로 틀립니다.** 폴드를 나누는 것은 "연도가 특이한가" 를 막아주지
"조건을 잘못 골랐나" 는 못 막아줍니다.

**② 뭉친 그룹으로 판정하지 않는다.**
`calendar` 6개를 통째로 빼니 두 폴드 모두 음수라 제거 후보로 나왔는데,
쪼개니 범인은 하나였고 그건 한 폴드에서만 나왔습니다. 작은 양수 여럿이
큰 음수 하나에 묻혀 부호가 같아 보인 것입니다.

**③ 품목별로 본다** (§8). 통합값이 방향을 뒤집습니다.
- 고정표 조건부성 비: 통합 1.31 → **품목 안에서는 1.00** (품목 차이가 만든 착시)
- `holiday_remain_d`: 통합은 "빼자" 인데 **무는 빼자 · 양파는 두자** 로 갈림

**④ 느린 평균은 시점 식별자가 된다.**
§5.2 는 "월 단위 자료가 해롭다" 였는데, **일별 자료라도 30일 평균을 내면
같은 함정**에 빠집니다. 뉴스·검색 자료는 **비율로** 넣습니다.

**⑤ 조건이 바뀌면 판정은 만료된다.**
타겟·앵커·학습 조건이 바뀌면 ablation 을 다시 돌립니다.
