## 스프린트 3.5 — 예측 구간 (2026-09-01 신설)

매입 파트가 **"구간이 넓어 못 쓰겠다"** 고 한 것이 출발점입니다.
재보니 **넓은 게 문제가 아니라 좁아야 할 날에도 넓은 것**이 문제였습니다.

| 제품 백로그 | 개발 완료 시 테스트 할 항목 | 스프린트 백로그 |
| --- | --- | --- |
| 담당자는 예측 구간이 **그날 상황을 반영하기를** 기대한다. | ① 조용한 날과 흔들리는 날의 폭이 갈릴 것 ② 목표 적중률 80% 를 **품목별로** 지킬 것 ③ 점 예측은 한 톨도 바뀌지 않을 것 ④ 되돌릴 수 있을 것 | ✅ 분위수 회귀 실험 (2폴드 · 세 타겟 · 품목별) |
| | | ✅ **품목별 학습 분위수 확정** — 양파를 배추와 같게 두면 74.5% 로 미달 |
| | | ✅ `train.py --quantile` · `predict.py` 자동 전환 (없으면 옛 방식) |
| | | ✅ 번들 `ops_auc_q` · `ops_whsl_q` 학습 |
| | | ✅ **점 예측 불변 확인** — 1,134행 전부 차이 0 · 실배치에서도 0행 |
| | | ✅ 배치 `shadow` 단계 — 나란히 돌리되 **`prediction_log` 에 안 넣음** |
| | | ⬜ **운영 교체** — 며칠 지켜본 뒤. `model_ver` 이름은 **바꾸지 말 것** |

| | | ⬜ 소매가 — **보류**. 지금도 목표를 지키고 바꾸면 넓어지기만 함 |

**교체 시 지켜야 할 것 하나**: 매입 파트 필터가
`model_ver = ANY('ops_auc','ops_whsl','ops_rtl')` 로 **정확히 일치**만 받습니다.
이름을 바꾸면 저쪽에서 **에러 없이 0건**이 됩니다.
