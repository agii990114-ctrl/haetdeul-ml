# 우리 파트 AI 도우미 기획서

**2026-08-31 · ML 파트 (지환)**
※ 팀의 supervisor·매입 agent 와는 **별개**입니다. 우리 시스템만 봅니다.

---

## 한 줄 요약

**AI 도우미의 일은 "아무도 안 볼 때 깨어 있는 것" 입니다.**

---

## 1. 왜 이 기획서를 다시 쓰나

먼저 만든 `agent/` 폴더의 프로그램은 **AI 가 아닙니다.**
전부 SQL 조회와 사칙연산입니다. AI 를 한 번도 안 부릅니다.

**이름을 잘못 붙였습니다.** 팀이 만드는 AI agent 와 같은 단어를 썼는데
성격이 완전히 다릅니다. 그래서 이름을 나누고, **AI 가 진짜 필요한 곳이
어디인지부터 다시 정리합니다.**

| | 팀의 agent | 우리가 만든 것 | 이 기획서 |
|---|---|---|---|
| 판단하는 주체 | AI | **코드** | 코드 + AI |
| 같은 입력에 같은 답 | 보장 안 됨 | 보장됨 | 규칙 부분만 보장 |
| 이름 | agent | **점검기** 로 변경 | **AI 도우미** |

---

## 2. AI 가 정말 필요한지 가리는 기준

무엇이든 AI 로 만들면 안 됩니다. **세 가지를 물어봅니다.**

```
① 답이 하나로 정해져 있나?              → 그렇다면 규칙
② 일어날 경우를 미리 다 셀 수 있나?      → 그렇다면 규칙
③ 처음 보는 상황이거나, 자유로운 글을
   읽고 이어붙여야 하나?                → 그렇다면 AI
```

**예를 들어**

```
"어제 데이터가 들어왔나?"          날짜 두 개 비교 → 규칙
"등급 순서가 뒤집혔나?"            비교 → 규칙
"이 오류 문구가 왜 났을까?"        처음 보는 문장 → AI
"이 이상한 값의 원인이 뭘까?"      뒤져봐야 앎 → AI
```

---

## 3. 후보를 이 기준으로 걸러냈습니다

| 후보 | AI 필요? | 판정 |
|---|---|---|
| **처음 보는 고장 원인 찾기** | ⭕ 매번 다른 오류 | **1순위** |
| **데이터 이상의 원인 캐기** | ⭕ 어디를 볼지 모름 | **2순위** |
| 예측 이유 설명하기 | 🔶 틀로도 절반은 됨 | 3순위 |
| 실험 결과 해석·다음 제안 | ⭕ 그러나 위험 | 보류 |
| 문서·회신 초안 | ⭕ 그러나 이미 됨 | 안 만듦 |

### 뒤 둘을 뺀 이유

**실험 해석**은 AI 가 잘하지만, **틀린 실험을 제안하면 며칠을 날립니다.**
우리는 오늘 하루에만 잘못된 채점 기준을 두 번 만들었습니다. 사람이 옆에
있을 때 하는 게 맞습니다.

**문서 초안**은 지금 Claude Code 로 이미 하고 있습니다. 같은 걸 또 만들
이유가 없습니다.

---

## 4. 만들 것 ① — 고장 원인 찾기 도우미  **(1순위)**

### 왜 이게 1순위인가

**오늘 실제로 있었던 일입니다.**

```
8월 29일 아침 9시   예측 실패
8월 30일 아침 9시   예측 실패
8월 31일 아침 9시   예측 실패
```

**사흘 동안 아무도 몰랐습니다.** 매입 파트에 나가는 표가 사흘째 멈춰
있었습니다. 알림 파일은 떴는데 아무도 안 열었습니다.

원인은 오류 문구 한 줄에 다 있었습니다.

```
입력에 feature 가 없습니다: ['_anchor_mix']
```

**이 한 줄에서 "8월 28일에 바꾼 것 때문" 까지 이어붙이는 게 AI 의 일입니다.**
규칙으로는 못 만듭니다. 다음 고장은 다른 문구로 올 테니까요.

### 어떻게 도나

```
1단계 (규칙)   실패했나? 며칠째인가? 전달표가 몇 일 멈췄나?
2단계 (AI)     오류 문구 + 최근 코드 변경 + 그 파일 내용을 읽고
               "왜 이런 일이 생겼나" 를 문장으로 씀
3단계 (사람)   읽고 판단. 고치는 건 사람이 함
```

### AI 에게 주는 것

```
오류 문구 원문        batch_run_stage 표에 그대로 있음
최근 7일 코드 변경    git log / 파일 수정 시각
관련 파일 앞뒤 30줄   오류 문구에서 이름을 뽑아 찾음
지난 고장 기록        진행기록/ 에 16개 문서
```

**지난 기록을 주는 게 중요합니다.** 같은 실수를 반복하기 때문입니다 —
"정의를 여러 곳에 복사해 두고 한 곳만 고침" 이 최근에만 세 번 있었습니다.

---

## 5. 만들 것 ② — 데이터 이상 원인 캐기  **(2순위)**

### 규칙 점검기와 짝입니다

```
점검기(규칙)   "배추 자기상관이 0.30 아래로 떨어졌습니다"   ← 여기까지
AI 도우미      "왜 떨어졌는지" 를 찾아냄                  ← 이어받음
```

### 왜 AI 가 필요한가

**어디를 봐야 할지 모릅니다.** 8월 27일 사고 때 제가 밟은 길입니다.

```
범위가 이상하게 넓다  →  최고가가 21배다  →  원본 API 를 열어본다
→ 거래 건별이고 포장 규격이 있다  →  하루에 15개 상품이 섞였다
```

**미리 정해둔 순서가 아닙니다.** 이상한 걸 발견하고 그다음을 정한 것입니다.

### AI 가 할 수 있는 조사

```
소분류별로 갈라보기      쌈배추가 갑자기 늘었나
포장별로 갈라보기        새 포장이 등장했나
시장별로 갈라보기        특정 시장만 이상한가
날짜별로 좁혀보기        언제부터 시작됐나
```

**결론은 AI 가 내지만, 근거 수치는 전부 SQL 결과입니다.** 지어낸 숫자가
못 들어가게 막습니다.

---

## 6. 만들 것 ③ — 예측 이유 설명  **(3순위)**

매입 파트가 **"배추가 2주 뒤에 왜 오른다고 봤어?"** 라고 물으면 답합니다.

**절반은 틀로도 됩니다.** "주산지 기온이 평년보다 2도 높음" 같은 건
값만 채워 넣으면 됩니다. **AI 가 필요한 건 그것들을 이어서 하나의
이야기로 만드는 부분**입니다.

**그래서 3순위입니다.** 앞 둘보다 급하지 않고, 틀만으로도 상당 부분 됩니다.

---

## 7. 구조 — 세 층으로 나눕니다

```
┌─ 1층 · 규칙 ─────────────────────────────┐
│  이상을 찾아낸다. 경보를 낸다.             │
│  AI 없이 끝까지 돈다.                     │
└──────────────────────────────────────────┘
                  ↓ 이상일 때만
┌─ 2층 · AI ───────────────────────────────┐
│  원인을 조사하고 설명을 쓴다.              │
│  고치지는 않는다.                          │
└──────────────────────────────────────────┘
                  ↓
┌─ 3층 · 사람 ─────────────────────────────┐
│  읽고 판단하고 고친다.                     │
└──────────────────────────────────────────┘
```

### 왜 1층을 규칙으로 두나

**AI 가 조용히 죽으면 "이상 없음" 처럼 보이기 때문입니다.**

우리는 이미 반대 방향으로 당했습니다. 8월 27일에 경보 파일이 안 지워져
**성공해도 계속 "실패 중"** 으로 보였습니다. 같은 함정의 반대편입니다.

**1층이 규칙이면, AI 가 죽어도 경보는 뜹니다.**

---

## 8. 절대 못 하게 막을 것

| 금지 | 이유 |
|---|---|
| **스스로 고치기** | 표를 통째로 비우는 단계가 있습니다. 잘못된 재시도로 데이터가 날아갑니다 |
| **숫자 지어내기** | 근거 수치는 전부 SQL 결과만. AI 가 계산하지 않습니다 |
| **AI 만으로 경보 내기** | AI 가 죽으면 경보도 사라집니다 |
| **DB 에 쓰기** | 조회 전용 계정으로 붙입니다 |
| **팀 코드 건드리기** | 우리 몫은 `backend/app/ml/` 뿐입니다 |

### 숫자를 못 지어내게 하는 방법

AI 에게 **"직접 계산하지 말고, 준 표에서 그대로 옮겨라"** 고 지시하고,
답에 나온 숫자가 우리가 준 표에 있는지 **프로그램이 대조**합니다.
없는 숫자가 나오면 그 문장을 버립니다.

**오늘 그래프 만들 때 이미 이 방식을 썼습니다** — 그림의 수치가 실험
기록과 같은지 기계로 대조해 "불일치 0건" 을 확인했습니다.

## 9. 시작하려면 필요한 것

**지금은 아무것도 없습니다.**

```
API 키          없음  ← 이것만 있으면 시작 가능
SDK 패키지      없음  (pip install 한 줄)
읽을 재료       있음  실험기록 68개 · 진행기록 16개 · DB 전체
```

### 선택지

| 안 | 내용 | 비용 |
|---|---|---|
| **ⓐ** | 우리 몫 API 키 발급 | 사용한 만큼 |
| ⓑ | 팀 공용 LLM 사용 | 팀 협의 필요 |

**ⓐ 를 권합니다.** 팀과 별개로 간다고 하셨고, 우리 쪽 호출량은
**하루 1~2번**(고장 났을 때만)이라 비용이 거의 안 듭니다.

## 10. 만드는 순서

| 단계 | 무엇 | 걸리는 시간 |
|---|---|---|
| 0 | 이름 정리 (`agent/` → `점검/`) | 10분 |
| 1 | 규칙 점검기 오탐 수정 | 30분 |
| 2 | API 키 준비 | (사용자) |
| 3 | **고장 원인 찾기 도우미** | 2~3시간 |
| 4 | 실제 고장으로 시험 | 30분 |
| 5 | 배치에 연결 | 30분 |
| 6 | 데이터 이상 원인 캐기 | 이후 |

### 4단계가 중요합니다

**8월 31일 사고를 그대로 재현해서 시험합니다.**

```
넣을 것   run_id 28
나와야 할 것
  · 3일 연속 실패
  · 예측 단계
  · _anchor_mix 라는 이름이 8/28 변경과 연결됨
  · 전달표 3일 정체
```

**우리가 손으로 찾은 것과 같은 결론이 나와야 합격입니다.**
안 나오면 그 도우미는 쓸 수 없습니다.

## 11. 다 되면 무엇이 달라지나

**지금**

```
아침 9시 실패 → 알림 파일 생성 → 아무도 안 봄 → 사흘 지남
                                             → 사람이 2시간 조사
```

**바뀐 뒤**

```
아침 9시 실패
  → 알림 파일 생성 (규칙)
  → AI 가 원인 조사해서 같이 적음
      "3일 연속 · 예측 단계 · 8/28 에 만든 _anchor_mix 가 추론에 없음
       · 관련 코드는 train.py 449줄 · 전달표 3일 정체"
  → 사람이 파일 하나 열고 바로 고침
```

**사흘이 하루로, 조사 2시간이 10분으로 줄어듭니다.**

## 12. 한 가지 솔직한 말

**이 도우미가 오늘 사고를 막지는 못했을 겁니다.**

막으려면 8월 28일에 **배치를 끝까지 돌려보게** 했어야 하는데, 그건
AI 가 아니라 **규칙**이 할 일입니다. "모델을 새로 저장했으면 push 까지
확인" 같은 규칙이요.

**AI 는 이미 난 고장을 빨리 알려줄 뿐입니다.** 안 나게 하는 건 규칙과
사람의 몫입니다. 기대를 정확히 두는 편이 낫습니다.
