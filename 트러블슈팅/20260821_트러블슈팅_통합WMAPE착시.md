# 트러블슈팅 — 통합 WMAPE 착시

> 원가 캣쳐 · 4품목 확장 후 baseline 급락 현상
> 작성일 2026-08-21 · 데이터셋 `crop_price_train_202608211407.csv`

---

## 1. 증상

품목을 배추·양파 2종에서 배추·양파·무·마늘 4종으로 확장한 뒤
baseline WMAPE 가 비정상적으로 좋아졌다.

| 구성 | 품목 | baseline WMAPE |
|---|---|---|
| 이전 | 배추 단독 | 0.2114 |
| **현재** | **4품목** | **0.0781** |

리드타임 1일이 0.0272(2.7%) 로, 농산물 가격이 하루 만에 2.7% 밖에
움직이지 않는다는 뜻이 되어 현실과 맞지 않았다.

검증 스크립트도 경고를 냈다.

```
[상관 검사] |corr| > 0.995 이면 누수 의심
  whsl_prc_lag1   +0.9978  ✗ 누수 의심
  whsl_prc_lag3   +0.9956  ✗ 누수 의심
  whsl_prc_avg7   +0.9957  ✗ 누수 의심
```

**초기 판단**: 시계열 평활화 또는 타겟·앵커가 같은 행에서 나오는 구조적 오류를
의심하고 "학습 금지" 로 결론지었다.

## 2. 진단 — 데이터는 정상이었다

### 확인 1. 개별 행 검사

```sql
SELECT base_dt, item_nm, lead_biz_d, target_dt, whsl_prc_lag1, target_whsl_prc
FROM crop_price_train
WHERE item_nm='배추' AND base_dt='2024-03-15' ORDER BY lead_biz_d LIMIT 5;
```

| base_dt | lead | target_dt | lag1 | target |
|---|---|---|---|---|
| 2024-03-15 | 1 | 2024-03-18 | 1,380 | 1,500 |
| 2024-03-15 | 2 | 2024-03-19 | 1,380 | 1,500 |
| 2024-03-15 | 3 | 2024-03-20 | 1,380 | 1,460 |
| 2024-03-15 | 4 | 2024-03-21 | 1,380 | 1,420 |
| 2024-03-15 | 5 | 2024-03-22 | 1,380 | 1,460 |

**구조가 정상이다.** 같은 기준일이므로 `lag1` 은 18행 모두 동일하고,
`target` 은 리드타임마다 다르다. 변화율도 +2.9~+8.7% 로 자연스럽다.
금요일 기준일에서 lead 1 이 월요일로 넘어간 것도 영업일 축이 맞게 작동한 증거다.

### 확인 2. 품목별 분해 — 여기서 원인이 드러났다

```sql
SELECT item_nm,
       ROUND(SUM(ABS(target_whsl_prc - whsl_prc_lag1)) / SUM(target_whsl_prc), 4) AS wmape
FROM crop_price_train WHERE lead_biz_d = 1 GROUP BY 1;
```

| 품목 | 평균가(원/kg) | 개별 WMAPE | **분모 비중** |
|---|---|---|---|
| **마늘** | **6,244** | **0.0389** | **66.0%** |
| 양파 | 1,135 | 0.0926 | 12.8% |
| 배추 | 1,088 | **0.2135** | 12.3% |
| 무 | 801 | 0.1603 | 9.0% |
| | | **통합 0.0781** | |

**배추 단독 WMAPE 는 0.2135 로, 이전 데이터의 0.2114 와 거의 같다.**
데이터가 달라진 것이 아니라 지표가 달라진 것이다.

## 3. 원인 — WMAPE 의 가중 특성

WMAPE 는 오차의 합을 실제값의 합으로 나눈다.

```
WMAPE = Σ|실제 − 예측| / Σ|실제|
```

분모가 합계이므로 **가격 수준이 높은 품목이 자동으로 큰 가중치**를 갖는다.
마늘은 kg당 6,244원으로 다른 품목의 6~8배라 분모의 66% 를 차지한다.

그런데 마늘은 예측하기 가장 쉬운 품목이다.

| 품목 | 전일과 값이 바뀐 날 | lag1 이 전날과 동일한 날 |
|---|---|---|
| **마늘** | **10.2%** | **94.4%** |
| 양파 | 47.6% | 68.5% |
| 배추 | 66.6% | 43.7% |
| 무 | 75.8% | 37.2% |

**마늘 가격은 20일 중 19일이 전날과 똑같다.**
6월에 수확해 1년 내내 저장 출하되므로 시세가 계단식으로만 움직인다.
(주산지가 연중 경남 창녕 하나였던 것과 같은 이유다)

결과적으로 **"분모는 가장 크고 오차는 가장 작은" 품목이 통합값을 지배**해
전체 WMAPE 가 0.2114 → 0.0781 로 떨어진 것이다.

### 상관 0.9978 도 같은 이유

마늘의 94% 가 전날과 동일한 값이므로 `whsl_prc_lag1` 과 `target_whsl_prc` 의
상관이 1 에 가까워진다. 누수가 아니라 **품목의 성질**이다.

검증 스크립트의 상관 검사는 배추 단일 품목 기준으로 만들어져
이 상황을 오탐한다.

## 4. 조치

### 4-1. 평가를 품목별로 분해 (필수)

통합 WMAPE 는 보고하지 않는다. 마늘 하나가 지배하므로 의미가 없다.

```python
for item, g in va.groupby("item_nm"):
    print(item, wmape(g[TARGET], g["pred"]))
```

발표 시에도 "전체 WMAPE 0.078" 이 아니라 품목별로 제시해야 한다.
전자는 방어할 수 없다.

### 4-2. 앵커 타겟 변환의 중요성이 커졌다

품목 간 가격 수준이 6~8배 차이 나므로, 절대가격을 학습하면 모델이
**마늘 오차 줄이기에만 집중**한다. 로그 비율로 바꾸면 모든 품목이
"±몇 %" 라는 같은 스케일이 되어 이 편향이 사라진다.

```
y = log(target / anchor)
```

2품목일 때보다 4품목에서 이 처리가 더 중요해졌다.

### 4-3. 마늘의 성격을 인정할 것

94% 가 전날과 같은 값이면 **"어제 가격 그대로" 를 이기기가 원리적으로 어렵다.**
예측 문제로서 성격이 다르며, 서비스 관점에서도 마늘은 예측 수요가 낮다.

선택지 두 가지가 있다.

| 방안 | 내용 |
|---|---|
| A | 4품목 글로벌 모델 유지, **평가만 품목별로** 분해 |
| B | 마늘을 별도 모델로 분리하거나 대상에서 제외 |

**A 를 권한다.** 글로벌 모델은 품목 간 공통 패턴(폭우→출하 감소)을 공유하는
이점이 있고, 마늘이 학습에 해를 끼친다는 증거는 아직 없다.
ablation 에서 마늘 포함/제외를 비교해 판단하면 된다.

### 4-4. 검증 스크립트 보완

`validate_train_table.py` 의 두 항목이 4품목 환경에서 오탐한다.

| 검사 | 문제 | 보완 |
|---|---|---|
| 상관 검사 | 마늘 때문에 0.9978 오탐 | 품목별로 나눠 계산 |
| 주산지 매핑 대조 | 품목 구분 없이 대조 | 품목별로 그룹핑 |
| baseline | 통합값만 출력 | 품목별 분해 추가 |

## 6. 배운 점

**지표는 데이터가 바뀌면 의미도 바뀐다.**
같은 WMAPE 라도 단일 품목일 때와 가격대가 다른 여러 품목을 합쳤을 때
해석이 완전히 달라진다. 품목이 늘어난 순간 통합 지표는 신뢰할 수 없게 됐다.

**개선처럼 보이는 것을 먼저 의심할 것.**
baseline 이 0.2114 → 0.0781 로 좋아졌을 때 "데이터가 좋아졌다" 가 아니라
"무언가 잘못됐다" 로 접근한 것은 옳았다. 다만 원인 추정(구조적 오류)이
빗나갔고, 품목별 분해라는 한 단계를 거쳤어야 했다.

**검증 도구도 전제가 있다.**
`validate_train_table.py` 는 배추 단일 품목 기준으로 만들어져
상관 검사와 매핑 대조에서 오탐을 냈다. 도구가 만들어진 맥락이 바뀌면
도구도 함께 갱신해야 한다.

**저장 출하 품목은 예측 대상으로서 성격이 다르다.**
마늘 94%, 양파 68.5% 가 전날과 동일한 값이다. 배추·무(37~44%)와는
문제의 난이도 자체가 다르며, 같은 지표로 묶어 평가하면 왜곡이 생긴다.
