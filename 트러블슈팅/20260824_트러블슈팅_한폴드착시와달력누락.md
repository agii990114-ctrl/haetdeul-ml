# 트러블슈팅 — 한 폴드 착시와 미래에만 틀린 달력

> 원가 캣쳐 · 학사일정 feature 판정 · 가락시장 휴업 공고 대조
> 작성일 2026-08-24 · 데이터셋 `crop_price_train_202608241719.csv`

오늘 걸린 네 가지는 성격이 같다. **눈앞의 숫자가 맞아 보이는데 틀린 경우**다.
지표가 개선처럼 보이거나, 결측이 무해해 보이거나, 기준선이 그대로인 것처럼
보이거나, 달력이 과거에 완벽해서 미래도 맞을 것처럼 보였다.

---

## 1. 학사일정 feature — 한 폴드만 봤으면 채택했다

### 증상

백로그 P3 의 "개학·방학 캘린더(급식 수요)" 를 만들어 첫 판정을 돌렸다.
검증 2023 한 폴드에서 결과가 좋았다.

```
경락가  전체(32 feature)  WMAPE 0.1763  +5.6%
        − school(31)      WMAPE 0.1799  +3.7%     손실 +0.0036  편차 0.0014  → O
```

**+1.9%p 개선**이다. 시드 편차의 2배를 넘어 판정도 O(유의)였다.
중도매가도 같은 폴드에서 +12.1% → +13.2% 로 나왔다.

가설도 그럴듯했다. 중도매가의 사용자는 식당·급식 구매담당이니
방학이 수요에 직접 걸린다고 볼 수 있었다.

### 진단 — 폴드를 셋으로 늘렸다

`CLAUDE.md` 5.7 의 규칙("폴드 두 개 이상에서 부호가 같을 때만 채택")에 따라
검증 2022·2021 을 추가했다.

| 타겟 | A(검증2023) | B(검증2022) | C(검증2021) | 합산 | 편차×2 |
|---|---|---|---|---|---|
| 경락가 | **+0.0036 O** | −0.0017 △ | +0.0027 △ | +0.0046 | 0.0028 |
| 중도매가 | +0.0011 △ | −0.0014 △ | −0.0009 △ | −0.0012 | 0.0023 |
| 소매가 | −0.0002 △ | +0.0005 △ | −0.0005 △ | −0.0002 | 0.0012 |

**세 타겟 모두 부호가 갈렸다.** 9개 조합에서 O 는 경락가 폴드 A 하나뿐이다.
채택 조건 미충족 → **기각**.

### 왜 속을 뻔했나

**① 모델에 연중 시점 feature 가 하나도 없다.**
`DROP` 에 `base_dt`·`target_dt` 가 들어 있고 월(月) 컬럼도 없다. 달력 계열은
`target_dow`·`kimchi_season_yn`·`holiday_remain_d` 뿐이다.
`school_open_ratio` 는 연중 프로파일이라 **월과 상관 +0.443** 이다.
급식 수요가 아니라 "지금이 몇 월인가" 를 알려준 것일 수 있었다.

**② 가설이 맞는 것처럼 보이면 검증을 덜 하게 된다.**
"중도매가 사용자 = 급식 구매담당" 이라는 서사가 그럴듯해서 폴드 A 의 O 를
확인 사살로 받아들이기 쉬웠다. 정작 **중도매가가 가장 나빴다**(B·C 모두 음수).

### 조치

- 3폴드 판정 결과를 `results/ablation_school_3fold.txt` 에 근거와 함께 남김
- 계절성 대조 실험(`+season` 을 준 뒤에도 school 이 기여하는가)을 설계해 뒀으나
  기각이 확정돼 실행하지 않음. 재실험 시 사용

## 2. 결측 36.6% 를 그대로 넣을 뻔했다

### 증상

NEIS 학사일정 실측은 2020-09 부터다. 학습 구간은 2017~2022 이다.

| 구간 | 실측 커버리지 |
|---|---|
| 학습 2017~2022 | **36.6%** |
| 검증 2023 | 97.5% |
| 테스트 2024~25 | 88.5% |

LightGBM 은 NaN 을 알아서 처리하니 그냥 넣어도 돌아간다.
**검증 구간은 커버리지가 97.5% 라 오히려 성능이 좋게 나왔을 것이다.**

### 진단

이건 이미 겪은 함정이다. `CLAUDE.md` 5.2 에서 경제 변수를 제거한 이유가
"월 단위로 같은 값이 반복돼 모델이 시점 식별자로 오용" 이었고,
`crop_area_yoy_rt` 를 `DROP` 에 넣은 이유가 "결측이 무작위가 아니라
발간 일정에 의존" 이었다.

여기서는 **결측 여부 자체가 "2020-09 이전인가" 라는 시점 식별자**가 된다.
학습 구간의 63% 가 NULL, 검증 구간의 2.5% 만 NULL 이므로 모델이
"NULL 이면 학습 데이터, 값이 있으면 검증 데이터" 를 배울 수 있다.

### 조치 — 추가 수집을 먼저 확인하고, 안 되면 규칙으로

`open.neis.go.kr` API 를 직접 호출해 보유 범위를 실측했다.

```
DATA 개방일 2019-04-01
서울 경기초등학교(7031110):
  2026-03 ✓ 23건   2026-08 ✓ 24건   2025-03 ✓
  2024-03 ✗   2023-03 ✗  …  2017-03 ✗
→ 보유 = 최근 2개 학년도. 2017-01~2019-03 은 원천적으로 없음
```

결측을 없앨 방법이 없으므로 **실측 5년으로 (월,일) 중앙값 프로파일을 만들어
2015~2028 전 구간에 같은 규칙을 적용**했다. 전 구간이 같은 성격이 되어
시점 식별자 문제가 사라진다.

leave-one-year-out 으로 규칙의 손실을 쟀다.

| | 값 |
|---|---|
| MAE | 0.0315 |
| 급식일(≥0.5) 이진 일치 | **96.7%** |

규칙으로 바꾸면서 잃은 신호는 3% 남짓이다. 덤으로 **미래 리드타임에도 값이
있어** 배치에서 쓸 수 있게 됐다(실측이었다면 불가능).

## 3. 새 컬럼이 기준선을 조용히 바꾼다

### 증상

`train.py` 는 `DROP` 에 없는 컬럼을 전부 feature 로 쓴다.

```python
feats = [c for c in df.columns if c not in drop]
```

`crop_price_train` 을 재생성하면 `school_open_ratio` 가 생긴다.
그 순간 **확정된 31-feature 기준선이 아무 경고 없이 32개가 된다.**
"feature 변경 없음" 으로 확정한 ablation 2차 결론이 무효가 되는데
아무도 모른다.

### 조치

판정 전까지는 기본 제외로 두고 실험 플래그로만 켜게 했다.

```python
SCHOOL_COLS = ["school_open_ratio"]
TARGET_DROP = { "auc": ECON|SCHOOL, "whsl": ECON|SCHOOL,
                "rtl": ECON|WEATHER|SCHOOL }
# --with-school 로만 포함
```

**반대 방향 사고도 막았다.** `--with-school` 을 줬는데 CSV 에 컬럼이 없으면
그냥 넘어가지 않고 멈추게 했다. 안 그러면 "학사일정 포함" 이라고 찍어놓고
기준선과 같은 결과를 새 결과로 착각한다.

검증: 46컬럼 CSV 로 세 타겟을 돌려 **feature 31/31/24** 를 확인했다.

## 4. 달력이 과거에는 완벽한데 미래가 틀렸다

### 증상

`ref_calendar` 는 2016-01~2026-08 실거래일 대조에서 **오탐 0 · 미탐 0** 이다.
비정기 휴장 14건을 `ref_calendar_override` 로 채워 만든 결과다.

그런데 서울시농수산식품공사 「가락시장 개장일 탄력적 운영 4차 시범휴업」
공고를 대조하니 5회 중 3회가 빠져 있었다.

```
2026-06-03 ✓  2026-07-08 ✓
2026-10-10(토)  !! 개장으로 잡힘
2026-11-07(토)  !! 개장으로 잡힘
2026-12-12(토)  !! 개장으로 잡힘
```

### 진단

**override 를 실거래일에서 역산했기 때문이다.** 그 방법은 원리적으로
**이미 지난 날만** 채운다. 아직 오지 않은 날은 거래 기록이 없으니 나올 수 없다.

경매 축 규칙에서 토요일은 개장이라, 토요일 시범휴업은 override 없이는 넘어간다.
과거 토요일 휴업(2023-11-04, 2025-11-01 등)은 전부 override 에 있었는데
그것도 실거래로 찾은 것이다.

**학습 테이블에는 영향이 없었다.** `target_dt` 최대가 2026-02 라 2026-10 이후는
범위 밖이다. 즉 **배치를 돌리기 시작해야 비로소 터질 오류**였고, 그때는
미래 리드타임이 조용히 하루씩 밀렸을 것이다.

### 조치

override 에 3건을 추가하고 `미검증` 으로 표시했다(공고 기준, 실거래 대조 전).

게시판 감시 스크립트 `watch_garak_notice.py` 를 만들었다. 다만 **본문이 거의 다
이미지**라 완전 자동은 불가능했다.

| 공고 | alt 속성 | 결과 |
|---|---|---|
| 시범휴업 `’26.6.3.(수)…` | 전문 수록 | **날짜 추출 가능** |
| 하계·추석 `채소 7.31 저녁 종료` | 전문 수록 | 경계일뿐 — 사람이 판단 |
| 정기·설·신년 | "자세한 내용은 이미지를 확인해 주세요" | 사람이 봐야 함 |

하계·설·추석 공고는 휴업일이 아니라 **경매 종료/시작 경계일**을 적는다.
그 사이 어느 날이 휴장인지는 부류별 경매 시간까지 따져야 해서 기계가 못 정한다.
그래서 스크립트는 **못 뽑은 공고를 숨기지 않고 "사람이 봐야 하는 공고" 로
URL 과 함께 따로 출력한다.** 조용히 0건을 반환하는 것이 가장 나쁘다.

역할 분담을 명확히 했다.

```
과거  auction_prices_daily 실거래일   ← 정답. 자가교정으로 계속 정확해진다
미래  게시판 공고                     ← 앞으로 3~4주만. 월 1회 사람이 확인
```

## 5. 함께 정리된 것

**성능 기준점 재수립.** `ref_calendar` v2 연결과 자연키 정렬 수정 이후
기존 기록이 재현되지 않아 P0 로 열려 있었다. 오늘 재측정했다.

| 타겟 | feature | WMAPE | 개선율 | 이전 기록 |
|---|---|---|---|---|
| 경락가 | 31 | 0.1767 | +5.4% | +5.2% |
| 중도매가 | 31 | 0.1364 | +13.0% | +13.5% |
| 소매가 | 24 | 0.0891 | +15.1% | +15.4% |

구본(`...1210`)에 학사일정을 조인해 돌린 중도매가가 0.1364 로 **완전히 일치**해,
v5 재실행 재현성까지 함께 확인됐다.

**원본 데이터의 숨은 결함.** 학사일정 CSV 71개 중 일부가 파일명과 내용이
어긋났다. "2024년10월" 이 실제로는 10/09~11/08 을 담는다. 31일 창으로 받은
흔적이고, 이어붙여도 **8곳 45일**이 빈다. 프로파일은 연도별 중앙값이라
영향이 작아 그대로 안고 갔다.

**NEIS 는 일요일에 휴업일 행을 만들지 않는다.** 그래서 실측 일요일 개교율
중앙값이 0.995 로 "개교" 로 잡힌다. 조사 축(`target_dt`)에 일요일이 없어
실무 영향은 없지만 프로파일을 오염시키므로 산출에서 제외했다.

## 6. 배운 점

**한 폴드는 가설을 확인해 주지 못한다.**
`auction` 그룹에 이어 두 번째다. 폴드 A 만 봤다면 "+1.9%p 개선" 으로 보고하고
채택했을 것이다. 규칙이 있어서 살았지 판단력으로 산 게 아니다.

**서사가 그럴듯할수록 더 의심해야 한다.**
"중도매가 사용자 = 급식 구매담당" 이라는 설명이 맞아떨어져서 폴드 A 의 O 를
쉽게 믿을 뻔했다. 결과는 정반대로 **중도매가가 가장 나빴다.**

**결측은 값이 없는 게 아니라 "없다는 정보" 다.**
결측 패턴이 시간과 상관되면 그 자체가 feature 가 된다. 경제 변수·KREI 재배면적에
이어 세 번째 사례다. 커버리지를 **학습/검증 구간별로 나눠** 보는 게 진단의 핵심이었다.

**"과거에 완벽함" 은 "미래에 맞음" 을 뜻하지 않는다.**
실거래일 역산은 원리적으로 과거만 채운다. 오탐 0 · 미탐 0 이라는 숫자가
미래를 보장하는 것처럼 읽혔다. 검증 방법의 **적용 범위**를 함께 적어야 한다.

**자동화가 안 되는 구간은 안 된다고 표시해야 한다.**
공고 절반이 이미지뿐이라 파서가 날짜를 못 뽑는다. 그때 0건을 반환하면
"휴업 없음" 으로 읽힌다. 못 한 일을 못 했다고 말하는 출력이 필요하다.

**폴드 B 가 두 번째로 예외 부호를 냈다.**
`volume` 재판정에서도 음수는 폴드 B 하나뿐이었다. 서로 무관한 feature 둘이
같은 폴드에서만 반대인 건 우연 같지 않다. 폴드 B 는 학습에 코로나기가 들어가고
검증이 회복기 2022 다. 규칙을 바꿀 근거는 아니고 관찰로만 남긴다.
**세 번째 사례가 나오면 조사할 것.**
