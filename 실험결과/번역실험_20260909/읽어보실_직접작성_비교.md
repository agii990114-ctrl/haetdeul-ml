# 실험 · flash-lite 가 보고서를 **직접** 쓰면 어떻게 되나

Claude 를 안 거치고, 아침 배치가 남긴 자료만 주고 flash-lite 에게 일별 점검
보고서를 쓰게 했습니다.

```
준 것      규칙 도구 여섯이 09:05~09:23 에 남긴 파일   8,925자
           (수집검사 · 재학습판정 · 뉴스요약 · 배치장애조사 ·
            데이터품질 · 드리프트감지)
           + 말투 규칙 (초등학생도 알아듣게 · 짧은 문장 · 결론 먼저 ·
             나쁜 소식 순화 금지 · 지어내지 말 것)
안 준 것    DB 직접 조회 · git 변경분 · 어제 보고서
           -> 자동으로 돌 때 손에 쥘 수 있는 게 딱 준 것뿐이라서
결과       3.9초 · 토큰 5,510 · 1,412자
```

---

## 한 줄 결론

**글은 잘 씁니다. 그런데 오늘 제일 중요한 두 가지를 못 냈습니다.**
못 낸 이유는 모델이 나빠서가 아니라 **그 자료를 안 줬기 때문**입니다.
그리고 그 자료는 **누가 DB 를 뒤져야 나옵니다.**

---

## 1. 잘한 것

**용어에 풀이를 붙입니다.** 시키지도 않은 자리까지 붙였습니다.

```
경락가(농산물이 경매에서 팔린 가격)
강수량(비가 얼마나 왔는지)
앵커(비교 대상 모델)
```

**「없음」과 「0」을 가릅니다.** 이건 제가 규칙으로 적어 둔 것인데 지켰습니다.

```
무: 오늘 비교할 기사가 없습니다.
    기사가 없다는 뜻이지 문제가 없다는 뜻은 아닙니다.
```

**판정을 자기가 다시 정하지 않습니다.** 도구가 낸 정상/주의/이상을 그대로 씁니다.

**빠릅니다.** 3.9초 · 토큰 5,510.

---

## 2. 못 낸 것 — 오늘 보고서의 값어치가 여기 있었습니다

### ① 매입 전달표의 모양이 바뀐 것 — **통째로 빠졌습니다**

오늘 실제로 일어난 가장 중요한 일입니다.

```
어제까지   가까운 날(1~2일 뒤) 12행은 «어제 가격» 을 그대로 내보냄
오늘부터   그 12행이 «모델 예측값» 으로 바뀜
```

매입 파트가 받는 표의 **성격이 바뀌었는데, 저쪽에 알렸는지 아무도 모릅니다.**

flash-lite 보고서에는 이 이야기가 **한 줄도 없습니다.**

**왜 못 냈나** — 규칙 도구 중 아무도 이걸 안 봅니다. 알아내려면
`run_batch.py` 의 어제 변경분을 읽고, 전달표를 어제·오늘 각각 조회해
게이트 걸린 행 수를 세어 봐야 합니다.

### ② 배추 「이상」이 헛경보라는 것 — **거꾸로 갔습니다**

같은 자료를 놓고 결론이 반대입니다.

```
flash-lite   "진짜 시장에서는 이런 일이 거의 없습니다.
              서로 다른 포장 크기가 섞였을 수 있으니
              포장 규격이 잘 맞는지 확인해야 합니다"

실제         분모가 2일뿐입니다. 그중 하루에 상등급 50kg 한 건이
             (같은 날 특등급은 518,140kg) 특등급 평균보다 비쌌던 것이 전부.
             규격은 멀쩡합니다.
```

**flash-lite 는 헛경보를 진짜 경보로 올려 보냈습니다.** 읽는 사람은
「포장 규격을 확인해야 한다」로 받습니다. 08-27 규격 사고를 겪은 팀이라
그 말 한 줄에 사람이 반나절을 씁니다.

**왜 못 냈나** — 도구가 낸 것은 「배추 2일 중 1일 (50%)」 한 줄뿐입니다.
그 이틀에 무슨 거래가 있었는지는 **원자료를 직접 뒤져야** 나옵니다.

### ③ 수집검사 「주의」도 그대로 넘겼습니다

```
flash-lite   "평소 458줄인데 오늘 248줄(54%)만 들어왔습니다.
              휴일이나 연휴가 아니라면 왜 줄었는지 확인이 필요합니다"

실제         최근 8거래일이 197~273줄입니다. 09-03 하루만 497줄이라
             기준선이 끌어올려진 것입니다. 248은 요즘 수준입니다.
             우리 타겟 규격은 09-01~09-08 전 거래일에 셋 다 있습니다.
```

또 「확인이 필요합니다」로 넘겼습니다. **확인은 누가 합니까.**

---

## 3. 지어낸 것 하나

```
flash-lite   "오늘 새벽 0시에 자동 프로그램이 잘 돌았습니다"
실제         아침 9시에 돌았습니다
```

도구가 낸 `00:00:02` 를 그대로 받은 것까지는 맞습니다 — 그건 그날
우리 도구가 시각을 UTC 로 찍고 있던 버그입니다(오늘 고쳤습니다).

문제는 **거기에 「새벽 0시에」 라는 해석을 붙인 것**입니다. 자료에 없던
말입니다. 「지어내지 말 것」이라고 적어 뒀는데도 그랬습니다.

---

## 4. 길이

```
flash-lite   1,412자
사람이 쓴 것   9,224자
```

여섯 배 차이는 문장을 길게 써서가 아닙니다. **없는 이야기는 못 쓰기
때문**입니다. 조사한 만큼만 나옵니다.

---

## 5. 그래서 제 판단

**「글쓰기」와 「조사」를 갈라 봐야 합니다.**

```
글쓰기    flash-lite 가 저보다 낫습니다. 용어 풀이도 알아서 붙입니다
조사      규칙 도구가 낸 줄 밖으로는 한 발도 못 나갑니다
```

일별 점검의 값어치는 **조사에 있습니다.** 「50kg 한 건이 만든 숫자다」와
「248줄은 요즘 수준이다」가 오늘 보고서의 전부이고, 둘 다 DB 를 직접
뒤져야 나옵니다.

### 세 갈래

**㉮ flash-lite 가 혼자 쓴다** — 오늘 결과가 그것입니다.
빠르고 싸지만 **헛경보를 진짜 경보로 올립니다.** 매일 「확인이 필요합니다」
가 쌓이면 아무도 안 읽게 됩니다. 우리가 이미 겪은 실패입니다.

**㉯ 규칙 도구를 늘려서 flash-lite 에게 더 준다**
「분모가 몇 일인지」「전달표 게이트 행 수가 어제와 다른지」를 도구가 재서
같이 넘기면, 오늘 못 낸 셋 중 둘은 잡힙니다. **다만 무엇을 재야 할지는
사람이 겪고 나서 알게 됩니다.** 50kg 이야기는 오늘 처음 겪은 것입니다.

**㉰ 조사는 Claude, 글은 flash-lite** (제가 권합니다)
Claude 가 DB 를 뒤져 **사실만 영어로** 모으고, flash-lite 가 한국어로
씁니다. 앞선 실험에서 숫자 216개 중 두 번 다 안 틀렸습니다.
글은 flash-lite 가 낫고, 조사는 Claude 만 합니다.

읽어보시고 정해 주세요.

### 1. 전체 돌아간 모양 (배치장애조사)
- **판정**: 정상
- 오늘 새벽 0시에 자동 프로그램이 잘 돌았습니다. 실패한 것 없이 11개 모두 성공했습니다.
- 매입 담당자분들이 보는 표에도 오늘 날짜(`2026-09-09`) 예측 값이 아침 9시 8분에 잘 들어갔습니다. 162줄이 적재되었습니다.

### 2. 들어온 자료 상태 (수집검사)
- **판정**: 주의
- 경락가(농산물이 경매에서 팔린 가격)의 자료 행 수가 줄었습니다. 평소에는 458줄인데 오늘은 248줄(54%)만 들어왔습니다. 휴일이나 연휴가 아니라면 왜 줄었는지 확인이 필요합니다.
- 날씨 기록 중 강수량(비가 얼마나 왔는지)의 빈자리(결측)가 늘었습니다. 평소에는 54.1%가 비어 있었는데, 최근 7일 동안은 83.2%가 비어 있습니다.

### 3. 자료의 품질과 오류 (데이터품질)
- **판정**: 이상
- **등급 순서 역전 현상**: 좋은 등급인 '특등급'이 보통 등급인 '상등급'보다 더 싸게 팔린 날이 있습니다. 
  - 배추: 2일 중 1일 (50%)
  - 무: 103일 중 4일 (4%)
  - 양파: 23일 중 1일 (4%)
  - 진짜 시장에서는 이런 일이 거의 없습니다. 서로 다른 포장 크기가 한꺼번에 섞여서 계산되었을 수 있으니 포장 규격이 잘 맞는지 확인해야 합니다.

### 4. 모델 성능과 변화 (재학습판정 / 드리프트감지)
